## 状态词

- **Supported**：当前公共入口实现且有任务内回归证据，仍受请求 budgets 和表中边界约束。
- **StructuralProbeOnly**：只返回边界可靠的已读结构；不承诺该 dialect、语义或 JVM 合法性。
- **PartialOnError**：遇到局部错误后停止并保留可靠前缀，内部 execution 为 `Partial`；不是静默成功。
- **MetadataOnly**：只识别并保留 metadata/位置，不执行其声明的安全或语义操作。
- **NotImplemented**：对应分析面没有实现。
- **Configured**：CI 或入口已配置，但尚无首次实际成功运行证据。
- **Validated**：限定范围已有实际执行证据；括号内限定（如 test-only）是状态的一部分。
- **NotValidated**：实现或依赖可能在该环境工作，但当前阶段没有建立支持证据；按不支持处理。
- **Unsupported**：入口明确拒绝，或超出当前支持范围。

所有 classfile Header 与方法指令结果的 `verification` 都是 **NotPerformed**。`parse: Supported` 只表示表中声明范围的结构读取，不表示完整 JVMS dialect validation、字节码 verifier、链接或运行成功。

X1 列的 `Supported` 一律限定在**请求声明的 consumer schema 与物理视图**内：P1 只分析 `constant_pool_contains`、`mentions_symbol`、`literal_value` 三个关系（`references_definition`/`may_dispatch_to` 返回 `UnsupportedAnalysis` 并保留原始候选），覆盖 Invocation、Field、Type、Constant、Exception、Signature、Annotation、InnerNest、Module、Bootstrap 与 Resource consumer；请求 `Verification`/`Debug` 时进入 `coverage.unsupported_categories` 且不声明 complete-within-schema。query 不按 runtime 视图过滤，`resolution` 恒为 `not_requested`。

### 已实现与未实现的分析面（2026-09-19 恢复复核）

- **X1（结构 XRef）已实现声明范围**：`Engine::query` 提供 `constant_pool_contains`（原始 CP 候选）、`mentions_symbol`、`literal_value`，覆盖 code（invoke/field/type/constant/`ldc`/`invokedynamic`/异常表）、metadata（hierarchy/descriptor/Signature/注解含 Record component 与 Code 内 type annotation/Exceptions/ConstantValue/InnerNest/Module）、bootstrap（deferred 图、共享子图、环与预算）与 resource（Manifest 属性、`META-INF/services`），以及实际使用点（`ldc`/`invokedynamic`/bootstrap 可达）的 descriptor 类型。范围外：`references_definition`/`may_dispatch_to` 返回 `UnsupportedAnalysis` 并保留原始候选（P2 resolver）；`Verification`/`Debug` 类别不实现；未知自定义 attribute 不解释；不构建 CFG、SSA 或 Java AST。
- **resolution：Supported（限定于显式运行环境下的类与成员声明解析与已知范围 dispatch；`Engine::query` 的关系语义不变）。** `Engine::resolve_symbol` 在显式绑定的 `ResolutionEnvironment` 内按 parent 链 + 每个 loader 的 delegation 与 roots 顺序查找类定义，返回 `Resolved`/`Missing`/`Ambiguous` 等状态并记录每次 Header 读取的理由；成员符号按 JVMS 5.4.3 在类/超类链与接口的 maximally-specific 集合上解析**声明**（`resolved.member` 的 owner 是声明类内部名，`target` 保留原始引用），并施加调用种类规则（静态/实例、class/interface owner、`<init>` 仅 `invoke_special`、`invoke_special` 不解析抽象方法）与访问规则（`public`/`private`/`protected`/包私有，运行时包 = loader + 包名；调用方类未知时返回 `Resolved` + `resolution_access_not_checked`，不谎称已检查）；default conflict（多个非抽象 maximally-specific 声明 → `IncompatibleClassChange`）、signature-polymorphic 按 name 匹配与数组 owner 各有明确分支。`Engine::declaration_references` 在显式运行环境下回答「哪些真实 use-site 解析到该声明」：候选来自结构 consumer 的**成员形状**匹配（owner 不参与，所以 `Sub.foo` 能被发现）、未使用的常量池条目不算引用、只有解析到请求声明的候选进入 `items`，解析未决（缺失/歧义/链接与访问失败/数组 owner/预算/取消/损坏/证据不含指令级种类）计入 `unresolved_candidates` 并保留 use-site 证据；声明报告的每条 item 与诊断各计一次 `ResultItems`；class 符号的声明查询与签名多态声明各有明确分支（后者按 owner+name 匹配，因为站点描述符可能与声明不同）。**已知范围 dispatch 已实现**（2.5）：`ResolutionRequest.dispatch = Some(DispatchScope)` 时在显式物理范围内枚举该声明的已知实现/覆盖（CHA-lite，只读 Header；候选来自「自身声明同 kind/name/descriptor 且声明 owner 严格在其超类型路径之上」的类，不筛访问/静态/抽象标志，也不排除 `<init>`），每个候选附 open-world 证据（缺失依赖、外部内容、链外 loader、运行时不确定性、非首个 root），`open_world` 在有证据、范围存在不可判定位置或预算/取消停止时为 true；报告不含「唯一运行目标」字段，因此单一已知候选也不声称唯一。不加载依赖、不绑定宿主 loader、不做 runtime selection；报告的计费纪律与前面的声明报告同一口径：`Engine::resolve_symbol` 发布到报告里的每条诊断（2.3 的规则诊断与闭包自报的分支诊断如 `resolution_hierarchy_cycle`）各计一次 `ResultItems`，环境平面诊断、停止解释诊断（`budget_exceeded_*`/`cancelled`/结构错误码）与「范围未运行」的说明性诊断（如 `resolution_dispatch_no_declaration`）不收费；停止按发生位置分开：查找或 listing 被截断时 `runtime_resolution` 保留 `skipped = [examined, positions)` 的未检查位置，而发布阶段的停止（候选或诊断的 `ResultItems` 被拒）不产生 skipped、只把覆盖标为 Partial；P1 的 `QueryResolution` 仍恒为 `not_requested`；MR 只按 Manifest 与唯一 winning level 给出选择事实和合规诊断，不据此过滤 query 结果。
- **decompile-quality：Partial（P3 方法体恢复已实现，尚未完成发布验收）。** 已有普通直线/if/loop/switch、验证过的 LambdaMetafactory 子集、受限 concat/bridge/accessor。`return x++` 的旧值重读与 branch-local 作用域**已在 `1e6521e`/`f7f90b7` 关闭**（含真实 `javac` 语料回归）；被拒 cast/访问器的 producer effect 漏失已在 2.3 关闭（引用报全 BCI）；**3.1 把方法声明事实（access_flags/descriptor/参数槽含 receiver 与 category-2/debug/物理身份）放进载荷**，门面不再固定 `parameters=0`；**3.2 让门面按需读取被调用点点名的 callee**，公开入口已能呈现 accessor 字段访问（A12 同次入口验收）；**slot 复用已按 spec 拆分**（`58f0df9`）；**TWR/monitor 已呈现、finally 如实拒绝**（2.4）；**每条已解码指令必须被块或 `unreachable` 交代**（P3-R7，`0b5eeb0`）。**仍未做**：`MethodParameters` 未读、类级事实（`InnerClasses`/`ACC_INTERFACE`）不在载荷（故不声称嵌套、门面级 `declaration@1` 给被陈述的拒绝）、canonical 对「handler 入口即根」的取舍待裁决。
- **output-level：** P2 的 analyze_method/method_analysis 保持 Bytecode 分析报告；P3 的 recover_method 已在库/CLI 提供同次分析报告与 RecoveryReport，包含方法体 text、段表、rules/profile、quality/representation/diagnostics。完整区域可为 Java/Structured，存在 fallback 为 Mixed/Fallback；不是完整 compilation unit（边界逐条记录在 tests/fixtures/p3-corpus/README.md），P3-R1/R2/R3/R5/R6/R7 与发现 (i) 均已关闭，证据见 verification。MethodIr 只读接口已交接真实 CFG/Frame/SSA/code/CP/bootstrap。P3 生产 compile_status=NotAttempted、semantic_validation=Unproven、verification=NotPerformed。
- **已知边界**：类符号查找按「首个命中即胜出且不回退」；任一环境问题（含 `CallerLoaderMismatch`）拒绝整次查找且零读取；每次 Header 读取尝试计一次 `class_headers`（18 项 limit 中的 P2 维度之一）；`output_bytes` 在 standalone root（`root_bytes`）与 ZIP/tree entry 之间口径不同。cursor 绑定完整查询身份（`QUERY_ENGINE_SCHEMA = 2`，含完整 target 与 digest），跨目标/跨快照续页被拒；预算、取消与损坏输入永不伪造 Complete；`page.has_more` 与 `execution` 独立，停止且未发布新项时可能 `has_more=true` 且无 cursor（调用方需重试同一请求）；`Type`-only 请求会读 `BootstrapMethods` 并对每个 unit 解两遍方法体（属 P5 债务）；`PhysicalClassLocation::Entry.span` 的坐标口径与其它来源不一致，record component 的 descriptor 类别也有已知不一致（D05，接受为既有边界，不在 P2 修正）。

P3 当前边界分别验收：方法声明事实（access_flags/descriptor/receiver 与参数槽/debug 范围/物理身份）已由同一次 Header 读取进入 `MethodIr`，门面不再固定 `parameters=0`，参数按描述符定型（`boolean` 参数写 `if (b)`）；source-map anchor 已带**物理方法身份**（caller/callee 同 BCI 可区分，复用 reader 的 `OriginMember`）；accessor 的 callee 证据由 `jarde-jvm` 按**被调用点点名的候选**读取，有预算、有 reason、绑定同一物理定义与 CP，且**不预装全类 Body**。仍不在载荷里的是**类级**事实（嵌套/接口标志），故不声称嵌套（`new@1` 只呈现实例化）、门面级 `declaration@1` 给出被陈述的拒绝。
