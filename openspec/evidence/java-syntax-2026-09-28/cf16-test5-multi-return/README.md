## Test11 comparison

Test11's recorded loop was an exception-only handler SCC `{48,58}` with its sole physical normal-flow entry at BCI 48 from handler BCI 38; it was unreachable from method entry in the plain-transfer graph. Its failure was caused by applying method-rooted dominance to that handler component. See the existing [Test11 architecture trace](../cf16-test11-loop-finally/architecture-trace.md) and [bounded reducibility follow-up](../cf16-test11-loop-finally/architecture-trace-followup.md). The bytecode and same-run Jarde region facts supporting this distinction are detailed in [cfg-dataflow-facts.md](results/cfg-dataflow-facts.md).

Test5 has different facts. Its do-while SCC is the ordinary protected-body loop with back edge `76 -> 53`, entered on normal flow from BCI 44. The catch-all handler at 93 is a cleanup-and-rethrow block, not the loop header or a loop component. The difficult values are pending exits across cleanup: the early `null` at local 5, the list saved in local 6, and the caught Throwable at local 7. The body itself cycles while the single list reference in local 5 remains live and is mutated; the bytecode does not reassign that local inside the loop. Thus Test11's component-root reducibility work is not reusable as the mechanism for this case; this baseline instead points to finally/return ownership and SSA definition-use handling across the three shared handler rows. This is an evidence-based scope boundary, not a proposal for how to implement that handling.

## Replay

Run from the Jarde checkout on macOS with the fixed JADX test build and installed CLI present:

```sh
openspec/evidence/java-syntax-2026-09-28/cf16-test5-multi-return/replay.sh
```

The script pins the JADX checkout/source/class and auxiliary interface class hashes; regenerates JADX output; compiles/runs original, JADX and the direct fixed class; builds Jarde in a fresh dedicated Cargo target; records class-source and method recovery; and confirms the explanation-only compilation failure. Its exit trap runs `cargo clean --target-dir` for that dedicated target and removes only that script-created temporary directory. `JADX_ROOT` and `JADX_BIN` may select equivalent local paths; the pinned checkout and input hashes still apply.
