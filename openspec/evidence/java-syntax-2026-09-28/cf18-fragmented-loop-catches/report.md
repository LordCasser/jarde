# CF-18 fixed-shape implementation evidence

The evidence is for the two frozen `run()I` methods only. `same-run-facts.txt` is regenerated by
`CARGO_TARGET_DIR=/tmp/jarde-cf18-target cargo test -p jarde-java --test p3_java_recovery cf18_same_run_facts --locked -- --ignored --nocapture`.
It prints Code rows, Canonical blocks/edges/throw sites, and SSA entry/exit, phi, instruction,
definition, use and physical origin from each method's **one** `analyze_method_ir` result. The
normal-flow and recovery assertions use that same result in `cf18_fixed_methods_preserve_rows_dispatch_and_presented_origins`.

## CFG, row and value facts

| Method | Physical rows in ordinal order | Normal handler paths | Update |
| --- | --- | --- | --- |
| `HandlerLoopProbe` | `0 [9,16)→19 NFE`; `1 [9,29)→38 ISE`; `2 [32,35)→38 ISE` | `19→51`, `38→51` | `51 iinc local1`, `51→4` |
| `ExceptionRegionsAudit` | `0 [28,35)→38 NFE`; `1 [13,25)→72 ISE`; `2 [28,52)→72 ISE`; `3 [55,69)→72 ISE` | `38→52→85` or `38→55→58→63/66→85`; `72→85` | `85 iinc local1`, `85→8` |

`NFE` and `ISE` denote the physical `NumberFormatException` and `IllegalStateException` catch
types. The Canonical throw-site handler ordinal lists are respectively `11:[0,1], 20:[1],
26:[1]` and `17:[1], 22:[1], 30:[0,2], 39:[2], 45:[2]`. Full row 3 and reduced row 2 have
no actual throw site; both remain in the certificate with their Canonical protected blocks and
exception edges. Every row end is the BCI of a terminal `goto` in exactly one block with exactly
one ordinary successor to the method's update. The inner row end separately leads to its normal
join (`32` or `58`).

Normal-flow `loop_entered_at().blocks()` is the reverse closure of a natural backedge, not a
lexical-owner set: it can contain exception roots. The proof therefore distinguishes the
head-dominated normal core from exceptional-only roots. For the full class, `38,52,55,72` are
exceptional-only; `58,63,66` are shared ordinary continuation and have one loop AST owner.
The only exceptional-root edges into the core lead to inner normal join `58` or update `85`.
The reduced handlers enter update `51`. Neither handler root has a normal predecessor. All
normal paths through their finite closure terminate at the same update; a cycle or a bypass is
refused. The verifier-valid `other-loop-point`, `ordinary-handler-entry`, and
`handler-index-write` variants test three distinct violations.

SSA says Local(1) is the induction value. At each method's header, both handlers, every block
in their normal closures and the update entry, Local(1) resolves (following trivial phi
replacements) to the same loop-carried `ValueId(1)`; the update's `iinc` reads it and writes
the next value. The new certificate checks both entry and exit identity before the update.
Local(0) is the accumulator and **changes** on normal and exceptional paths: the full method's
join at 58 merges the value written at 34 with the one written at 55; the join at 66 merges
the 58 value with the optional write at 63; the outer handler writes again at 82. It is thus
wrong to demand one accumulator identity. Existing statement-builder reaching-write checks,
including the `iinc` read/write shape, close its Java local scope; the frozen whole-class
recompile and execution below test the resulting source. Both catch entries consume a caught
Stack(0) value at their first `astore`, with the outer handler's multiple inputs merged by its
SSA stack phi. `same-run-facts.txt` gives the exact definition/use IDs and physical BCI origins.

The `run()` Region records in `replay/*/jarde/report.json` own each Canonical block once:
reduced loop `[4,9,19,32,38,51]`, full loop `[8,13,17,28,38,52,55,58,63,66,72,85]`.
The integration test compares this union to all Canonical blocks and rejects duplicates.
It also checks source-map anchors for every listed handler, protected site, shared continuation
and update, and confirms each primary origin identifies `run()` in the exact input class digest.

## Whole-class replay and verifier-valid refusals

`replay.py --cli /tmp/jarde-cf18-target/debug/jarde-cli --output replay` generated Jarde's
complete class source and report, copied the fixed original/JADX complete sources, compiled
all six with `javac --release 8 -g:none`, then ran every class with `java -Xverify:all`.
The commands, exit codes, stdout and stderr are in `replay/results.json`.

| Class | Original | Fixed JADX | Current Jarde |
| --- | --- | --- | --- |
| `HandlerLoopProbe` | `4:110`, exit 0 | `4:110`, exit 0 | `4:110`, exit 0 |
| `ExceptionRegionsAudit` | `124:115`, exit 0 | `IllegalStateException: two`, exit 1 | `124:115`, exit 0 |

Both Jarde class sources contain no `@bytecode` marker. The complete fixed JADX class is a
negative comparator because its outer catch is inside the positive branch and lets the `two`
exception escape. The original complete class is the semantic oracle.

`NegativeFixtures.java` deterministically mutates the frozen original class with JDK ASM and
stores eight class files under `negatives/`. Every class loads under `java -Xverify:all`
(some intentionally exit from their changed runtime behavior). They vary outer catch type,
row priority, missing protection, an added throw site in a row gap, handler entry at another
loop point, a normal handler entry, an induction write in the handler, and a crossing range.
`cf18_verifier_valid_near_misses_refuse_the_whole_method` checks that none receives a partial
Java catch. The CLI additionally reported a whole-method fallback for every variant.
