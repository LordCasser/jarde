# Static API review v2

Frozen input evidence: javac23 `javap` line 81 declares `asciiToLowerCase(java.lang.String)` and line 82 gives `(Ljava/lang/String;)Ljava/lang/String;`. The frozen Jarde report names the same method and descriptor. The candidate passes this name to both `analyzed_caller` and `MethodFacts::new`, and logs it. The class header reports major 52; existing `analyzed_caller` configures Java 8 and the site census now also uses release 8.

API checks against pinned source: `SsaTable::value(ValueId) -> &SsaValue`; `SsaValue::{def,replaced_by,uses}` are public methods; `SsaPhi::{block,value,inputs}` are public; `PhiInput` is re-exported from `jarde_jvm::method_ir`; `NormalFlowView` exposes `ids`, `id_of`, `predecessors`, and `successors`; `Sites` exposes `allocation_candidates`, `refusals`, and `site_at_head`; `outside_readers` is private but the candidate is in the same `init` module; `Gap` exposes `code` and `message`, but not an `at()` accessor. `ValueId` derives ordering for the candidate's `BTreeSet`.

Region recovery and conditional proof were removed: they are second-stage behavior beyond confirming whether a constructor-produced SSA value's Phi operand is visible to the reader gate. This keeps the diagnostic on one exact IR and avoids making static assumptions about region traversal. No compile/run was used to validate Rust syntax or typechecking; static API review does not prove the candidate compiles.

Architecture boundary: this observation should not be treated as a proposal to accept any Phi in `Sites`. The run should establish only the concrete producer-to-Phi-input path, that Phi's unique actual instruction consumer, and the arms/predecessor shape. Even if `Sites` identifies one rendered reader position at the conditional consumer, Builder remains responsible for its existing full conditional proof and syntax/ownership checks. The diagnostic does not establish safety for multiple arms, multiple incoming aliases, or multiple consumers; those remain explicit review points before any implementation.
