# SequentialLoops2 same-IR diagnostic runner v1 review

This is a private runner draft for root-controlled execution after CI acceptance closes. It has not been run. No shared source or Git state was changed, and no Cargo/JDK/JADX/Atlas command was invoked during preparation.

The runner is `/private/tmp/jarde-sequential-loops2-same-ir-diagnostic-root-v1.py`. It is pinned to the private v3 `init.rs` candidate (`4506b652e0ded4408bd740cd8f1349065e2f6d5f5fcbdcf7f708e11b32c1b1c2`), the live `init.rs` baseline (`f1c0c96fed82e86729fefbef55f40d85473526fb86b0389b9253bb6f41f4c4a1`), and the external `UpstreamSequentialLoops2.class` bytes (`524b1746bdff10a3b9da021679f9832202df1552c2eb42c02d150284b7dd8664`). The class is an explicit external input pin and is not counted as one of the repository source files.

Before mutation, the runner requires the accepted final-build-v3 receipt and runner hashes, validates the receipt's `for-condition-final-lint-build-root-v1` / `passed_candidate_build_only` state, and independently repeats the exact source-path enumeration used by final-build-v3. It requires the enumerated set to equal the receipt's 4,718 paths and the live hashes to equal `source_pins_before`. With the candidate installed, it does not invoke the ordinary source-closure scanner; it hashes only the fixed receipt path set and requires `init.rs` to be its sole changed pin. Thus the candidate's absolute `include_bytes!` input is handled only by its separate class pin.

The only runtime test command is `cargo test -p jarde-java --lib --all-features --locked init::tests::cf11_sequential_loops2_constructor_phi_same_ir_diagnostic -- --exact --nocapture`. The runner removes any inherited `RUST_MIN_STACK` so Rust uses its default stack, applies the existing root guard environment and fixed proptest seed, and uses the pinned one-second target/free-space guard with 1 GiB target and 5 GiB free-space limits. The runner records each command's argv, exit code, guard status, and stdout/stderr file path, byte count, and SHA-256. It records both the 4,718 repository source pins and all candidate/tool/evidence pins before and after; the run is accepted only if they match, the runner hash is stable, and the restored source set matches the final-build baseline. If the candidate fails to compile or the test exits nonzero, those raw streams remain in the receipt.

A `finally` path restores the original `init.rs` bytes and verifies the pinned baseline, records all 4,718 post-restore hashes, then attempts guarded `cargo clean` and records whether `target/` is absent. A concurrent unexpected `init.rs` edit causes refusal to overwrite that file and a failed receipt. This protects unrelated edits while making restoration status explicit.

The candidate test is restricted to observing the same decoded/canonical/SSA/NormalFlowView facts, `outside_readers`, and existing `sites` census. It does not call Region or Builder and introduces no production behavior. The root may still need to interpret the diagnostic output; a successful test only means the observation test ran and the cleanup invariants held.

`pins.json` contains the actual runner, candidate, class, guard, scanner, accepted build receipt, closure digest, and candidate dependency hashes. The exact verifier path is `/private/tmp/jarde-for-condition-next-round-luna-v1/jarde-for-condition-ci-verifier-luna-v4.py`; this runner itself does not assert that CI acceptance is closed, so root must defer execution until that acceptance is complete. Static validation here was limited to Python AST parsing and byte/hash checks. No Rust parsing, formatting, compilation, or execution was used.
