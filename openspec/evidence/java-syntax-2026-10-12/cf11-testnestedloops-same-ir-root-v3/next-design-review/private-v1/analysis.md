The diagnostic has no complete slot-use, declaration-owner or liveness dump.

Code read: `Builder::loop_region` saves the parent `self.stmts`, builds the loop body in a fresh list, restores the parent list, then calls `iterable_for_each_candidate`. The current candidate requires the first body statement be a value-initialized declaration; after that it looks for the iterator initialization in the current `self.stmts` and requires an earlier blank Iterator declaration in the same vector. The returned `Vec<usize>` is later applied only to the restored current vector. `declare_at` emits declarations from `Declarations::at_region` and marks the exact `LocalVariable` declared. `Declarations::placements` already carries `Local`, `Elevated`, or `Incomplete` with a `RegionPath`; `reuse::Plan::variable_at(slot, bci)` returns a split-aware `LocalVariable`. AST `StmtKind::Declare` and `Assign` only preserve the source name, type/value and origin, not the internal `LocalVariable`.

JADX `LoopRegionVisitor.checkIterableForEach` examines the iterator SSA value, phi/use count, iterator/hasNext/next calls, wrapped cast/element variable and loop ownership; after acceptance it hides iterator initialization and related uses and installs a `ForEachLoop`. `RegionGen` prints the header. The checked `TestIterableForEach` only tests a simple `Iterable<String>` body. The checkout build version is pinned separately from the product runtime; no attempt was made to execute it. This is architectural comparison only, not proof transferable to JVM classfile SSA or Jarde's lexical declaration planner.

All read paths and byte/hash pins are in `pins.json`. No shared file was written. No compiler, formatter, Git, JDK, JADX, or CLI was run.
