# 普通 LVT descriptor 元数据路径（只读静态分析）

## 结论

`LocalDebugName` 在 reader 层确实携带 LVT 的原始 descriptor、name、slot 和 BCI 范围；它们不是在 classfile decode 时丢失的。reader 把 LVT 与 LVTT 分成两份事实传出。生产 facade 把每条 LVT 事实转换成 `DebugLocal::over(slot, name, start, end)`，这一步只传 name/range/slot，因而普通 LVT descriptor 没有进入 `DebugLocal`。仅当同一 `(slot, start_bci, end_bci, raw name)` 在 LVT 中恰好一条、且 LVTT 对同一 key 恰好一条时，facade 才调用 `with_type_metadata(LVT descriptor, LVTT signature)`。所以“唯一 LVTT 关联”是当前 reader→facade 生产路径将 descriptor 写入 `DebugLocal` 的唯一通道；这不意味着原始 LVT descriptor 只在 reader 中存在于该情形。

现有 `DebugLocal` 结构已有 `descriptor: Option<Vec<u8>>`，无需新增实体即可在结构上保存普通 LVT descriptor。但当前字段和 getter 明确承诺“有唯一匹配 generic signature 的 LVT descriptor”，且唯一写入器同时设置 generic signature。若另一个变更选择让它表示普通 LVT descriptor（即使没有 LVTT），须先定义/调整该字段语义和 setter/getter 文档，并保持任何 generic 类型推断仍要求真实 LVTT signature。也可在同一 `DebugLocal` 中增加独立的 LVT descriptor 字段/构造方法以保留两种语义；这会增加字段而非新实体。这里只记录选项，不作实现或范围扩展。

## 数据路径与精确位置

1. reader 的 `MethodCodeFacts` 私有字段分别保存 `debug: LocalDebugTable` 和 `generic_debug: LocalDebugTypeTable`（[`classfile.rs:4058-4092`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-reader/src/classfile.rs:4058>)）。`LocalDebugName` 明确有 `slot`、`start_bci`、`end_bci`、raw JVM `name` 和 raw JVM `descriptor`；后者的注释称为 name 旁声明的 erased field descriptor（[`classfile.rs:4113-4132`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-reader/src/classfile.rs:4113>)）。LVTT 独立用 `LocalDebugType` 保存相同形状的 slot/range/name 与 raw `signature`，没有 descriptor 字段（[`classfile.rs:4134-4159`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-reader/src/classfile.rs:4134>)）。
2. 解码完整 `Code` 后，`decode_method_code` 调用 `local_debug_tables(&code, pool)`，随后把两张表分别存进 `MethodCodeFacts`（[`classfile.rs:5264-5271`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-reader/src/classfile.rs:5264>)、[`classfile.rs:5472-5486`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-reader/src/classfile.rs:5472>)）。LVT reader 从 classfile entry 取 index、range、name 与 descriptor，并把后二者解成常量池内容的原始 bytes 后放入 `LocalDebugName`（[`classfile.rs:5494-5532`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-reader/src/classfile.rs:5494>)）。LVTT 独立读取 name 与 signature；重复 LVTT 或内容无法完整解码时将 generic 表标为 `Unstated`（[`classfile.rs:5535-5565`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-reader/src/classfile.rs:5535>)、[`classfile.rs:5571-5583`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-reader/src/classfile.rs:5571>)）。因此 reader 并未丢弃普通 LVT descriptor。
3. `recovery_facts` 将 `debug_locals(code)` 产物附到两种 `RecoveryFacts` 构造路径（[`facade.rs:41717-41748`](</Users/lordcasser/workspace/projects/jarde/src/facade.rs:41717>)）。若无可读 LVT 或无 Code，`debug_locals` 返回空；LVTT 不可读时仅作为空 slice（[`facade.rs:41781-41794`](</Users/lordcasser/workspace/projects/jarde/src/facade.rs:41781>)）。facade 的 join key 是 `(slot, start_bci, end_bci, raw name)`；它分别统计 LVT key 的数量，并按 key 收集 LVTT rows（[`facade.rs:41795-41819`](</Users/lordcasser/workspace/projects/jarde/src/facade.rs:41795>)）。
4. 对每条 LVT row，facade 先调用 `DebugLocal::over(slot, name_lossy, start, end)`，没有把 `record.descriptor` 作为参数传入。只有 LVT key count 为 1 且 LVTT key 恰好只有一条时才调用 `local.with_type_metadata(record.descriptor, generic.signature)`；其余分支直接返回未带 type metadata 的 `local`（[`facade.rs:41820-41841`](</Users/lordcasser/workspace/projects/jarde/src/facade.rs:41820>)）。所以 descriptor 的生产层断点精确位于这个映射分支，不在 reader 表解码。
5. `DebugLocal` 已有私有字段 `descriptor` 与 `generic_signature`（[`names.rs:327-333`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-java/src/names.rs:327>)）。`over` 和 `named` 都把二者初始化为 `None`（[`names.rs:335-356`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-java/src/names.rs:335>)）；现有 `with_type_metadata` 一次设置两者（[`names.rs:359-368`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-java/src/names.rs:359>)）。`descriptor()` 的文档明确限定为“when this record has a unique matched generic signature”；`generic_signature()` 也要求 unique exact LVT match（[`names.rs:385-392`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-java/src/names.rs:385>)）。这说明当前行为是有意收窄字段语义，而不是类型容量不足。
6. 下游 `prove_debug_generic_locals` 先要求 `generic_signature()`、`descriptor()` 和 range 同时存在，才继续校验 `Ljava/util/Map;` 并解析 signature（[`build.rs:1639-1678`](</Users/lordcasser/workspace/projects/jarde/crates/jarde-java/src/build.rs:1639>)）。该调用条件支持将普通 descriptor 传播与 generic LVTT 推断分开考虑；此处没有追踪其他类型决策、SSA 或 LVT 类型推导。
