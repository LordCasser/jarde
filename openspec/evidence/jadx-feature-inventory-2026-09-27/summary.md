# JADX 测试驱动的 Java 恢复路线

## 范围与计数

基线固定为本地 JADX 提交 `2fb1b16386941660fda07e9017285aec40fcb37f`。已逐组审阅其 27 个集成测试目录的 **612/612 个 Java 文件**，并把每组文件归入语法、交叉、支撑或容错账本；证据与生产算法入口见 [控制流](control-flow.md)、[声明和类型](declarations-types.md)、[表达式与杂项](expressions-misc.md)。612 是测试文件数，不是独立特性数或成功重编数。

按当前可独立构造输入、设定拒绝边界和验收结果的粒度，去重后有 **71 个源级验收单元**：

| 组别 | 原始条目 | 去重后 | 口径 |
| --- | ---: | ---: | --- |
| 控制流 CF | 20 | 20 | CF-01～20；CF-17 仅有未完成目标 `TestTryWithResources`，不是 JADX 正向能力 |
| 声明/类型 DT | 31 | 30 | 保留 DT-01～29、DT-31；DT-30 数组初始化并入 EM-18 |
| 表达式/杂项 EM | 31 | 21 | 保留 EM-01～07、EM-10～13、EM-17～25、EM-27 |
| **总计** | **82** | **71** | 其中最多 70 个有 JADX 正向测试候选；部分候选仍混有弱断言、禁用编译或未完成变体 |

EM 的 10 个剔除条目各有去向：EM-08→CF-18，EM-09→CF-07/16，EM-14 是调用机制而非独立 Java 语法，EM-15 是合成访问器内联机制，EM-16→DT-05～08，EM-26→CF-04/05，EM-28 是注释/元数据，EM-29→CF-19，EM-30→DT-10/12，EM-31→DT-23。EM-25 仅保留装箱/拆箱的独立验收边界；强转与重载消歧分别复用 DT-28/29 和 EM-11。`Outer.super` 在 JADX 代码中有生成路径，但本批测试缺直接断言，只登记为**代码线索和待补测试**，不虚增第 72 个单元。

这些是工程验收单元，既不是 Java 语言规范的语法条款数，也不表示 Jarde 已覆盖 70 项。一个单元可以含正例、负例和多个 lowering；例如 DT-13 的嵌套枚举与 `enum implements I` 可在实施时进一步拆开。每个单元进入“已追平”前，必须重新确认该 JADX 断言是否实际运行并检查原 class、JADX、Jarde 的完整源码在 Java 8 下重编和执行。仅文本相似、单文件能编译或旧 OpenSpec 勾选不足以结项。

## 逐项状态账本

状态只反映**本轮三方实测**，不抹去 Jarde 已有的实现与测试。`未测` 表示尚未按本轮统一门槛重放；`有差距` 必须有具体反例；`JADX 未完成` 不进入追平分母。合并行中的每个 ID 仍是一个单独验收单元，推进时逐个更新。

| 状态 | ID | 当前证据 |
| --- | --- | --- |
| 冻结差距已修复，单元待扩验 | DT-01、DT-03 | 成员局部类型已由准确成员路径写为 `Outer.Member`，`OuterSuperEffects` 全家族 Java 8 重编运行通过；其他成员形态仍按各自单元扩验 |
| 冻结差距已修复，单元待扩验 | EM-13 | 唯一同类 `ACC_VARARGS` 目标的完整调用数组可安全展开，冻结正反例重编运行通过；继承、跨类和其他 lowering 未纳入此闭环 |

当前有 **3 个冻结差距已修复但待扩验的单元、67 个未测的正向候选、1 个 JADX 未完成单元**。上述两项 OpenSpec 和 root 独立验收已闭合；这不自动把 DT-01/03 或 EM-13 的全部变体标为“已追平”。若发现测试本身无有效正向断言，先修正其证据级别和分母。

## 顺序与验收门槛

先使用这 71 项作为固定巡查队列，对每项登记 `未测 / 已追平 / 有差距 / JADX 未完成`、代表正反例、Jarde 生产入口及可重放结果。没有实测证据的条目保持“未测”，不因存在实现代码就算完成。按依赖和实测差距安排以下批次；同一批中语义边界互不冲突的任务可并行，汇总验收由 root 独立重放。

| 批次 | 范围 | 已有证据与下一步 |
| --- | --- | --- |
| 1：已确认的窄缺口 | DT-01/03 的成员类局部类型源名；EM-13 可变参数调用展开 | [成员类类型 OpenSpec](../../changes/spell-proved-member-local-types/) 与 [可变参数 OpenSpec](../../changes/recover-proved-varargs-calls/) 已并行实现，并由 root 独立完成冻结三方编译运行、来源、拒绝边界与测试验收；单元的其余形态留在巡查队列。 |
| 2：高价值成员恢复 | DT-05～09 匿名类与捕获；DT-02/04 具名成员关系；EM-12 `super`/词法外层接收者 | 从 JADX 对应测试与 `AnonymousClassVisitor`、`ProcessAnonymous`、`ClassModifier`、`InsnGen` 提取证明条件，再测 Jarde。捕获、重复分配、跨类关系先于内联美化；JADX 的 `NotYetImplemented` 变体不当作追平基线。 |
| 3：其余声明/表达式 | DT-10～29、DT-31；EM-01～07、10～11、17～25、27 | 按每项正反 fixture 批量跑 Jarde 与 JADX，先消掉“未测”，只为实测差距开独立 OpenSpec；可借用 JADX 的算法与负例，但不复制错误假设。已实现的 enum、注解、签名等仍需逐单元重验。 |
| 4：控制流 | CF-01～16、18～20 | 对分支、循环、switch、异常和监视器分别做 CFG/副作用对照；交叉测试归入其主要失败单元，避免一个测试导致跨模块改动。 |
| 5：超出 JADX 正向基线 | CF-17、`Outer.super` 测试缺口及巡查中新增形态 | 在上述 70 个正向候选完成差距确认后再探索；现有 Jarde 局部能力可以保留和验证，但不伪称 JADX 已有基线。 |

批次 3 与 4 可按 fixture 构造成本交错推进，不需等整批结束。每个实施任务先写出源代码、编译器产物和三方输出，再判断是现有证明路径未消费、证据不足还是确需新机制；优先在原有事实与候选路径内修复。若审阅发现与当前单元无关的架构债务，单列记录，不混入当前改动。

匿名类批次已有一条不能照搬 JADX 的明确边界：`ProcessAnonymous.checkUsage` 以构造器的**使用方法数**判断可内联；同一方法内两个分配 BCI 仍可被当作一次使用。[双分配冻结反例](../java-syntax-2026-09-25/anonymous-double-site/report.md)中，JADX 全源码能重编，但运行时类身份被拆成两份，`sameClass` 从 `true` 变为 `false`。Jarde 的候选应按完整物理分配点和构造目标做唯一性证明；[跨类冻结反例](../java-syntax-2026-09-25/anonymous-cross-class-use/report.md)还要求区分单类借助原 jar 重编与完整输出自洽重编。JADX 的构造实参/捕获字段映射和依赖次序可参考，不能继承这两个错误的身份假设。

Jarde 已在同次方法恢复中采集 `AnonymousAllocationScan`（每个 `new` 的 BCI、目标、构造调用、完整性），并在类装配层保留扫描；因此 DT-05～09 无需先发明第二套全局分配计数。真正待证明的是：唯一分配点、匿名体方法与合成捕获字段能否作为**同一组物理类**原子投影；如果任一成员、来源或预算不完整，就保留物理类表示。这是下一批 OpenSpec 的架构切入点，不先把 JADX 的 `DONT_GENERATE` 标记照搬进 Jarde。

EM-13 的[可变参数冻结 fixture](../../../tests/fixtures/proved-varargs-calls/README.md)也显示，JADX 虽能把简单调用写成展开形式，却会把单个 `null`、`String[]` 传 `Object...` 等边界展开成改变运行时数组形状的源码。我们只借鉴其目标方法识别与调用投影入口；数组是不是语法糖由原 class 行为和唯一消费证明决定，不能把所有 `new T[]{...}` 机械展开。
