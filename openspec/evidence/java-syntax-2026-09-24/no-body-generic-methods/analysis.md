# 无正文方法自有泛型参数/返回的三方对照

Java 8 顶层抽象类 [`NoBodyGenericIdentity`](fixture/NoBodyGenericIdentity.java) 有两个无正文方法：`<T extends Number> T echo(T)`，以及 `<T extends Number> T checked(T) throws IOException`。后者的物理 `Exceptions` 有 `IOException`，方法 `Signature` 却没有 `^` 异常后缀；这是合法且必须保留物理异常的边界。[覆写与强类型调用方](fixture/NoBodyGenericCaller.java)按泛型方法签名实现两方法，并把返回值直接赋给 `Integer`。`-g`/`-g:none` 的原 class 均通过 `javac --release 8` 与 `java -Xverify:all`，输出 `values=7,8`、`returns=T,T`、`throws=java.io.IOException`。

JADX 1.5.6 在两个调试变体都输出 `<T extends Number> T echo(T)` 与 `<T extends Number> T checked(T) throws IOException`，类、覆写实现及调用方都可重编，运行和方法反射与原 class 一致。实现前 Jarde 把两方法写成 `Number echo(Number)` / `Number checked(Number) throws IOException`：类单独可重编，但方法类型参数反射数从 1 降为 0、泛型返回 `T` 降为 `Number`；同一调用方产生 7 个编译错误，涉及覆写名称冲突及 `Number` 无法赋给 `Integer`。两种调试变体结果相同。这与[方法自有异常变量的独立样本](../method-local-generic-throws/analysis.md)一起说明，无正文方法 `Signature` 的早退同时损害 JADX 已覆盖的参数/返回泛型与 JADX 尚未正确覆盖的 `throws X`。

`javap -v` 中两方法的签名都是 `<T:Ljava/lang/Number;>(TT;)TT;`；`checked` 另有 `Exceptions: java.io.IOException`。reader 的同一方法 proof 已支持局部变量作用域、第一界擦除和空泛型异常后缀与物理 `Exceptions` 并存。[实现与独立验收](../../../changes/recover-no-body-generic-method-signatures/verification-root.md)已复用现有 proof 和结构化拼写器；缺失父类契约及同类调用绑定保留为局部拒绝。

[根接口 fixture](fixture/RootGenericInterface.java)进一步把 `<T> T echo(T)` 与 `<X extends Exception> void raise() throws X` 放在不继承其它接口的顶层 interface 中。原类两种调试变体运行均输出 `raised`、`value=9`、`returns=T`、`throws=X`。JADX 保留 `echo` 的 `<T>`，但把 `raise` 的异常写成物理 `Exception`；[调用方](fixture/RootGenericCaller.java)的无检查异常 `narrowed` 因此在 JADX 下编译退出 1，而原源码通过。实现前 Jarde 的根接口源码把两方法都写成擦除声明，类型参数反射数均为 0，原调用方的覆写/参数返回也不能编译。物理 superclass 为 Object 且 interfaces 列表为空，故它与无继承抽象类共享同一来源/擦除/调用绑定门，无需接口专用 parser。根接口原类 SHA-256：`-g` 为 `f82455134b6ef0db85afbb7d9c9242b6d2d6fc24e09cc45c9b9c9e92f3a35c3a`，`-g:none` 为 `82aed4e0c9d022211b4f20fd037e44aff727d733c36141f6557c2b431e077bf8`；JADX 两份源码均为 `7c0c1d495d399eaf1e5ad6407be1c2dbed380b40621c863b72a5d7ac4e9841a0`，实现前 Jarde 两份源码均为 `a028da446b52f9f3184354fa105b1f758adc39708dbd5a4872e72e2d700e8bfb`。最终调用方 fixture SHA-256 为 `a768759c48f6085b4ffdbfb36e4d632f6c0d507cb8aa162f327c10e0977832b3`。
