# Partial-dimensional array creation audit

`root-ecab/` preserves the first 72-case source-only class, including an `Object[]` overload consumer. The `core-no-overload/` rerun removes only that overload method and runner call **from the input source before `javac`**. It preserves the nine allocation/consumer methods (plus the constructor), source, class bytes, `javap`, complete original/JADX/jarde outputs, compile and runtime logs, and the exact replay script.

Run `JARDE_AUDIT_STAGE=core-no-overload JARDE_AUDIT_CLI=target/debug/jarde-cli python3 core-no-overload/run_audit.py` from the repository root. The implementation CLI SHA-256 is `7152f4358111c313e0641256f2b118ea233d8ddbdae32d58b92f72e62f377b92` before and after the run. The main Java 8 class is 777 B, 10 Code methods, SHA-256 `487389b770dbfdd226ae9ae3ff87c9d6be9df4e7df01781505f5d2a55e10e8f2`.

The 69 runner lines exercise `new int[n][]`, `new String[n][]`, `new int[a][b][]`, `new Object[a][b][]`, local/field/length consumers, effectful dimensions, and `new int[a][b]` as a full-dimension control. Original class, complete JADX source and complete jarde source compile and run identically under `java -Xverify:all`; jarde emits zero bytecode-reference comments. The `effects` cases distinguish first and second dimension failures by the trace and exception identity; `0` and negative dimensions distinguish unallocated tails from full allocation. The separate 72-case class remains evidence for the array-reference overload issue, not an acceptance condition of this change.

The JVM instruction distinction is explicit: `anewarray` receives a *component* class (`[I` or `[Ljava/lang/String;`) and creates one outer dimension; `multianewarray` receives the complete array class (`[[[I` or `[[[Ljava/lang/Object;`) plus the count of dimensions created now. See [JVMS `anewarray`](https://docs.oracle.com/javase/specs/jvms/se23/html/jvms-6.html#jvms-6.5.anewarray) and [`multianewarray`](https://docs.oracle.com/javase/specs/jvms/se23/html/jvms-6.html#jvms-6.5.multianewarray).
