# Same-class integer names in array initializers: extension audit

Read-only architecture audit of the existing class-source integer-constant projection, using `ConstantIntArray` as the narrow MVP. No product files or tests were changed and no toolchain, Git, or verifier was run.

## Finding

This is a small extension of the existing same-run AST projection, not a missing constant table. The class-source path already retains the candidate field identity and value, captures an opaque method AST when requested, has an `IntegerConstantName` expression that emits the field name, and publishes the resulting name range with a field anchor and method/BCI anchor. The current producer only edits switch labels and one direct integer return inside a switch arm; it does not visit array element expressions.

The fixture is exactly the useful first case: [`ConstantIntArray.java`](sources/ConstantIntArray.java#L1-L7) declares `public static final int CONST_INT = 0xffff` and returns a direct `new int[] { 127, 129, CONST_INT }` from `test()`.

## Existing proof and reuse points

- Candidate creation is already deliberately narrow. [`src/facade.rs:7147-7292`](../../../../src/facade.rs) reads each field's `ConstantValue`, retains only a spelled declaration with `static final`, descriptor `I`, exactly one `ConstantValue`, and a Java identifier, then requires a complete field inventory, unique field name, and unique `i32` value. The candidate retains the physical field item, name, and value. No new candidate registry is needed.
- The projection already checks full class and method execution and only visits recovered structured Java bodies with statements and no fallback. [`src/facade.rs:19171-19235`](../../../../src/facade.rs) joins each physical method to its captured same-run AST and sends stops through the existing projection diagnostic path.
- [`ExprKind::IntegerConstantName`](../../../../crates/jarde-java/src/ast.rs#L192-L196) is already a class-source-only `int` expression, and [`emit.rs:1179-1181`](../../../../crates/jarde-java/src/emit.rs) prints its name. It can replace a direct `Integer` child in a proven `NewArray` initializer; a new typed AST node is unnecessary.
- The AST already represents a fully proved array initializer as `ExprKind::NewArray { element, lengths, initializers, total_dimensions }`; `initializers: Some(..)` is reserved for a complete recovered store chain ([`ast.rs:307-321`](../../../../crates/jarde-java/src/ast.rs)). `program_node_count` already accounts for array lengths and initializer children ([`report.rs:11128-11260`](../../../../crates/jarde-java/crates/jarde-java/src/report.rs)).
- Existing class-source publication already has the right result container. [`src/class_source.rs:1207-1217`](../../../../src/class_source.rs) supports `IntegerConstantName` derived spans with physical anchors; [`source_text_with_method_projections`](../../../../src/class_source.rs#L12908-L12953) validates and translates method-relative ranges into the root source; `integer_constant_projection_text` rebuilds a method around replacement statements ([`class_source.rs:11322-11340`](../../../../src/class_source.rs)). These seams allow field and literal provenance to remain tied to the same class and physical method.

## Current limits that explain the empty projection

- The report-layer walk is statement-only. The first pass gathers occupied statement names, and the mutating pass enters `StmtKind::Switch`; it does not descend through expression children such as `Return.value -> NewArray.initializers` ([`report.rs:3843-3899`, `3921-4022`](../../../../crates/jarde-java/src/report.rs)). The generic node-count helper does visit `NewArray` children, but counting them is not rewriting them.
- AST capture is also switch-gated. The facade requests candidate ASTs when a class has a candidate ([`src/facade.rs:7561`](../../../../src/facade.rs)), but `recover_prepared_member` only keeps the AST for this feature when the bytecode contains `tableswitch`/`lookupswitch` (`0xaa`/`0xab`, [`src/facade.rs:19402-19444`](../../../../src/facade.rs)). `ConstantIntArray.test()` has an array allocation and no switch, so it does not receive this feature's AST handoff today.
- The handoff `IntegerConstantNameUse { name, bci, case_label }` has only two spellings. In the facade, `case_label=true` searches for `case NAME:`, while `false` searches for `return NAME;` ([`report.rs:3818-3825`](../../../../crates/jarde-java/src/report.rs), [`facade.rs:19238-19280`](../../../../src/facade.rs)). `false` is currently produced only for a direct integer return in a selected switch arm. It cannot identify a name inside an array initializer.
- Range recovery by searching emitted text is already conservative: each `case NAME:` or `return NAME;` needle must occur exactly once. That cannot robustly locate repeated array elements or the same literal in other expressions. For array elements the handoff needs the exact emitted byte range of the replaced leaf, not another special-case string pattern.
- The existing method-return predicate is specifically `descriptor.ends_with(b")I")` ([`facade.rs:19219-19224`](../../../../src/facade.rs)); an `int[]` method has descriptor suffix `)[I`. Do not treat an array return as the existing integer-return path.

## Smallest MVP shape

Extend the current projection only for a method whose same-run AST is complete, whose returned expression is the direct one-dimensional `new int[] { ... }` shape, and whose `NewArray` has `element == Type::Int`, `total_dimensions == 1`, and `initializers == Some(elements)`. Among those immediate elements, replace only a direct `ExprKind::Integer(value)` whose presented type is `int` and whose value maps to one retained unique same-class candidate. Leave all other elements unchanged. This admits the `CONST_INT` element in the fixture while avoiding arithmetic, casts, array dimensions, nested arrays, partially recovered store chains, and unrelated integer literals elsewhere in the body.

Use the existing candidate ambiguity rule and lexical-name checks. The current prewalk refuses a candidate whose name is used by a method parameter, local/for-each declaration, resource, or catch binding anywhere in the method ([`report.rs:3837-3904`](../../../../crates/jarde-java/src/report.rs)); it is intentionally method-wide and conservative. The first implementation should keep those refusals, and should also refuse any expression scope whose binding names the current prewalk does not inspect rather than claiming an unshadowed field use. No global lookup or same-value search across classes is appropriate here.

The value match remains a reconstruction heuristic, not bytecode proof of the original Java token: Java constant variables are inlined, so the same classfile `int` can come from either a field reference or a numeric literal. The specific fixture provides the source-level expected symbol. Keep the existing uniqueness requirement and report the normal field plus literal BCI anchors; do not describe every equal-value literal as proven to have been written with that symbol.

## Required API seam and publication behavior

1. Broaden the private retention gate so a candidate-bearing method with the admitted `newarray` form can retain its existing opaque `ClassSourceMethodAst`. For this MVP, the `newarray` opcode (`0xbc`) is sufficient; keep the existing switch path. This is a condition change around `integer_switch_ast`, not a second AST or a new analysis pass.
2. Extend `project_class_source_integer_constants` to inspect the direct returned `NewArray` and direct initializer leaves, reusing `IntegerConstantName`. Its existing `returns_int` argument is switch-return-specific; either add a narrowly named `returns_int_array` admission bit or perform the exact `[I` descriptor check at the facade before the new arm. Do not admit arrays via `ends_with(b")I")`.
3. Replace or extend the internal use handoff so it can carry the output range for the actual named initializer leaf together with its BCI. `case_label: bool` is insufficient. The minimum seam is a private class-source emission result that returns the emitted body and the exact ranges for `IntegerConstantName` leaves; it can use the emitter's existing node/write offsets. `emit_class_source_statements` currently returns only a `String` ([`emit.rs:194-217`](../../../../crates/jarde-java/src/emit.rs)); its opaque AST already has each expression's `OriginSet`. The generic source-map replay is not a direct drop-in at this call site because the retained class-source AST does not carry `RecoveryFacts`.
4. Feed those exact method-text ranges into the existing `MemberFamilyDerivedProjection { kind: IntegerConstantName, anchors: [Field, MethodPoint] }` and retain the existing final source-text consistency gate. The physical method report remains unchanged, and the class-level projection remains staged until every selected method and the whole class text are ready.

No public report schema, candidate table, cross-class/global value lookup, or second typed AST is required. The only internal cross-crate report API that needs broadening is the existing projection/use handoff; the exact range can be produced by a crate-private emitter helper.

## Stop and refusal boundaries

Keep the operation transactional. The current pass charges `IrItems` while collecting names and before cloning/walking the retained program, emits into a local cloned AST, charges `OutputBytes` after assembling the full class text, and only then replaces method/root text and records derived ranges ([`report.rs:3847-3918`, `facade.rs:19298-19311`](../../../../crates/jarde-java/src/report.rs)). The facade merges any stop into execution and diagnostics without publishing the staged projection ([`facade.rs:2180-2198`](../../../../src/facade.rs)). An expression walk should charge the existing budget before each newly traversed/replaced leaf; any stop discards the local clone and staged text. No new mechanism or production test hook is indicated.

For the MVP, refuse if the field table is incomplete, same-valued candidates are ambiguous, required method parameters have no stable names, the candidate name is shadowed by a binding, the method AST/body is incomplete, any fallback exists, the initializer is not a proved one-dimensional `int[]`, or a precise output span cannot be attached to the literal's BCI. Existing class-text consistency failure should continue to leave the class text untouched.
