# Loop3 prefixed retry production architecture review

## Scope and source binding

Read-only review of `prefixed_catch_retry_facts`, its `retry_loop_facts` / `try_region` consumer, exact retry catch assembly, the `continue_inner_join_arm` continuation, and `prefixed_catch_retry_tests.rs`. No build, tests, CLI, or source edits were run. Source pins are in `pins.json`.

## Shape actually proved

`prefixed_catch_retry_facts` at `crates/jarde-java/src/region.rs:9583` proves a narrow **exception-handler retry cycle**. It requires one non-cloned header block with a nonempty unprotected lead and protected suffix, one named catch type and one exact physical/canonical handler row, the row beginning at the lead boundary and covering only that canonical header owner, an exact protected throw-site/exception edge, and a handler branch whose only two normal successors are an unconditional retry transfer to the header and a normal-completion entry. The already-walked `entry_prefix` must be a unique linear normal path into the header.

The retry proof does not call `NormalFlowView::loop_entered_at` and does not discover a natural loop. Its retry edge is reached from the exception handler; the returned `RetryLoopFacts` authorizes the existing region writer to render the proved exceptional cycle as `Region::Loop`/`LoopContinue`. The ordinary normal-flow loop finder is not the evidence for this shape. The helpers named `loop_break_body_edges_closed` and `loop_break_body_acyclic` are reused here only to validate the finite normal-completion owner DAG; they do not turn that DAG into a natural loop, and this path does not prove or emit a gateway.

The normal completion walk stops at the exact Try join. It rejects foreign entry/exit edges, cycles, non-normal edge crossings, clones, and pre-owned nodes, then records the DAG owners separately from the protected header, handler, and retry block. Later `retry_owned_regions_complete` requires the rendered Try body, catch handler, and visited delta to match those exact owner sets. The existing guard remains responsible for catch parameter/type and SSA binding. `try_region` gates the new proof to an otherwise unframed top-level context and snapshots the complete walker state for the prefixed case; stop or incomplete assembly restores that state without refunding budget.

For the fixed inner normal join, `continue_inner_join_arm` admits the validated `Straight + LoopBreak` tail only when the physical terminal BCI matches the break source, the active loop target header matches, and the active break target is the enclosing frame boundary. It checks the continuation's exact normal predecessors, scope, path, and newly visited block set before appending it. In the fixture this keeps BCI 76 straight and the physical BCI 79 transfer as `LoopBreak` to header 11; it does not invent a bytecode gateway.

## Residual budget-accounting concern

There is a resource-accounting/polling concern in the large proof, not a demonstrated semantic misrecovery. At `region.rs:9650-9662`, the proof prepays one combined `blocks + edges + instructions + throw-sites` scan. It then has a bounded `find` over canonical blocks (`9665-9672`), another full canonical-block loop (`9676-9688`), a full edge loop for header/handler closure (`9792-9810`), materializes all edge tuples with a non-polling `collect` (`9970-9975`), and later performs another full edge loop for owner closure (`10037-10101`). The helper closure and Kahn scans have their own precharges at `loop_break_body_edges_closed` / `loop_break_body_acyclic` (`4654-4765`), but those do not make the extra direct edge materialization itself cancellable. The current aggregate precharge appears to cover only one base block/edge pass; it is not obvious that the repeated base passes and the non-polling materialization are fully represented.

There is also a duplicate visited checkpoint on the prefixed path: `try_region` clones `self.visited` into `previous` (`10831-10833`) and then `loop_body_trial_state` clones it again after charging its snapshot units (`10837-10842`, helper at `5621-5674`). The first clone is retained for the final delta comparison. This is bounded by the method's visited set but is not separately charged at its point of copy. The late-stop test validates non-publication and no budget refund, but not a per-operation accounting lower bound or cancellation during edge-vector materialization.

Minimal follow-up if the budget contract requires exact scan accounting: account for each repeated base pass and the checkpoint copy in the existing AnalysisSteps dimension, and materialize edge rows with a polled, charged loop (or avoid the copy by making the existing helper consume canonical edge references). This can remain local to `prefixed_catch_retry_facts`; it need not widen accepted CFG shapes or change the shared helper's meaning. I did not modify implementation or tests.
