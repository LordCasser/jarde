# Independent adjudication: prefixed retry budget concern

## Ruling

Classify the review’s residual accounting/poll-latency point as a bounded cost-model debt to split, not a demonstrated release-blocking violation of the current OpenSpec acceptance. This conclusion is not based on tests passing. It follows from the existing contract’s abstraction: `AnalysisSteps` is a deterministic work/processing bound, not a count of CPU instructions, and the current proof has finite graph-sized scans with a checked precharge plus explicit large-product precharges. The OpenSpec capability requires a real stop to retain cause/usage and publish no partial loop; it does not state a one-charge-per-iterator-element rule for Java recovery scans.

There is a narrower caveat: if Jarde’s intended hard contract is that every iteration of every collection scan must consume one `AnalysisSteps` unit, then the current aggregate does not visibly account for every repeated pass and would need correction before claiming that stronger contract. Neither the prefixed-retry OpenSpec nor the Java recovery spec states that per-item rule; the `budget.rs` description uses “one worklist pop/processing step,” which allows an algorithm to precharge a deterministic bounded amount for a scan. Root should preserve this caveat when deciding whether to make the cost model stricter.

## Evidence and bounds

At `region.rs:9583`, only `prefixed_catch_retry_facts` handles this shape. Before its whole-method work, it requires a nonempty lead, one named catch site, a single physical and canonical handler row, exact row/handler/type/lead agreement, and canonical protected list `[start]`. The later physical-range scan requires exactly one root-path block intersecting the row and that block must be `start`. Thus the candidate is tied to one row start/one header in the method rather than being a per-block × per-row retry search. The caller (`try_region`, lines 10797–10829) first applies a fixed prefixed-retry shape and an otherwise empty frame gate. A successfully accepted candidate builds one synthetic RetryLoop and exits the walk; the prefix is already consumed and stays outside that loop. The code does not prove that a refused candidate can never be reconsidered through a later fallback walk, so the safe statement is “one eligible start/row, no cross-product scan,” not an unconditional claim of exactly one function invocation on all refusal paths.

The proof performs an aggregate `AnalysisSteps` precharge of `blocks + canonical edges + code instructions + throw sites` at lines 9650–9662 before block/range/SSA/target scans. That amount is explicitly O(method IR size) and includes one edge-sized advance charge before `all_edges` is materialized at lines 9970–9975. The header edge closure, throw-site checks, owner closure, DFS, and branch-target construction poll while iterating. The two shared normal-DAG helpers add their own precharges: `loop_break_body_edges_closed` charges `edges × normal owners` before its nested scan, and `loop_break_body_acyclic` charges `2 × edges + 4 × owners` before building and topologically consuming the owner graph. Those helper charges bound the potentially larger product; their implementation is not bypassed by the aggregate.

`try_region` performs a full mutable-state checkpoint only after the prefixed retry proof succeeds. `loop_body_trial_state` polls and charges the counts of visited nodes, catch joins, terminal owners and their blocks, fragmented state, excluded-edge nodes, monitor owners, and fixed overhead before cloning them (lines 5621–5672). Stop/refusal restores that state without refunding usage. There is also a second `visited.clone()` into `previous` just before the charged trial-state snapshot (lines 10831–10842); this is a real, bounded O(visited) duplicate copy that is not separately itemized.

The only uninterrupted collection build called out by the review is the `all_edges` tuple `collect` (one E-sized vector of cloned canonical IDs). It has an earlier E-sized aggregate precharge, so its allocation/work is bounded and not wholly uncharged. It has no poll within the copy, but the preceding full edge scan polls and the following `loop_break_body_edges_closed` polls before processing/publishing the proof. Cancellation can therefore be observed after that one bounded copy, not during it. This is a responsiveness gap, not a path that publishes after cancellation or skips all later polling. The two duplicated state snapshots and repeated O(E) scans likewise make the constant factor larger than the single aggregate’s count suggests, but do not create an unbounded search or an unbounded number of materialized vectors.

## Contract comparison

The Loop3 design requires that the prefixed/nonempty-lead and exact-row shape gate run before the added whole-method scans, that old Loop2 contracts remain unchanged, and that budget/cancel Stop restore complete state while retaining charged use. The main Java recovery spec requires an interrupted proof to retain the actual reason and usage and not publish partial ownership; the acceptance task specifically calls for bounded stop, cancellation, and late-stop rollback. The current implementation has that admission gate and rollback, and the review identified no way for these scan/copy concerns alone to bypass the later polling or commit a partial owner set.

The P2 `AnalysisSteps` enum comment defines a unit as a worklist pop/processing step charged before it runs. It does not define the unit as a CPU operation or require exact accounting of each machine instruction. The JVM IR contract’s strict “before allocation” storage language governs IR graph construction; this Region proof’s temporary edge tuple is charged in `AnalysisSteps` by size, and the invoked shared closure helpers each prepay their own scan bounds. No new `IrItems` requirement for this private temporary proof vector is stated in the prefixed-retry change.

## Follow-up recommendation

Record a small follow-up to make the cost model easier to audit: either split the prefixed proof’s aggregate charge into named scan-bound charges and poll during edge-vector construction, or document which aggregate prepays each bounded pass and why that weight is the intended `AnalysisSteps` unit. Consider eliminating/reusing the second visited snapshot or charging its additional copy. Keep this local; do not expand the accepted CFG shape or change the shared helpers. If the project chooses a strict per-item iteration contract, treat the direct repeated scans and duplicate visited clone as required fixes before claiming that contract.
