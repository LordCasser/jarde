## What the evidence says

The original physical `test(Ljava/util/Map;I)I` has a 74-byte Code array. BCI 69 is a three-byte `goto` (one opcode byte plus a signed 16-bit branch offset) whose offset is -62, so its destination is BCI 7 (`69 - 62`). BCI 72 loads the result local and BCI 73 returns it. The candidate map audit reports exactly BCI 69 missing for this method; the other physical BCIs are mapped. This is an implicit loop-tail transfer: the Java source has no corresponding explicit statement at that position.

The recovered whole-class source still contains the enclosing loop and its explicit body statements. In the selected candidate report the test method is `structured`, `java`, `contains_statements`, with 3 regions, 13 statements, and 41 source-map segments. BCI 63 and 66 (the `length` and `x` increments in the loop body) have direct segments; BCI 72/73 have return segments. BCI 69 has no source-map segment/origin. This is therefore a narrow provenance-coverage gap, not a missing loop reconstruction or a missing source statement.

The emitter architecture explains the shape of the gap. Atlas inspection of `emit.rs` found `emit_source_map` replaying the already-built AST against the artifact text, and `Emitter::stmts` wrapping each AST statement in `node(&stmt.origin, ...)`. `node` records a segment only for the emitted byte span and uses that node's existing `OriginSet`. `stmt_with_indent` sets its write anchor from `stmt.origin.primary().bci()` and emits a `While` from its label/condition/body/closing brace; there is no separate emitted AST node for a JVM back-edge instruction. `put` in replay mode checks exact text agreement; normal emission charges `OutputBytes`, and `node` checks phase continuation before publishing the segment. Thus the map does not infer every control-flow edge from Code; it reports provenance carried by the nodes whose text is emitted.

Direct inspection of the pinned `region.rs` at line 17904 confirms `implicit_tail_latch_origin` only examines `body.last()`. It accepts (a) a final `Region::Straight`, using its last block, or (b) a final `Region::If` with `join: None` under its guard, where each arm is exactly one `Region::Straight` block and exactly one arm's final instruction is a JVM `Return`; the other arm is the latch candidate. It then checks the header's natural loop is reducible with exactly one latch, that candidate ends in `goto`/`goto_w` to the header and has that as its only normal successor and only canonical outgoing edge, and (when a `ForHeader` exists) that the preceding update matches its block and slot. It polls and charges analysis work while inspecting arms, latch sets, and edges.

At `header_tested_loop` line 18465, `Some(latch_bci)` is appended to `gateway_origins`. `build.rs::loop_region` folds those into the loop statement's `OriginSet` as derived origins at line 21963. `Emitter::stmts` wraps each statement in `node(&stmt.origin, ...)`; the node records a segment for its full emitted span. The selected candidate report's loop-sized segment `[284,729)` has primary BCI 11 and no derived origins. This means no BCI 69 origin reached that segment in the recorded output. Static shape suggests why the helper may return `None`: the source's tail has two nested `if`s and a `break` arm. If the final Region is the outer `if`, its nested arm fails the helper's straight-single-block requirement. If the final Region is the inner `if`, the break transfer and back-edge are both non-return arms, so the helper rejects the second latch candidate. This is a likely rejection path, not a measured result: the source text is not a Region dump and no probe of the actual helper return was run.

## Assessment and bounded direction

**Verified:** BCI 69 is an actual back-edge to loop header BCI 7; it is absent from the candidate map; existing mapped spans do carry derived origins (for example BCI 11 is derived on a loop-header-owned span); and source-map publication is AST replay rather than a sweep over physical Code.

**Not yet verified:** which Region shape is `body.last()` for this concrete loop, whether the helper returns BCI 69, and whether physical control-flow edges are contractually required to map when they have no standalone source statement. No new probe was run here. The recorded outer loop segment has no derived BCI 69; source inspection shows exactly where a successful proof would be attached, but not whether this input reached that branch.

The existing plumbing is sufficient if the narrow proof succeeds: the Region already carries `gateway_origins`, the builder moves them into the loop statement origin, and replay publishes it on the loop-sized segment. Therefore first follow why this candidate does not produce BCI 69, rather than adding a separate mapper. If the final-`If` shape is the blocker and this one site is in scope, the smallest bounded extension appears to be proof over the concrete acyclic tail decision tree: the outer null branch and nested y-test have two loop-exiting break leaves and one unique back-edge latch leaf. Each branch/leaf must be tied to the same loop, all joins and incoming/outgoing edges must close exactly, and the latch must remain the unique natural-loop latch returning to this header. Reuse the exact loop-exit evidence already available around `header_tested_loop`; do not classify arbitrary transfer leaves as breaks or recursively accept unbounded trees. Reject other nested/multi-block, joined, ambiguous, exceptional, subroutine, or extra-edge shapes. Do not tag a loop with an unproved transfer or broaden mapping to all body edges. If statement-only mapping is the intended contract, keep BCI 69 unmapped and document that contract rather than calling the physical map exhaustive.

Any implementation must keep primary statement origins unchanged, preserve exact text replay and physical method identity, add derived provenance only after the same exact loop/latch proof succeeds, and make the new origin charge/publish through the existing replay path. A cancellation or budget stop must still return only the charged prefix; a map must not be post-hoc completed after a stop or failed text gate. Refusal or ambiguous/exceptional/subroutine edges must retain the current conservative behavior. This note does not authorize those changes in the active leaf.
