# Nested conditional value

`NestedConditional.nested(int)` is the exact local-value shape `int t = a > 10 ? (a > 100 ? 3 : 2) : 1;`. `javac --release 8 -g:none` produced classfile major version 52; `hashes.sha256` pins both original classfiles and source files, and `javap.txt` is the full `javap -v -c -p` listing. The target method's bytecode tests at BCI 3 and 9, sends the three arms at BCI 12, 16, and 20 to the join at BCI 21, stores the joined value at BCI 21, then returns local 1 at BCI 23.

The output in `ssa-probe.txt` comes from a one-off probe using the public method-IR analysis API (`ssa-probe.rs`). The canonical CFG has normal predecessors `12 -> 21`, `16 -> 21`, and `20 -> 21`. At block 21 there is one operand-stack `Stack(0)` Phi with three `Instruction` inputs defined at BCIs 12, 16, and 20. There is also a `Local(0)` Phi for the unchanged argument; its three operands all resolve to the method-entry local and the trivial Phi is replaced by that entry value. This distinguishes the value join from an unresolved `Entry`: the stack Phi exists and is complete in SSA.

Current Jarde's `jarde-method.java` reports `quality=fallback`, `representation=mixed`, and `syntax_status=not_java`. It emits the outer and inner `if` tests but no arm-value expression; at BCI 21 it says stack depth 0 is the entry state with no producing instruction, then at BCI 23 says the read of `local1` has no declared local because its write was refused. `jarde-report.txt` and `jarde-report.json` preserve the stage and evidence records: SSA completed; the region record for the root `if` claims blocks `[0,6,12,16,20]`, and a separate `straight` region claims join block `[21]`. The public report records regions as a flat list, so this evidence does not claim a serialized arm tree.

JADX 1.5.6 emits the joined expression as `i2 = i > 100 ? 3 : 2` inside the outer true arm, assigns `1` in the outer false arm, then returns `i2`. Its source compiles with the package-adjusted runner. The original and JADX builds both pass `java -Xverify:all`; their complete output files are byte-for-byte equal, including boundary cases 9/10/11/99/100/101 and effect/exception cases. The effect trace confirms that only the selected arm runs, an outer-call exception prevents the inner test, an inner-call exception prevents either inner arm, and the selected arm's exception is observed after both tests. The failing arm uses the fixed message `"arm-2"` so the baseline isolates conditional-value recovery from string-concatenation recovery.

The frozen Jarde baseline was built from commit `ee18bef1c5919370b4889af964519733001278a0`; its CLI hash is in `jarde-cli.sha256`. Its full class-source output is retained in `jarde/NestedConditional.java`; with the fixed exception message, the helper and both limit methods compile, while javac reports missing-return errors only in `nested` and `nestedEffects` (see `jarde-javac.stderr`). The single-method excerpt is intentionally stored separately as `jarde-method.java`. No Jarde runtime output exists because those two methods keep the emitted class from compiling.
