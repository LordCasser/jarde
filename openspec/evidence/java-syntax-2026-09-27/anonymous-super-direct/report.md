# DT-06a: no-capture anonymous superclass constructor arguments

This fixture isolates the no-capture case from the existing `anonymous-super-args` capture fixture. The complete Java 8 source oracle is [AnonymousSuperDirect.java](../../../../tests/fixtures/proved-java-structure/anonymous-super-direct/AnonymousSuperDirect.java); all three physical class files and their SHA-256 values are frozen beside it.

The original source compiled with `javac --release 8 -g:none`, matched all frozen class hashes, and ran under `java -Xverify:all` with output `13:2`. The `make()` bytecode has `new AnonymousSuperDirect$1` at BCI 0; it invokes `next()` at BCIs 4 and 7 in left-to-right order, then calls `AnonymousSuperDirect$1.<init>(II)V` at BCI 10. The anonymous constructor forwards those two `int` parameters to the selected `Base.<init>(II)V`; the other available overload is `(IJ)V`. Its classfile has no synthetic capture fields or enclosing-instance parameter. See [original-javap.txt](original-javap.txt).

JADX produced a complete source set of two files and restored the expression as `new Base(next(), next()) { ... }` in `AnonymousSuperDirect.make()`. Those sources compiled as Java 8 and ran under `-Xverify:all` with the same `13:2` output. The source snapshots and compile/run logs are in [jadx-source](jadx-source/), [jadx-javac.log](jadx-javac.log), and [jadx-run.log](jadx-run.log).

Jarde returned source for all three physical classes: `AnonymousSuperDirect`, `AnonymousSuperDirect$1`, and `Base`. `make()` remains `new AnonymousSuperDirect$1(next(), next())`, while the anonymous implementation is a separate physical class whose `(II)V` constructor calls `super(arg1, arg2)`. This makes the allocation target, argument order, overload descriptor, and absence of capture state directly auditable, but does not restore anonymous-class source syntax. The complete three-file source set compiled with `javac --release 8 -g:none` and ran under `-Xverify:all` with `13:2`. Snapshots and per-class CLI results are in [jarde-source](jarde-source/) and [jarde-cli-status.txt](jarde-cli-status.txt).

`replay.py` rebuilds the frozen original classes, checks each SHA-256, decodes and recompiles both complete source sets, runs both with verification enabled, and records `javap` evidence. It builds a fresh Jarde CLI in a temporary `CARGO_TARGET_DIR`; the temporary directory is removed on exit. Temporary paths are normalized in saved logs. Set `JADX_ROOT` if the JADX checkout is elsewhere. This is baseline evidence only: it does not modify production code or the separate capture fixture.
