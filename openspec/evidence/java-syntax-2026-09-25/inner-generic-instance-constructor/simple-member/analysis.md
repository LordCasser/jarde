# 非泛型成员内部类创建：先拆出调用点边界

[`SimpleOuter.java`](../fixture/SimpleOuter.java)、[`UseInner.java`](../fixture/UseInner.java)、[`InnerRunner.java`](../fixture/InnerRunner.java) 由 `javac --release 8 -g:none -Xlint:-options` 编译。`UseInner.make(SimpleOuter,int)` 原文是 `outer.new Inner(SimpleOuter.mark("A", value))`，返回 `Object`，故方法头本身不依赖嵌套类型拼写。冻结 `UseInner.class` SHA-256 为 `e44ce3a6eb4cba73ec50c530727d6764680d84e14c2d58d899083b002028ccae`，成员 class SHA-256 为 `7ce649089f60472371b1a2ca9308175d601dd3df259752dd2451d941459d2c4d`；字节与 [`javap-UseInner.txt`](javap-UseInner.txt)、[`javap-SimpleOuter$Inner.txt`](javap-SimpleOuter$Inner.txt) 已冻结。

原 class 在 `java -Xverify:all` 下给出 `7:IA`、`null:I`：调用方的 `I` 总执行；限定接收者为空时，参数内的 `A` 不执行。BCI 0/3 分配与复制内部类，BCI 4/5 读取并复制外层实例，BCI 6 `Objects.requireNonNull`、9 `pop`，随后 BCI 10–13 才求值普通实参，BCI 16 调用物理 `(Lnested/SimpleOuter;I)V` 构造器。调用者的 `InnerClasses` 将目标指向 `SimpleOuter.Inner`；目标构造器 BCI 2 把首参写入 `ACC_SYNTHETIC` `this$0`，BCI 6 才调 `Object.<init>`。因此物理首参不是源级普通实参，空值检查也不是可随意移到 `A` 后的无关语句。

本机 JADX 1.5.6 对完整 jar 输出 [`UseInner.java`](jadx/UseInner.java) 的 `Objects.requireNonNull(simpleOuter); return simpleOuter.new Inner(SimpleOuter.mark("A", i));`，并在 [`SimpleOuter.java`](jadx/SimpleOuter.java) 内嵌 `Inner` 声明。三份 JADX 源以 Java 8 重编成功；[`jadx-run.txt`](jadx-run.txt)与[`original-run.txt`](original-run.txt)逐行相同。JADX 的 `ClassModifier.removeFieldUsageFromConstructor` 仅在首形参类型等于外部类且构造器首块的 `IPUT` 把它存入捕获字段时设置 `SKIP_FIRST_ARG`；`InsnGen.addOuterClassInstance` 又要求该标志、`isInner()`、首参数类型与声明外层类型相同，才发射限定接收者。可借鉴其“物理首参与源级实参分界”，但这些局部门槛没有独自证明本调用点的空值检查、效果顺序、唯一目标或 verifier-valid 异常变体，不能照搬为 Jarde 的完整准入。

Root 构建的基线 Jarde CLI SHA-256 `b72291f8cf4c75aa9a8db9d3c2a3a0f71bbb278b41180448af21de308048eadd`。无论输入单个 class 还是含全部类的 jar，`new@1` 首先在 BCI 5 的 `Duplicate` 拒绝 `jre_new_interleaved_effect`；[`jarde-UseInner.json`](jarde-UseInner.json)为 `fallback/mixed`，完整 [`jarde-UseInner.java`](jarde-UseInner.java)缺返回，Java 8 重编失败。即便放宽该局部指令门，现有 `ExprKind::New { ty,args }` 也不能拼 `outer.new Inner(args)`；`new_expr` 会把物理外层实例误当普通构造参数。方法恢复只持有声明类与同类成员事实，`InnerClasses` 已在 reader/类源码装配，但尚未作为可证的目标类关系交给调用点。依赖解析还必须按选中物理环境确认目标 class，不能由 `$Inner` 名称推断。

设计边界要求分别验证错误外层关系、不同身份的限定接收者/物理首参、错误 null-check 位置、额外可观察效果与缺失目标 class，不能把尚未构造的负控写成已验证事实。优先复用 `new@1` 的真实 SSA 构造站点、现有 reader 的 `InnerClasses` 与类源码装配的确认读取，在私有证明中绑定物理目标、首参栈值、半开 null-check 区间和后续普通参数顺序；源码形状只需为既有 `New` 增加经证明的限定接收者，不需要公开全局 IR 或仅按类名跳过首参。调用点可先用冻结的目标 class 作编译依赖验收；把 `SimpleOuter` 与成员类全部作为新源码重编还要求独立的成员声明/合成字段投影。已有[泛型外层正例](../analysis.md)又需类级 `T`/成员级 `V` 作用域，不能把本非泛型拆解冒充完整泛型支持。
