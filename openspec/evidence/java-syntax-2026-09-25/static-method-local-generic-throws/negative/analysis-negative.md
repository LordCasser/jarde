# Static direct-return method with a method-local generic throws variable

`EchoOnly.echo` is the narrow candidate: `public static <T, X extends Exception> T echo(T value) throws X { return value; }`. The Java 8 fixture compiles and runs under `java -Xverify:all`; the runtime prints `verified`. `javap -v` reports descriptor `(Ljava/lang/Object;)Ljava/lang/Object;`, generic `Signature` `(TT;)TT;^TX;`, and an `Exceptions` entry of `java.lang.Exception`. At baseline Jarde refuses the generic projection with `generic_source_shape_unproved`: “generic throws type cannot be preserved by the physical Exceptions clause.” This is the exact positive shape the independent change must recover; the replay has `--mode baseline` and `--mode recovered` assertions so the original failure and post-change boundary remain reproducible.

The control `ioEcho<T, X extends IOException>` has `Exceptions: IOException` and a throws-variable signature. Jarde refuses it with the same code and message. This indicates a broader current boundary than only an Exceptions erasure mismatch; the fixture does not establish whether any bound other than `Exception` can be accepted.

The other controls exercise body and class scope. `sideEffect` calls `System.nanoTime()` before returning the parameter; `wrapped` returns `echo(value)`; both are rejected with `generic_source_shape_unproved` because the recovered body is not a direct parameter return. In a class containing same-class calls to `echo`, Jarde instead reports `generic_call_binding_unproved` (“a same-class Methodref names this method or an adjacent overload”). The generated output is explicitly marked as not a compilable project. A same-class consumer therefore carries class-level recompile/binding debt and should be audited as a separate scope from the isolated method shape.

JADX 1.5.6 decompiles the bundled `ThrowsProbe` class and its full emitted source compiles under `javac --release 8`. This comparison does not establish semantic preservation for thrown checked exceptions; the fixture only executes calls that do not throw. The replay script checks Java 8 compilation, JVM verification and output, `javap` generic-signature evidence, JADX source compilation, and the exact Jarde refusal markers. Its Cargo target and all generated outputs are temporary and removed on exit.

The replay also mutates the classfile `Signature` metadata without changing method code or the physical `Exceptions` attributes. Replacing the declared throws variable `X` with undeclared `Y` leaves `javap` readable and passes `java -Xverify:all` class loading; Jarde refuses it with `jvm_signature_scope_unproved`. A second mutation changes `ioEcho`'s declared bound from `IOException` to `Exception`, leaving its physical `Exceptions: IOException` entry unchanged. `javap` confirms that mismatch, and the reader's erasure proof rejects it as `jvm_signature_erasure_mismatch` before source-shape projection. These deliberately malformed generic signatures are not compilable Java source; the mutations make the metadata boundary reproducible while retaining valid JVM verification.

After implementation, root independently ran `replay.py --mode recovered` with a separate Jarde build: the isolated `EchoOnly` method projects `<T, X> ... throws X`; `ioEcho` keeps its physical `IOException` because the first bound is outside the scoped JDK roots; `sideEffect`, `wrapped`, and same-class `echo` still refuse locally. Both mutated classes load with `-Xverify:all`, and their exact reader refusal codes remain unchanged. This replay does not claim that the same-class physical fallback yields an entirely recompilable class.
