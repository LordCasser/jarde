# 位置约束负例 D/E（真 javac 8 N1$Stat 类的等长字节补丁合成探针）

补丁脚本：patch-position-negatives.py（自检：原类 SHA256 必须等于 root 冻结转录记录、目标模式全类唯一）。
补丁基准类：fixture/n1-realjavac8-rerun/N1$Stat.class（真 javac 8 重编，SHA 与 root 冻结类逐字节一致）。

## D：pop 缺失形（返回值未被丢弃）
- 补丁：BCI 9 的 pop(0x57) → astore_1(0x4c)（等长；locals=2 内；类型健全）。
  （首版 astore_2 越过 max_locals=2 触发 ir_frame_inconsistent，已弃用——见 fixture/position-negatives 的演进步。）
- javap 存证：
  int use(N1);
    Code:
       0: new           #2                  // class N1$Inner
       3: dup
       4: aload_1
       5: dup
       6: invokevirtual #3                  // Method java/lang/Object.getClass:()Ljava/lang/Class;
       9: astore_1
      10: bipush        9
      12: invokespecial #4                  // Method N1$Inner."<init>":(LN1;I)V
      15: invokevirtual #5                  // Method N1$Inner.total:()I
      18: ireturn
}
- 行为：baseline 与 fixed 二进制均拒绝（use 整方法 not recovered，jre_new_shape 门；
  转录见 postfix-negative-pop-missing.txt / prefix 副本），**不因拼写扩展而放行**。

## E：四条窗口错位形（aload_1; dup → nop; aload_1）
- 补丁：BCI 4-5 的 aload_1, dup → nop, aload_1（等长；栈形态不变、类型健全）。
- javap 存证：
  int use(N1);
    Code:
       0: new           #2                  // class N1$Inner
       3: dup
       4: nop
       5: aload_1
       6: invokevirtual #3                  // Method java/lang/Object.getClass:()Ljava/lang/Class;
       9: pop
      10: bipush        9
      12: invokespecial #4                  // Method N1$Inner."<init>":(LN1;I)V
      15: invokevirtual #5                  // Method N1$Inner.total:()I
      18: ireturn
}
- 行为：baseline 与 fixed 均响亮拒绝，但拒绝发生在更早的既有解码门（ir_frame_deferred），
  未达形状门。等长字节补丁的边界：任何打破 [load, dup, check, pop] 连续性的重排都会同时破坏
  消费方类型所强制的槽位纪律，无法在保持解码干净的前提下命中形状门——E 的『响亮拒绝』由既有
  解码拒绝承担（两腿一致、修复前后一致），D 承担了命中形状门的精确证明。
- 实参区间门（实参 BCI 须落在 pop 之后、构造器之前）无源码可表达形（javac 总是按序在窗口内发射实参），
  亦无等长补丁可把实参 push 移出窗口而不破坏类型——该臂由既有测试与代码路径覆盖，本片未触碰。
