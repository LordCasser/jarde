## ADDED Requirements

### Requirement: 异常 handler 中的重复迭代清理可恢复为唯一 finally

系统 SHALL 在 Java 8 方法中，只有当正常完成和异常完成的迭代清理具有相同的可观察操作、顺序与次数，且异常表、循环入口、原异常重抛和全部物理指令的归属均被证明时，把重复副本呈现为一个可重编的 `try/finally` 循环。仅由异常路径进入的单入口循环 MUST NOT 因方法入口不可达而误判为不可约；证明不足时 MUST 保留完整拒绝及来源，不能静默删去清理循环。

#### Scenario: 正常与原异常路径

- **WHEN** 固定 Test11 同布局 Java 8 类的正文正常返回或抛出异常，清理循环按列表逐项调用且自身成功
- **THEN** 原类、固定 JADX 与恢复源码在 Java 8 重编及 JVM 验证运行中的逐项调用顺序和最终结果 SHALL 一致，恢复源码只含一份 `finally` 循环

#### Scenario: 清理循环自身抛错

- **WHEN** 正常或异常路径的迭代器操作或逐项清理调用抛出异常
- **THEN** 恢复源码 SHALL 按原字节码的执行次序与异常覆盖关系传播该异常，不得重入同一份清理、吞掉异常或再次重抛已被覆盖的原异常

#### Scenario: 循环或异常所有权不完整

- **WHEN** 异常路径循环有第二个外部入口、两份循环的列表值/调用目标/操作序列不同、异常范围覆盖了清理自身、重抛值被改写或存在未声明的边/出口
- **THEN** 系统 MUST 拒绝唯一 finally 投影；真正多入口循环仍按不可约边界拒绝，保留对应字节码与异常行来源

#### Scenario: 来源与停止

- **WHEN** 证明成功、预算耗尽或请求取消
- **THEN** 成功产物中两份物理清理及目标方法的全部 BCI SHALL 可追溯；停止或证明失败时 MUST 原子保留安全拒绝，不得发布半个循环或半个 finally
