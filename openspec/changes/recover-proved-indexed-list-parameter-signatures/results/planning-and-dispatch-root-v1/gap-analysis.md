## Two concrete blockers

1. The same-run generic-return candidate is a return-shape gate. `GenericReturnValue::VoidBody` is documented as a complete void body and is only constructed for a body ending in `return;` (`crates/jarde-java/src/report.rs:8543-8556,11463-11523`). `prove_generic_list_parameter_body` starts by destructuring only `VoidBody`, returning `None` for every other candidate (`src/facade.rs:14483-14513`). In addition, `ordinary_parameterized_declaration` permits this candidate only when the parsed result is absent; its existing `Conditional` branch is specifically a ternary return from a boolean parameter and two parameter slots, not an arbitrary boolean body (`src/class_source.rs:7424-7428,7559-7602`). Thus a structured method returning `Z` cannot currently carry the complete parameter-use census that generic projection needs. This is separate from the `get` rejection.

2. The closed List receiver contract has no `get:(I)Object` entry (`src/facade.rs:12943-12952`). The body proof rejects any receiver call not in that table (`14660-14676`). Each matched invoke already carries optional SSA result identity and a result-value fact, in addition to receiver/argument facts (`src/class_source.rs:2588-2607`); the physical get-to-cast chain can therefore be checked without a new IR payload. The existing retained-AST call-site join should be extended only if it can prove the exact cast child; otherwise keep the optional generic projection refused. The contract supports `iterator`, `add`, `remove(Object)`, `size`, and `clear`, then separately proves their exact AST/value uses. The `get` site in the capture therefore prevents closed-use proof even though the displayed cast and assignment remain explicit and structured.

The generic declaration is staged/finally re-proved through the same body helper (`src/facade.rs:17985-18008,18509-18551`) and the ordinary Signature gate (`src/class_source.rs:7183-7198,7424-7455,7550-7572`). Fixing only one gate still leaves the other.

## Smallest sound reuse path

Keep the physical Signature parser as the sole source of `E`; do not infer `E` from the cast. Extend the existing complete-body parameter-use evidence so it can describe a complete body with a supported primitive result, with an explicit descriptor/result-category check at the ordinary Signature gate. Prefer factoring the current `VoidBody` census into a shared body-parameter evidence payload and separating its return category (`void` versus an exact unchanged primitive descriptor). This reuses the existing unchanged-parameter, read-BCI, and receiver-call census without adding IR. A new narrowly named doc-hidden primitive-body variant is a smaller localized alternative if factoring would spread changes, but it must only admit a primitive return whose physical descriptor and parsed Signature result are the same primitive; do not extend this to reference, type-variable, array, or inferred returns. The source method body itself remains the same physical candidate and no return rewrite is implied.

Add an exact `List.get:(I)Object` use branch to the existing List closure, but treat it as a contract/use proof, never as an element-type inference source. Reuse the existing invoke key, same-caller physical invoke facts, retained AST call sites, body-value facts, and Signature-selected `E`. Require a unique `List` interface call with one `int` argument; its result must be unreplaced and have the exact call BCI definition, with its only consuming use the physical `checkcast E`; the AST must show that exact cast over that call. Keep the cast in projected output. The cast target must equal the concrete `E` selected from the parsed `List<E>` Signature. This lets the existing AST local assignment remain type-correct after the parameter is rendered as `List<E>` while avoiding deleting a real cast or trusting Signature alone. The proof must preserve the existing closure rule: every parameter read is accounted for by an approved exact receiver-use site, and any unsupported read/write, extra consumer, duplicate call key, alias, phi/replacement, mismatched cast, incomplete AST, or unrecognized overload declines the generic projection.

No new List element type is derived from `get`'s return fact: the type comes only from the parsed Signature after the independent physical/AST checks. No broad “remove casts” rule is needed; the demonstrated output can retain `(String)` unchanged.

## Decision boundary

This appears achievable by extending the current transaction-local candidate and same-class call proof. It does not require a new solver, general cast-removal pass, or public AST/IR. The first missing carrier is a complete-body parameter-use candidate that is not void-only; the invoke record already has `result_value_fact` (`src/class_source.rs:2604-2607`), so no new IR is indicated. The remaining proof work is joining that result to one physical `checkcast E` and the exact retained AST call/cast. If the AST helper cannot expose the cast as a unique exact child of the matched get call, that is the specific missing source fact to verify before implementation; do not substitute descriptor-only matching.
