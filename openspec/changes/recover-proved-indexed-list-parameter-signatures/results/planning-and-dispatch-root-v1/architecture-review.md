# NestedLoops2 primitive-result List signature path: static adversarial review

## Conclusion

The direction fits the existing same-run evidence path, but the return category must remain explicit throughout projection. A narrowly named complete-body carrier (`result: None` for void, `Some(BaseType)` for an exact primitive result) can reuse the current whole-Code/SSA/effects/parameter-read census without adding IR, a pass, or a RecoveryRequest input. Gate primitive-result admission in `ordinary_parameterized_declaration` to a parsed Signature result that is the same primitive as the physical method descriptor and the carrier; keep the existing method-local-generic/void-only paths void-only. Also require at least one selected, fully closed exact `List<ConcreteReference>` formal for this new use. Do not let a generic “body complete” marker become generic return-source evidence.

The exact `List.get:(I)Object -> checkcast E` proof can reuse the existing facts, but one precise AST relation is currently absent from its exported query surface. `class_source_invoke_result_uses` reports a generic `Other { consumer_bci }` for the parent of a producer call; it does not name that parent node's AST kind or prove a direct edge. `class_source_local_assignments` exposes only an assignment RHS's outer cast type/BCI. An opaque doc-hidden boolean query inside `report.rs` is the smallest safe bridge: for this complete method, prove exactly one assignment RHS is `Cast(E, Call(key))`, with the cast at the supplied BCI and the direct child the unique exact producer call. Reuse the existing AST, call-target inventory, complete-Code check and charging; do not publish a new AST record or expand the `Other` enum. Then pair that boolean with the already-captured physical SSA chain.

## Adversarial constraints

1. **Do not lose the primitive result.** The ordinary declaration starts with the descriptor spelling, spells the Signature result, then installs that result into the declaration (`class_source.rs:7228-7273, 7728-7750`). A non-void candidate must carry its exact primitive category and be checked against both descriptor and Signature. A raw rename of `VoidBody` with no result discriminator would make existing matches dangerous: `generic_method_declaration` treats that variant as `void_body` and emits `void` (`class_source.rs:8665-8680, 8833-8836`); the special generic void branch also assumes `parsed.result.is_none()` (`class_source.rs:5630-5640, 8260-8272`). Keep those gates explicitly `None`/void-only.
2. **Do not turn unrelated signatures into new positives.** Primitive-body evidence is generated from recovery generally, while its consumers include ordinary parameterized declarations and method-local generic declarations. Gate the new branch at the ordinary path to a primitive result matching the physical descriptor and exact parsed Signature result, empty unsupported throws metadata, and at least one exact selected List formal whose complete reads are closed. Do not broaden `generic_method_declaration`, type-variable return-source proofs, reference/array results, wildcards, `List<T>`, `List<E[]>`, or nested-parameterized `E`. Leave the existing per-parameter `preserved` checks active so class-scope variables, arrays and references still need the same prior assignment/erasure rules (`class_source.rs:7440-7538`).
3. **Keep the element type's authority separate.** `E` comes from the physical method Signature and its existing erasure/spelling gate; the `checkcast` must be physically present and match that `E`. Do not infer `E` from the Object return descriptor, `Expr::presented`, a local name, or just a checkcast. Pass the already-selected `(slot, Type)` element type from `generic_list_parameter_types` to the get branch, or return the cast type as an observed use and let the ordinary Signature gate compare it. Direct comparison with the preselected type is easier to audit. Keep `(String)` in the projected body; this work only changes the generic parameter declaration.
4. **Prove the exact direct use, not just a shared BCI.** For the physical method: the unique interface invocation is owner `java/util/List`, name `get`, descriptor `(I)Ljava/lang/Object;`, opcode `invokeinterface`; its receiver is the selected formal's direct load; its argument is one int; result `Definition::Instruction` is at the invoke BCI and has only `Some(cast_bci)` as use, no replacement. At that BCI, exactly one body-value row is opcode `0xc0`, it consumes that identical value and produces one unreplaced value with only the target store as use. The AST proof must show the unique direct assignment RHS `Cast(E, Call(exact key))`, not a call buried below another expression. Join the cast BCI to one assignment and one local declaration/use shape. Refuse phi/`None` use, duplicate rows, extra consumers, wrong opcode/owner/descriptor, mismatched `E`, incomplete AST/Code, or any failed join.
5. **Staging is already transactionally repeated.** The facade computes the List proof during staged component construction and recomputes it from the original method/scan during final validation before installing edits (`facade.rs:17984-18018, 18495-18550`). The new get/primitive facts must be recomputed in both places and equality-checked with the existing staged List proof. On budget/cancel, preserve the existing Stop propagation; an optional missing proof leaves the erased declaration/body intact. The early `list_body_needs_transaction` probe and every `VoidBody` consumer need intentional updates if the carrier is renamed, even though parameterized List signatures also reach the generic Signature transaction selector.

## Specific failure examples

- Accepting the primitive body marker in `generic_method_declaration` can emit `void` for a primitive method result or misroute it toward a method type-variable return; the current API method returns `boolean`, so this is a direct type-loss hazard.
- Adding only `get(I)Object` to the member allowlist would accept a structured get with an uncast Object result, a cast to a different type, or an extra result consumer. The raw Object descriptor does not establish `String`.
- Treating `Other { consumer_bci }` as “cast parent” is unsound as an API contract: that variant represents arbitrary immediate parent shapes. The assignment cast record and physical opcode narrow the candidate but do not themselves explicitly state that the exact producer Call is the Cast's direct child. A small opaque query can state that fact without exposing AST internals.
- Projecting `List<T>` or an array/generic `E` by widening the selector from exact `SignatureType::Class` would step beyond this bounded fix. Keep the current concrete-reference selector.
