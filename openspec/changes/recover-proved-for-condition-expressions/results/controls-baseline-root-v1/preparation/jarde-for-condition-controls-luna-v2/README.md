# For-condition controls (prepared v2)

These Java 8 source fixtures are prepared for comparison against a future compiled-class decompiler result. They have not been compiled or run. The three target classes and Runner are separate simple top-level classes in package `cf11`; there are no explicit static initializers, generics, anonymous classes, or assertion framework dependencies.

`ForConditionEffects` isolates condition expressions whose producers have observable effects. `sumWithFunctionBounds` evaluates `offset()` before `limit()` on every header check; each appends a distinct digit to `events`, and configurable calls throw `IllegalStateException`. Runner covers zero and two body iterations, exceptions on the first or later offset call, exceptions on the first or later limit call, and the event/call counts. `sumWithFunctionBoundsAndContinue` uses the same calls and a `continue` on the first body iteration; event digit 4 marks that path, while the following header events show that the `i++` update still runs and the second body iteration completes. `sumWithChangingFieldBound` decreases its static bound inside the body to expose a hoisted condition read. Function bounds are 0 or 2; the dynamic field starts at 3 and decreases once per body iteration.

`ForConditionReads` covers a static field boundary changed in the body, `array.length` with both a non-null and null array, an array-element condition with safe, out-of-bounds, and null inputs, and unary negation of both a static field and a parameter. `oldWhileWithWrittenLocalBound` preserves a legacy `while` whose local boundary changes in the body. All cases have fixed finite inputs. The element-read positive bound is `{2, 0}`; `{3}` reaches index 1 only after one body iteration. The field controls start at 3, and the local-bound control starts at 3.

`ForConditionRefusals` is a separate control class for two `while` shapes. `sumWithLeadingTickAndBreak` puts a `tick()` statement before the independent `if (i >= limit()) break` statement under `while (true)`. `sumWithAssignedCallBound` assigns `limit()` to a local in the condition and returns only `sum + bound`, keeping the induction variable local. Both use limit 2. Runner resets `counter` and `limitCalls` before each case and records them.

Runner resets observed static fields before each call. It prints actual results (`-` when an exception prevented a result), exact exception class names, effect events, function call counts, and final dynamic bounds. It contains no expected-output assertions; output from original compiled classes is the oracle for candidate comparisons. Runner is separate from the target classes and is not part of the control shapes.
