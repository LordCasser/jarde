## Context

见 `proposal.md`。`class_source` 已逐成员运行一次恢复并装配类文本；`ClassSourceRecovery` 可带同次 `AnonymousAllocationScan`，其中每个 `new` 有物理成员、BCI、目标、构造调用和完整性。reader 已提供 typed `InnerClasses`/`EnclosingMethod`；类级枚举常量体证明已有按所选物理输入范围执行的 owner XRef 完整性检查。当前调用者和匿名实现各自作为物理类输出，没有匿名体的表达式级投影。冻结 `anonymous-interface-basic` 验证原/JADX/Jarde 均可重编执行且输出 `7`，但 Jarde 使用点仍为 `$1` 构造。

## Goals / Non-Goals

**Goals:** 只让直接返回的、无参无捕获、仅实现一个接口的匿名实例成为完整表达式；在方法/类来源、唯一性和预算上失败即原子拒绝。复用当前请求已读的物理事实及方法 AST，保留独立物理报告。

**Non-Goals:** 捕获局部/外层实例、具名或带参数基类、实例初始化器、匿名类字段、嵌套匿名类、非直接返回的创建位置、开放世界身份排除或将整个 jar 导出为单个可编译源码项目。它们按 DT-05～09 后续切片记录，不用当前样例推定完成。

## Decisions

1. **类级闭合证书消费现有事实。** 从所选匿名子类的 typed 无名 `InnerClasses` 行和准确 `EnclosingMethod` 绑定调用者方法；校验 `Object` 直接父类、唯一接口、无字段、唯一 `()V` 构造器。调用者的每个有 `Code` 方法都必须带完整 `AnonymousAllocationScan`，对目标类恰有一个已验证的 BCI，且构造调用/零实参与该站点精确对应。不能像 JADX `ProcessAnonymous.checkUsage` 那样只计使用方法数。对所选输入范围使用现有 `jarde-query::xref::scan_candidates` 的 owner/consumer 完整扫描，允许准确创建、构造与已核验的匿名声明元数据；其他类、代码、句柄和未决引用均拒绝。枚举常量体的范围扫描是可复用模式，不复制其枚举专用规则，也不新设全局索引。
2. **构造过程只认平凡证明。** 子类构造器必须是完整结构化的 `super()` 调用与无效果返回，原始指令还需核对仅 `aload_0; invokespecial Object.<init>; return` 这一等价形状；无参数、捕获字段、实例字段或其他初始化效果。仅看恢复文本的 `super()` 会漏掉字节码中的字段写入或异常次序，故不作为证明。子类每个非构造方法须有完整 `Code` 恢复、结构化质量、无引用/回退，声明可写成合法 Java 8 方法；不从 `contains_statements` 单独推断完整性。
3. **在同次 AST 上投影，整类最后提交。** 仅为准确调用者方法保留必要的私有 AST/来源 sidecar；类级证书成功后，把直接 `return` 的准确 `New` 节点投影成带接口类型和全部子类方法 AST 的匿名表达式，再由现有发射器写出文本。物理调用者与子类方法的原报告及各自来源映射保持独立，不把子类 BCI 冒充调用者 BCI；本切片不增公开来源 schema。避免对已渲染源码搜索或替换 `$1`，它可能是合法顶级类名、字符串或注释。构建完整候选文本后才替换 `ClassSourceReport::text`；停止或任何方法不合格时不提交局部投影。该节点只是表达式的必要语法形状，不建立第二套方法恢复机制。
4. **物理报告与源码单元分离。** 独立 `class_source($1)` 仍可查；调用者源码中的匿名声明不再另附一份具名 `$1` 声明。`class_source` 从未承诺把所有物理报告直接拼成项目，因此 Java 8 验收编译入口类与接口依赖的源码单元，子类物理报告单独核查。若日后提供项目导出，需要明确合并/去重规则，另案处理。
5. **JADX 仅作语法与算法参照。** 参考其匿名候选、构造参数映射和内联代码，但本切片不需要参数映射；JADX 双分配和跨类反例用于拒绝测试。Rust 当前 typed facts/AST/XRef 足以实现，不引入外部库；新增依赖无法替代本请求的物理身份、预算和来源约束。

## Risks / Trade-offs

- `[XRef 漏掉某类身份用法]` → 要求完整范围、精确确定性、已支持 consumer 集和零 unknown；无法覆盖时拒绝，冻结跨类反例复测。
- `[恢复文本看似完整却有未归属指令]` → 核对成员正文质量、coverage 与原始 Code 完整性；任一缺口拒绝整次匿名投影。
- `[源码里两次声明产生不同运行时类]` → 只接受一个准确 BCI；同方法双站点、其他类引用均拒绝。
- `[物理子类源码与匿名源码同时编译导致生成类名碰撞]` → 本次只验收入口源码单元及接口依赖；物理子类保留为查询报告，不混作同一源码项目的另一输入。
