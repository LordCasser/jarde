## 2. 实现

- [x] 2.1 站点扫描接受局部声明初始化形（分配表达式为唯一初始化值），**且覆盖分配点位于方法体中部、其后仍有语句的情形**；保持直返形与 `recover-anonymous-mixed-super-capture` 的判据逐字不变（其新锚 `anonymous-super-mixed-direct` 必须仍逐字节相同）。**不变量**：该方法内已证分配点计数仍须为 1；分配点**之后**的语句必须整体 `quality=structured` 且无引注，否则整方法回落物理文本（不得只投影前半段）。

  `class_source_direct_return_new` **零字节未动**（DirectReturn 语义逐字保留：直返候选存在时无视声明初始化位，`anonymous-super-mixed-direct` 呈现逐字节相同已由 corpus 双腿扫描证实）。新增共享扫描 `class_source_anonymous_site`（同文件同机制：直返优先，否则计声明初始化位候选、恰 1 才产站点，≥2 拒绝），`class_source_anonymous_return_site` 携带形状返回四元组，AST 保留门（report.rs ~5594）改用共享扫描。声明初始化位候选要求目标名为池形（含 `$`）——普通可命名类的分配（如 `Inner inner = new Inner();`）不是匿名站点、不得消耗计数（corpus 双腿扫描抓到该回归：`anonymous-inner-this` 因此未投影；修复后逐字节恢复，证据 `corpus-two-leg-scan/diff.txt`）。"分配点之后语句整体 structured 无引注"由发射层兜底：`LocalDeclInitializer` 形的重发射文本含 `// @bytecode` 即整方法拒绝（`anonymous_decl_site_body_unproved`）；DirectReturn 形体按构造无引注、行为不变。
- [x] 2.2 emitter 增加赋值左端声明类型重拼（匿名子类名 → 父类源码名），不可证明时保持物理文本。**须实现 design 判据 3 的三项检查**：(i) 重拼后的类型可拼写（复用既有 `anonymous_super_source_type_unproved` 判据，父类 binary 名含 `$` 即拒绝）；(ii) 池形类型名结构反射陷阱判据适用（最终文本含 `$` 且被 `STRUCTURAL_REFLECTION_METHODS` 之一消费则拒绝）；(iii) 该局部被后续读取时，若任一读取点在重拼类型上不可解析则**回落物理文本**（不得用 `var`/`Object` 兜底——兜底会改变静态解析结果，属禁止的静默偏离）。在代码注释中保留 design 判据 3 的健全性论证要点。

  重拼在既有 `AnonymousOverride` 同一接缝上实现（非第二词法通道）：emitter 新增 `anonymous_override_matches`（谓词与表达式路径逐字一致），`StmtKind::Declare` 臂在"初始化值恰为匹配分配点且左端拼写的正是匿名池名"时以 `source_type` 重拼左端——仅重拼匿名子类名本身，不碰其它声明。三项检查的落点：(i) 既有 `anonymous_super_source_type_unproved` 门对两位形继续生效（`nested-super-parent` 负例证其仍响亮）；(ii) 发射后幸存者检查——投影文本仍含匿名 child 池名即拒绝（`anonymous_decl_site_retype_incomplete`），池名幸存必然不可编译或被结构反射消费，拒绝先于发布（自引用分配负例证其兜底生效）；(iii) 既有 owner 普查（`prove_anonymous_owner_xrefs`）拒绝一切非分配/构造/捕获位的 child-owner 引注——锚的 `instance.render()` 在字节码层 owner 本就是 `Base`（`javap -c` 实证，记录于 1.1），任何不可解析读取都构成 child-owner 引用而被拒（`unresolvable-child-read` 负例证其仍响亮）。健全性论证要点已在 `emit.rs` 的 `StmtKind::Declare` 臂与 facade 形状门注释中保留。
- [x] 2.3 `project_class_source_anonymous_super` 根方法门按 **design 判据 1** 放宽：父类源码名的信息来源改为"声明初始化值 `new` 操作数的 owner 类型"，**不得保留对根方法返回描述符的检查**（否则 `void main` 锚永远被拒），也不得改为"忽略返回类型"（会放宽到未取证范围）。捕获证明与参数角色划分复用 `recover-anonymous-mixed-super-capture` 的通道，不新增第二套机制。

  返回门改为形状条件化：`DirectReturn` 形保留 `descriptor == "()Lparent;"` 原检查逐字不动（未放宽到"忽略返回类型"）；`LocalDeclInitializer` 形无返回描述符检查，父类源码名来自 `allocation_type`（声明初始化值 `new` 操作数的 owner，与左端重拼同一来源）。`prove_anonymous_val_capture`/`partition_anonymous_val_constructor`/`ProvedCapturedParameterRead` 全部复用零改动；混合捕获站点证明中的两处站点/实参解构改为形状感知（`class_source_anonymous_return_site` 四元组 + `class_source_anonymous_argument_local` 走共享扫描），接口侧的 `class_source_anonymous_outer_argument_bci`/`single_argument_bci` 保持仅调未动的 `class_source_direct_return_new`（`hidden_outer_argument_bci` 通道无需两遍接线）。
- [x] 2.4 确认 design 的 Open Question：锚的 `main` 在放宽后是否仍全程 `structured`、有无与 `explanation_only`/混合 fallback 冲突。若出现混合 fallback，**停手报告**，不得自行放宽 `present-proved-java-structure` 5.3 的该项要求。

  **无冲突**：锚 `main` 全程 structured（投影后的重发射文本无任何 `// @bytecode` 引注，事件日志逐行一致为旁证）；投射方法文本由 `anonymous_return_projection_parts` 的 `Recovered` 判据与 2.1 的发射层无引注检查双保险。5.3 的"任一方法 explanation_only/混合 fallback 则保持分开"未被触碰。
