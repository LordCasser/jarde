## Corrected physical-list boundary

The v1 rule `owner.len() < path.len()` conflated two facts: region-path nesting and which `Vec<Stmt>` is active when `loop_region` performs removal. The code shows why they differ. Top-level construction calls `declare_at(&[])` once, then emits each root region into the same `builder.stmts` (`build.rs:8222-8225`). `region` calls `declare_at(path)` before dispatch (`18014`, `18143`), and `Sequence` appends child indices (`18145-18155`). `loop_region` takes `self.stmts` only while recursively building a loop body, then restores the parent vector before calling the foreach candidate and removing indices (`18878-18890`, `18987-19015`). Therefore a declaration row emitted in the parent list can have a strict-prefix owner path and still physically belong to the active list from which the candidate may remove it. For an inner loop, the candidate runs after the outer loop has taken its parent vector, so a method/outer-loop-owned declaration can be absent from the inner candidate's active list; that absent-row case must not synthesize an index into another vector.

The accepted direct-Iterable contract is `tests/p3_iterable_foreach.rs:123-139`, especially `direct_iterable_projects_with_or_without_debug_names_and_preserves_cast`. Its frozen source `RawIterableIterator.rawCast` has `Iterator it = values.iterator(); int result = 0; while (it.hasNext()) ...`. The pinned `javap` body has iterator store at BCI 6, literal `result` store at BCI 8, loop test at BCI 10 (target 9), and next/cast/store at 19/24/25/29. This gives a nonblank, literal-only statement between init and test, which the existing same-list rule allows. If a strict path prefix alone selects the new ancestor gap rule, it rejects this existing positive before the next/cast proof. The historical generated source is not used as a live assertion; the current test is the contract, and this report is static.

For the fixed nested class, root's accepted same-IR v3 trace observed inner loop path `[1, 1]`, `Elevated { owner: [1] }`, declaration emitted at owner `[1]` anchored at BCI 33, and the candidate's current-list init row at index 1. The earlier trace reported the declaration owner as visible/emitted/planned, but the follow-up physical-list question requires checking whether its blank declaration is in the active inner-candidate `self.stmts` list. The static body construction explains that owner `[1]` is emitted in the current vector only in a region context whose `declare_at([1])` runs before that candidate list is taken. In the nested case, it is emitted before the outer loop; when inner candidate executes, `loop_region` has switched to the outer body's separate vector. Thus the exact row search—not the path prefix—distinguishes the two cases. This is an interpretation of the fixed trace plus builder control flow; no new runtime trace was run.

## Candidate changes

`candidate.patch` modifies only `build.rs.candidate` relative to the pinned base. The reviewed production entry points in that base are `Builder::loop_region` around `crates/jarde-java/src/build.rs:18880-19010`, which calls `iterable_for_each_candidate`, and `Builder::iterable_for_each_candidate` at `21224-21600`. Declaration facts are `Declarations`/`DeclarationPlacement` at `build.rs:441-486`, `HoistedDeclaration` at `581`, and `Builder::declare_at` at `22663-22678`. `reuse::Plan::variable_at` is at `crates/jarde-java/src/reuse.rs:89-101`. The SSA read surface (`SsaUse`, `SsaValue`, `SsaPhi`, `PhiInput`, and `SsaTable`) is at `crates/jarde-jvm/src/ssa.rs:198-300, 477-518`; its replacement occurrence accounting is at `1822-1940`. `poll` and `charge` are at `crates/jarde-java/src/stop.rs:115-148`.

1. The loop path is passed into `iterable_for_each_candidate`. A private declaration-owner helper uses `reuse::Plan::variable_at` at the initializer Store and both local Load BCIs, and requires the same exact `LocalVariable`, matching source name, a present `DeclarationPlacement` other than `Incomplete`, and `self.declared`. The owner's path must be a prefix of the loop path. For `Elevated`, the exact owner entry in `at_region` must contain that same variable exactly once at the initializer store BCI. A matching blank declaration is searched in the active `self.stmts` vector by name, Iterator type, blank value, and the exact `LocalVariable` resolved at its origin BCI. If exactly one row is present, this is the old same-list removal path even when the owner path is a strict prefix of the loop path: return that active-list index and preserve the existing same-list gap rule. If no such row is present, admit only a strict-prefix `Elevated` owner whose exact `at_region` row and anchor are already verified; mark it as cross-list, return only the initialization index, and require the gap to contain blank declarations only. A duplicate matching row or any missing/invalid owner remains a refusal. This uses current-vector membership to determine editability; it does not infer a different AST list solely from `RegionPath` length.
2. The existing iterator-use gate is replaced by a private helper. It first validates every direct use is one of the known test/next loads, groups None-BCI use occurrences by canonical block, then visits each Phi in each such block. It counts only exact `PhiInput::Value(iterator_value)` occurrences. Every Phi with at least one such input must have a replacement, no remaining uses, and a bounded replacement chain to the iterator; every Value arm in each matched Phi must also resolve to that iterator. `Itself` is allowed but contributes no occurrence. The exact operand count across all matching Phis must equal the corresponding None-use multiplicity. A Phi with no exact iterator input does not affect this gate.
3. Owner checks, None-use/Phi scans, Phi-input inspections, and replacement hops poll and charge `AnalysisSteps` before work. These helpers return `Result`; the existing candidate body is an `Option` closure, so a captured `StopReason` is returned immediately after that closure and cannot be misreported as an ordinary proof refusal or a candidate. The normal candidate result remains unchanged.
4. Successful projection removes only returned indices from the current statement vector. The new ancestor path returns only the current iterator initialization index; its declaration remains in the ancestor owner. Existing descriptors, header-Phi shape, writes, loads, next/cast/store, effects, handlers, origins, and ordinary same-list gates remain in the proof.

The candidate intentionally does not widen outer-loop recovery, generic typing, iterator aliases, local liveness, SSA mutation, or declaration-planner behavior. It preserves the existing same-list literal-gap allowance when the exact blank declaration row is in the active list, while applying the stricter blank-only gap only when that exact row is absent and the validated Elevated owner is strict-prefix. The pre-existing same-list literal-gap behavior is retained as an independently recorded timing/effect debt. No new product API or reusable liveness service is introduced.

## Static review limits

The candidate was inspected against the pinned `SsaTable`, `PhiInput`, `SsaUse`, `DeclarationPlacement`, `HoistedDeclaration`, `Plan::variable_at`, budget, and caller-removal APIs. Syntax and control flow were manually reviewed; no Rust parser/compiler, formatter, Cargo command, Java/JADX/CLI tool, Git command, or network request was run. In particular, no claim is made that the candidate compiles or that inner BCI 42 reaches or passes later gates.

The architecture change is confined to the current foreach proof. Root should exercise:

- the accepted positive case and all existing same-list behavior;
- a split-slot identity mismatch and missing/Incomplete/non-visible owner;
- wrong or duplicate owner declaration anchor and an absent emitted declaration;
- an ancestor gap with an executable assignment, even if its RHS is a literal;
- None-use/input count shortfall and excess, duplicate operands, an extra matching Phi from another slot, `Itself` handling, mixed/non-resolving arms, missing replacement, and a live matching Phi output;
- an unrelated Phi with no exact iterator input, including a live/nontrivial one, which must not affect this gate;
- a real budget/cancellation stop during owner scan, Phi scan, input scan, and replacement walk, verifying no partial AST publication.

The immediate later gate after the original refusal was not observable in the accepted diagnostic. Do not infer it from source or declare the foreach recovered until a guarded same-IR/full-class run establishes it.
