# Private static review of the iterator regression-test candidate

The candidate is a tests-module-only patch over the pinned production `build.rs` SHA `df113e368d9eb8762abbe269ee3a58421cb0b7b5a01e64154a068dbd34cfe28a`. I compared the full source prefix through `#[cfg(test)] mod tests {`; it is byte-identical to the base. This is static review only: no Cargo, Rust compiler, Git, JDK, JADX, or CLI was run, so this does not establish compilation or passing tests.

The test analyzer is factored from the existing `analyze_own_grid` helper while preserving that helper as a wrapper with the original method identity. The new test context uses the pinned `UpstreamNestedLoops.class`, obtains the actual method declaration, canonical CFG, SSA, method code, operations, recovered regions, resource slots, debug locals, `reuse::plan`, and the production declaration planner. For `test(Ljava/util/List;Ljava/util/List;)V`, it carries the actual instance flags and parameter-slot count into `MethodFacts`; the method is public instance with descriptor-derived three parameter slots including receiver. The source bytecode confirms the asserted locations: `iterator()` at BCI 28, slot-5 store at 33, header receiver load at 35, `hasNext` at 37, branch at 42, next receiver load at 45, `next` at 47, cast at 52, and element store at 55. The prior same-IR trace for the same frozen class reports slot 5 as one local identity at init/test/next, name `local5`, `Elevated { owner: [1] }`, and exactly one at-region Iterator anchor at BCI 33.

The statement-list cases are sensible direct calls to the real helper with a synthetic blank declaration row at the real store BCI: one case verifies an exact current-list row returns its index even under the strict-prefix owner; the empty-list case verifies only the checked ancestor case returns `(None, true)`. Withholding the actual owner rows, changing placement to `Incomplete`, mutating the real owner anchor type, removing the variable from `declared`, and using a non-visible path each fail at the corresponding existing production gate. The `at_region` mutation is scoped: each `get_mut` borrow ends before the helper is called, and the saved type/rows/placement are restored before subsequent probes. No apparent borrow overlap is present in these blocks.

The slot-3 counterexample uses the checked-in debug class and source. In `Scope.reuse(ZI)I`, slot 3 has `c` reads within `[8,10)` and `d` reads within `[17,19)`, so `reuse.variable_at(3, 8)` and `(3, 17)` should be distinct. Passing those as the first two of the helper's access BCIs reaches and fails its same-identity condition before later name/placement checks. This is a real split-slot case, not an invented SSA value.

The real SSA Phi test is consistent with the frozen same-IR evidence: the iterator value has one block-only use in the header and three block-only occurrences at BCI 97; the header Phi has exactly one iterator input and an `Itself` backedge; the BCI-97 iterator Phi has three exact iterator inputs; a Local(6) Phi in the same block has no iterator input and is dead/replaced. The helper call should therefore accept the actual graph and demonstrates that an unrelated Phi without the target operand is not an obstacle. It does not claim mixed/live rejection coverage; the controls agent is preparing that separately, and those cases should not be inferred from this candidate.

Both low-budget assertions are reachable after a positive real identity/proof prefix. For the declaration helper, budget 1 pays for BCI 33 and the next identity read at BCI 35 is the first refused charge. For the Phi helper, the pinned use sequence begins with BCI-35 block-only/header use followed by a BCI-35 instruction use, so the second charged use also stops at BCI 35. The production call site captures helper `StopReason` and returns it after the candidate closure; the test candidates directly assert the helper's exact `Budget` reason. Root should still validate exact `at` behavior in its authorized build.

It is a warning, not an identified semantic or compile blocker. The remaining APIs and borrow scopes look consistent with the surrounding test module by inspection, but no claim of Rust compilation is made.
