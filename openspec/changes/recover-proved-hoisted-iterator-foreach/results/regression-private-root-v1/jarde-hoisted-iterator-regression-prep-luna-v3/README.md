# Hoisted iterator mixed-phi probes v3

This preparation adds one Java 8 source fixture and a tests-only Rust delta. The Java source has exactly two static methods and no nested/helper classes. It is ready for root's guarded Java 8 and Java 23 `--release 8` compilation. The expected `.class` is not present, and the manifest marks its bytes and SHA-256 as pending compilation.

`mixedIterator` initializes one iterator local from `a`, conditionally replaces it from `b`, then reads that local in a bounded-by-input `while`. Its intended SSA probe is a live, unreplaced phi for the same local with the initial source value and another iterator value. `extraAliasConsumer` initializes `original` from `a`, conditionally copies it into a separate `alias` local or initializes `alias` from `b`, then reads `alias.hasNext()`. Its intended SSA probe is a live, unreplaced phi for another local containing the exact source value.

The Rust delta is based on the v2 full test candidate recorded in `pins.json`. It locates the first `iterator()` invoke, its following local store and stored `ValueId`; collects real physical local-load BCIs from that value plus the relevant hasNext/next receiver loads; asserts the real phi shape; and calls `iterator_phi_use_ownership` expecting refusal. The current helper checks exact readers first, then rejects a matching phi whose value is unreplaced or still live. The tests assert the phi is actually mixed/live and the source value is actually an operand. They do not claim to exercise a later arm-resolution condition after bypassing the earlier live-phi gate.

The fixture source SHA is frozen in `pins.json`. No class was compiled, no Rust test was run, and no Java/JADX/CLI or other toolchain was invoked in this preparation. Root should inspect the actual class bytes and SSA before using the candidate assertions. If javac does not produce these exact relationships, keep the source pin and revise the test expectation from actual facts before freezing a fixture.
