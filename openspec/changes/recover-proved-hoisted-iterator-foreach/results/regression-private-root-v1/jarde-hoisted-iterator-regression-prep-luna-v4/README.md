# Hoisted iterator phi probes v4

This is a new private review snapshot. It leaves v3 untouched and corrects the alias test using root's actual dual-JDK javap outputs. Both compilers produce the same listed method BCIs, but the class files are different: Java 8 output is 606 bytes (`31cd1b…94ccda`), and Java 23 `--release 8` output is 603 bytes (`87e300…348f2a4`). Root still needs to select and install the permanent fixture bytes; this directory does not copy or choose one.

For `mixedIterator`, both javap records show the original `iterator()` result stored to local 3 at BCI 6, a second iterator stored to local 3 at BCI 17, then local-3 receiver loads at BCIs 21 and 30 for `hasNext` and `next`. The v4 test derives those receiver-load BCIs from analyzed operations and expects a same-local live, unreplaced phi carrying the initial and alternate values. The intended first gate is that live/unreplaced matching phi.

For `extraAliasConsumer`, javap shows the initial iterator stored to local 3 at BCI 6, then `aload_3` at BCI 11 and `astore 4` at BCI 12 in the copying arm. The other arm stores a fresh iterator to local 4 at BCI 23; local 4 is loaded at BCI 25 for `hasNext`. The v3 assertion that the local-4 phi contains the exact value produced by the original store was too strong. The inspected JVM SSA transfer code creates an instruction value for each stack/local write: the original local value is read by the BCI-11 load, that load defines its stack value, and BCI 12's store defines local 4's value. Thus the source value should first be rejected as an additional physical consumer at the BCI-11 load when the helper receives the real hasNext receiver load (BCI 25, repeated to satisfy its two-entry fixed argument). The test no longer puts the alias-copy load in the allowlist and no longer asserts that the original source ValueId appears in the other-slot phi. It checks that the branch-written alias has a live phi in another local, without claiming exact operand identity there.

The production helper checks physical uses before processing phi uses. This test's expected first rejection for the alias method is therefore the out-of-allowlist source load, before the helper can use any other-slot phi. The mixed-method test separately probes the exact same-local mixed phi path. The actual SSA shapes and helper results are pending root's focused IR run; javap and static transfer-code reading alone do not establish them.

`build.rs.phi-controls.patch` is a tests-only delta based on the v2 test candidate listed in `pins.json`. The class include path stays `tests/fixtures/p3-hoisted-iterator/HoistedIteratorPhiControls.class`. No source or production code was changed here. This agent did not compile or run tests or invoke any toolchain.
