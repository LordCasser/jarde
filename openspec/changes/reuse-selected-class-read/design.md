## Context

`optimize-demand-workloads` 的 O2 准入项：同一定义的读取会被重复支付，而这是可停的工作而非必需的工作。§3 的单因素实验（`../optimize-demand-workloads/evidence/g1g2-experiment-o2.md`）给出了前后对照与"不误命中"的判别性用例；本变更把它实现为默认行为，并把回退面逐条写清。

## Goals / Non-Goals

**Goals:** 同一定义在同一声明界内的读取只支付一次；命中计入既有两层上限并如实报告；关闭/拒绝/身份不符时与关闭时语义逐项相同；两个足额路径的结果 fingerprint 相同。

**Non-Goals:** 全局 `MethodIr` 复用；更高层 store 与淘汰（O5 暂缓）；名字搜索的候选读取（它读的是"用来判断候选"的字节，不是被选中的定义）；预热/预取（O6 暂缓）；任何加速主张——窗口份额上界 0.5%，本变更只主张**工作量下降**。

## Decisions

### 1. 复用单位是"定义读取"，不是"类解析结果"

身份 = 不可变 snapshot + 完整物理位置（origin chain、ordinal）+ 内容 digest + 声明 length + 变体 + 读取 schema。**任何一维不同即不命中**，走直读。这样"同名异内容""同字节异 origin""重复 entry""变体不同"四类都不能互相代答（§3 的判别性用例覆盖前两类，其余由既有 `p5_facts_cache`/`p5_shared_payload` 门禁承担）。

### 2. 共用既有两层上限，满则拒绝、不淘汰

定义读取层占用 container/CP/Header 层同样的 entry 与 retained-byte 额度，并且**不引入淘汰**：满则拒绝本次保留并继续以直读完成请求。理由：淘汰会让"命中"变成时间依赖的行为，而本仓库当前的复用契约明确是"满则拒绝"（`facts-cache` 既有要求）；引入淘汰需要自己的调查与准入（O5 已暂缓，触发条件写在它的证据里）。

### 3. 命中不伪造证据

命中不计入 `archive_entries`/`read_bytes`/`entry_bytes`/`class_bytes`，不重放旧 usage，不因命中恢复已耗尽的预算或提交 Complete。调用方仍须核对它声明的身份与返回的 digest/length 一致——复用的是"字节与校验结论"，不是"信任"。

### 4. 入口只在两处，名字搜索不入此路径

`src/facade.rs` 的身份绑定读取与 `crates/jarde-jvm/src/providers.rs::read_definition_class`（方法驱动与 bulk class task 的读取）经快照侧入口；**名字搜索的候选读取不入此路径**——那些读取的用途是"判断候选"，其成本属于搜索而不是被选中的定义。

### 5. 回退是一等公民

无 store、容量拒绝、身份不符、取消/到期耗尽、以及"读取被部分构造/被限额终止"五种情况逐条走直读；语义回归时撤回本独立提交即可回到旧行为（不保留开关、不留并行路径）。

## Risks / Trade-offs

- **紧预算下的完成度可能变化**：命中省下的额度可能让某个紧预算请求走得更远。这是"工作量节省导致完成程度不同可以报告"的既有允许面，但必须**不伪造 Complete**，并在 §4 的冷/热对照里显式测（§3 已把它列为未确认项）。
- **驻留增长**：每个被复用的定义增加其字节的驻留（实测 +2,056 B（1 定义）…+8,916 B（8 定义）），RSS 无可区分差；容量拒绝时不增长。
- **跨 crate 入口**：`jarde-reader` 与 `jarde-jvm` 之间新增一个调用面；按既有分层，`reader` 只提供事实，`jvm` 只消费。

## Migration Plan

一个提交：实现 + 反例门禁 + 与关闭路径的等价对照。若 G3 验收发现语义差异或紧预算行为不可接受，撤回该提交（无开关、无并行路径需要清理）。

## Open Questions

- 相同内容的两个 snapshot 共享同一 snapshot 身份时的复用行为未测（§3 未确认项 ④）：本变更按身份逐维比较，不因"内容相同"而命中，因此不依赖该行为；若将来要允许，需先测。
- 一次受信读取自身的耗时与 `p/s/h` 分量仍未测（§3 未确认项 ①）：本变更不以此为依据声明加速。
