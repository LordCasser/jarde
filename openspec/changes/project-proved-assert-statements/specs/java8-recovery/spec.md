## ADDED Requirements

### Requirement: 完整类中经证明的断言应写成 Java 8 assert

当一个类的断言状态开关、初始化和所有使用均有完整且一致的物理证据，并且每个被投影的条件与消息的求值路径等价时，完整类源码 SHALL 将整组条件抛错写成 Java 8 `assert` 语句。源码 SHALL 只保留一次条件求值、仅在启用断言且条件为假时求值消息并抛出等价的 `AssertionError`；由 Java 编译器重建的合成开关不得同时作为显式源码字段或赋值输出。

#### Scenario: 一条带消息的断言
- **WHEN** 原类的唯一开关来自当前类的断言状态，唯一使用保护 `assert guard(ok) : detail()` 的两个调用，且证据完整
- **THEN** 完整类源码含该 `assert` 语句，不含显式合成开关声明或赋值；原类与重编源码在 `-ea`、`-da` 下的返回、调用次数、消息和异常行为一致

#### Scenario: 多条断言共用开关
- **WHEN** 同一个已证开关被两个以上已证断言使用
- **THEN** 完整类源码 SHALL 整组投影且只让编译器重建一个开关；任一使用未证明时 SHALL 不发布部分投影

#### Scenario: 无消息断言
- **WHEN** 已证失败分支构造的是没有消息的断言错误
- **THEN** 源码 SHALL 写 `assert condition;`，并在启用与禁用模式下保留失败、跳过与求值次数

### Requirement: 未证明的断言形状不得按源级断言改写

系统 MUST 以实际类字节、成员身份、数据流及控制流作决定；字段名、合成标志或 `AssertionError` 出现本身均不得视为断言证明。初始化状态来源、值、额外读写、条件或消息的求值路径、异常边或重编生成的开关身份不能证明等价时，系统 MUST 保留已有忠实的显式输出或明确拒绝，不得写源级 `assert`。

#### Scenario: 状态来源改为其他类
- **WHEN** 唯一初始化读取其他类的 `desiredAssertionStatus()`，而当前类与该类在选择性启停下的状态不同
- **THEN** 不输出源级 `assert`，重编输出 SHALL 维持原类选择性启停的行为

#### Scenario: 开关写入值并非标准布尔取反
- **WHEN** 验证器接受的类在初始化分支中写入非 0/1 整数，并依 JVM 布尔字段窄化产生与标准断言开关不同的值
- **THEN** 不输出源级 `assert`，保留原开关语义或明确拒绝

#### Scenario: 开关有额外读取或写入
- **WHEN** 已识别开关还有未证明的使用，或另一路可达写入
- **THEN** 完整类源码不得只投影已识别的一部分，也不得删除该物理字段或赋值

### Requirement: 断言投影保留物理证据并原子发布

投影只作用于完整类源码；独立方法恢复、物理字段与方法身份、原属性和原恢复报告 MUST 保持可查询。输入读取、跨成员证明、来源及输出 MUST 遵守已有预算和取消合同；停止或任何证明失败 MUST NOT 发布半个断言组、孤立字段引用或半个类初始化器。必要与详细证据请求的正文 MUST 相同。

#### Scenario: 物理报告与来源
- **WHEN** 完整类源码成功写出 `assert`
- **THEN** 原字段、`<clinit>`、方法与相关 BCI 仍可通过物理报告追溯，独立方法报告仍呈现其原始分派

#### Scenario: 预算或取消打断投影
- **WHEN** 类级证明或二次发射在预算耗尽或取消时停止
- **THEN** 请求报告既有停止原因，不发布缺字段、缺方法或部分替换后的类源码
