## ADDED Requirements

### Requirement: 已证明的枚举常量专属类体

在枚举常量列表及其初始化效果已完整证明的类中，若某常量由只属于该常量的匿名子类构造，且子类声明与每个需呈现的方法体均可完整恢复，类源码 SHALL 将这些方法写入该常量的 `{ ... }`，并保留常量顺序、构造参数和运行行为。对于零源参数的两个常量，证明 SHALL 覆盖物理 `<clinit>` 的匿名子类构造 owner、子类到主枚举隐式构造器的委托，以及隐式 name/ordinal、数组和辅助方法；先前只支持主枚举 owner 加一个源整数参数的普通常量计划 MUST NOT 被当作此形状的成功证明。单纯的类名形状、`synthetic` 标志或 JVM 可执行性 MUST NOT 代替该证明。任何物理子类身份、独占使用、构造效果、声明或正文缺失/歧义时，系统 MUST 不发布该常量类体投影，也 MUST 不吞掉有疑义的物理成员或可观察效果。

#### Scenario: 两个独占匿名子类的常量

- **WHEN** 已证明的两常量 Java 8 enum 中，两条常量构造分别唯一指向自己的匿名子类，各子类覆写的 `apply(int,int)` 正文完整恢复
- **THEN** 类源码 SHALL 按原顺序写出两个带 `{ ... }` 的常量；Java 8 重编后 `values()`、`ordinal()`、`name()`、`apply`、`getClass() == Op.class` 的真假值和异常行为 SHALL 与原 class 一致，不要求编译器生成的匿名子类二进制名相同

#### Scenario: 抽象主枚举与 synthetic 访问构造器

- **WHEN** 主枚举的抽象方法没有 Code，匿名常量子类经带纯 `null` 哨兵的 synthetic 访问构造器委托到主枚举的私有构造器
- **THEN** 系统 SHALL 逐条确认子类与访问构造器原样转发隐式 name/ordinal、哨兵不被读取、每个常量体完整实现抽象方法，才可将无 Code 抽象声明与访问桥纳入整组投影；任一调用边、参数或实现未获证明时 MUST 拒绝整组投影

#### Scenario: 常量体与普通常量混用

- **WHEN** 两个已证明常量中只有一个由独占匿名子类构造，另一个构造主枚举且不带专属类体
- **THEN** 类源码 SHALL 只给前者写 `{ ... }`，后者 SHALL 保持普通常量声明，两者的构造顺序和运行结果 SHALL 不变

#### Scenario: 普通常量不凭名字获得类体

- **WHEN** 两个常量均直接构造枚举主类，或输入中仅存在同名 `$1` 类而常量构造并不指向它
- **THEN** 类源码 MUST 不写出无依据的专属类体，也 MUST 不隐藏那个无关类的物理事实

#### Scenario: 子类被额外使用或关系无法证明

- **WHEN** 候选子类还在其它常量、方法或字段中被构造/使用，或其父类、匿名关系、选定定义、构造调用任一不能唯一证明
- **THEN** 系统 MUST 拒绝内联该子类，MUST 保留常量和子类各自的物理事实与准确缺口；MUST 不把一份类体复制到两个常量

#### Scenario: 子类正文或效果不完整

- **WHEN** 候选子类存在不能完整恢复的方法、额外初始化效果、不可安全呈现的字段或声明，或主枚举常量前缀本身未获证明
- **THEN** 系统 MUST 不发布看似完整的常量类体，MUST 保留可追溯的原始正文、效果与恢复质量，不得按名称丢弃子类构造器或其它成员

#### Scenario: 来源、选择与停止一致

- **WHEN** 同一受支持输入请求默认/完整证据或 JSON 报告，或者依赖读取、方法恢复及发射遇到预算/取消停止
- **THEN** 成功请求的类源码正文 SHALL 与证据选择无关；主枚举原有物理成员报告 SHALL 保留，子类经其独立类/方法请求仍 SHALL 可取得原物理身份、成员结果和真实 Code 来源，投影 SHALL 标明所消费的子类身份；停止 MUST 如实呈现且不能发布部分已内联类体
