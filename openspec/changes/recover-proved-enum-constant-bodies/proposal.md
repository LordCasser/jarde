## Why

Java 8 枚举常量可带独立类体，例如 `ADD { int apply(...) { ... } }`。当前 Jarde 将常量匿名子类留在主枚举的字段和 `<clinit>` 中，完整源码无法重编；JADX 1.5.6 能重建该形状，但它依据 `$VALUES`、synthetic 标志和线性初始化的启发式不能直接作为删除物理子类的证明。

## What Changes

- 在普通枚举的完整类级证明交付后，复用其同次常量候选与隐式成员检查，并把首片扩至**零源参数、构造 owner 为匿名子类**的形状；只有主类初始化、子类身份/独占使用和完整方法体合并证明成功，才把方法体写入对应常量的 `{ ... }`。
- 主枚举和子类各自的物理成员、来源与恢复报告继续保留；任一依赖缺失、重复使用或方法体未恢复时拒绝此次类级投影，不按 `$1` 名称或 synthetic 标志吞掉成员。
- 用自写 Java 8 `-g`/`-g:none` 样例对照原 class、JADX、Jarde 的重编与 `-Xverify:all` 行为，并冻结拒绝边界。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `java8-recovery`: 对已证明的 enum 常量专属类体，输出可编译且行为等价的 Java 8 常量声明。

## Impact

此变更以 [recover-proved-enum-constants](../recover-proved-enum-constants/tasks.md) 的普通两常量、一个源级整数参数、直接构造主枚举的类级证明与投影完成为前置条件；该前置任务当前尚未完成。`Op` 正例没有源级构造参数，物理构造 owner 为 `Op$1`/`Op$2`，**不会被前置任务的准入条件证明**；本变更须在自身范围内把同一候选/辅助成员证明扩到这两个确切形状，不能把“普通枚举已完成”误当作 `Op` 已被证明。实现范围为现有 class-source 装配、选定物理类的按需读取与成员恢复，以及必要的局部源码投影；不更改 reader 公共 classfile 属性模型、单方法结果或 JVM 分派查询。不处理任意数量常量、任意源参数形状、带捕获的复杂构造、跨类任意匿名对象内联和不完整依赖环境。
