## ADDED Requirements

### Requirement: 两段保护区的四出口 finally 恢复

系统 SHALL 在 Java 8 方法的两段不连续异常保护区、一个具名 catch 及其共用异常清理都得到完整证明时，输出语义等价的单个 `try`/`catch`/`finally`。系统 MUST 保持早退、正常汇合、catch 汇合和异常重抛路径的清理次数、调用目标、效果顺序、返回或异常结果。

#### Scenario: 早退和两处汇合
- **WHEN** 两段受保护正文分别可提前返回或到达正常汇合，具名 catch 到达另一汇合，四条完成路径各执行一次等价清理，异常 handler 清理后重抛原异常
- **THEN** 系统输出唯一 `finally`，在 Java 8 完整类重编并验证运行后，各路径的可观察结果与原 class 一致

#### Scenario: 命名异常和外抛异常
- **WHEN** 两段正文中的异常进入同一具名 catch 或共用异常 handler，catch 正文中的异常也进入该共用 handler
- **THEN** 系统保持具名 catch 的类型、处理顺序，以及未处理异常的原始身份和仅一次清理效果

### Requirement: 多段 finally 的完整证明和原子拒绝

系统 MUST 在异常行范围或顺序、保护段入口/出口、任一清理副本的成员/接收者/参数、清理必经性，或保存异常的重抛身份无法证明时，拒绝把物理副本折叠为一个 `finally`。系统 MUST 在预算耗尽或取消时停止且不发布部分恢复的结构。

#### Scenario: 副本目标或路径改变
- **WHEN** 早退路径调用不同清理目标，或一条分支绕过应执行的清理
- **THEN** 系统拒绝归并，且不输出声称所有完成路径共用的 `finally`

#### Scenario: 清理落入自身保护范围
- **WHEN** 异常保护范围扩到一份正常清理，使该清理抛错时再次进入共用 handler
- **THEN** 系统拒绝归并，不把可能执行两次的效果改写为一次

#### Scenario: 重抛值改变
- **WHEN** 异常 handler 重抛的值不是它保存的原异常
- **THEN** 系统拒绝把该 handler 作为原异常重抛的 `finally` 证据

#### Scenario: 预算或取消
- **WHEN** 证明、区域恢复或输出构建被预算或取消中断
- **THEN** 系统保留停止结果，不发布半份 `try`、重复认领的块或不完整来源

### Requirement: 多段 finally 的物理来源

系统 SHALL 保留恢复后的每条物理指令和异常表行的可追溯来源，并确保每个可达物理块只被一个结构拥有；折叠的清理副本 MUST 作为唯一源级 `finally` 的来源可查询。

#### Scenario: 四份副本折叠
- **WHEN** 两段保护区、具名 catch 和共用异常 handler 的四份清理获证并折叠
- **THEN** 来源图覆盖四份清理、早退返回、两处转移、handler 存储与重抛、五条异常行，而后续汇合块只被后续源码认领一次
