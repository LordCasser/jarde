## ADDED Requirements

### Requirement: 跨后续条件图保留调用实参的条件值

当 Java 8 class 的调用先在一个可证明的双臂条件图计算较早实参，保留该值经过后续可证明的条件实参图，再在同一调用消费时，系统 SHALL 以原栈身份和参数顺序输出等价 Java 条件实参。仅准入有界的普通 CFG/SSA 传递，所有折叠的真实 BCI SHALL 保持来源映射，完整类 SHALL 可用 Java 8 重编且可观察行为与原 class 一致。

#### Scenario: 两个连续条件实参传给委托构造器
- **WHEN** `this(String,String)` 的第一个实参先在条件分支汇合，随后第二个条件分支计算第二个实参，同时第一个值保持在栈上直到调用
- **THEN** 系统 SHALL 以真实顺序输出两个条件实参，保留委托调用、字段初始化语义与两个分支的来源；null/非 null 的六条验证路径 SHALL 与原 class 一致

#### Scenario: 直接汇合的单条件实参
- **WHEN** `this(int)` 的唯一条件实参在调用所在 join 块被直接消费
- **THEN** 系统 SHALL 保持现有结构化 Java 输出、来源和四条验证路径一致

#### Scenario: 值身份或效果次序无法证明
- **WHEN** 携带值的某个栈槽在路径上被替换、Phi 输入并非同一个已证明值、有额外入口/循环/异常边，或中途有不能按原顺序呈现的独立可观察操作
- **THEN** 系统 SHALL 拒绝折叠该调用及相关条件图，不得移动或重复效果，不得输出遗漏 `this/super` 调用的貌似完整 Java

#### Scenario: 调用约束或任务停止
- **WHEN** 调用参数描述符/类型、构造器前导身份、唯一最终消费不能证明，或证明中预算耗尽/取消
- **THEN** 系统 SHALL 保守引用或报告停止，不得发布部分条件实参、部分来源映射或未经证明的构造器委托
