## Context

见 `proposal.md`、`specs/java8-recovery/spec.md` 和既有 `compound-assignments/postfix-analysis.md`。目前 `build.rs::field_increments` 能证明局部变量接收者的八指令字段 `n++/++n` 返回形状，但要求接收者由 `load` 命名，且把整个更新放进预格式化 `ExprKind::Local`。它无法涵盖调用接收者或数组下标。现有 `Field`/`Index` 表达式、`field@1`、数组类型、SSA、延期消费者、来源与受限发射已提供构造真正表达式所需的基本能力；`recover-compound-lvalue-updates` 另行处理无结果的 `+=` 语句，不能吞掉留给 `ireturn` 的旧值。

## Goals / Non-Goals

**Goals:** 只接受在一个基本块内紧接写入后由 `ireturn` 唯一消费旧值的实例 `int` 字段和 `int[]` 元素后置递增；让完整生成类在正常、异常与溢出路径上保持原 class 行为。

**Non-Goals:** 任意位置的赋值表达式、前置更新的新形状、递减、窄型/`long` 更新、跨块旧值传递、通用复制求解、原始源码拼写复原。现有简单字段递增用整段文本承载的债务单独记录，不借本项迁移其所有形状。

## JADX 源码对照与取舍

本地 JADX `2fb1b163` 的 `jadx-core/src/main/java/jadx/core/dex/visitors/SimplifyVisitor.java::convertFieldArith` 从 `IPUT(ARITH(IGET, 1))` 的包裹结构识别相同字段，并比较读取、写入的接收者寄存器，再改为单操作数算术节点；`jadx-core/src/main/java/jadx/core/codegen/InsnGen.java::makeArithOneArg` 在右侧整数常量为 1 时打印 `++`。可借鉴的是“先认定同一可写目标，再由统一 emitter 输出更新”的分工。仅比较字段和寄存器，不能证明本案 `ireturn` 究竟消费旧值还是新值，也不能证明调用接收者或数组下标只求值一次且未跨越独立效果；这两点在 Jarde 用现有 SSA 复制链、最终消费者和延期顺序事实逐项证明。JADX 的 `TestJavaDupInsn` 含 `versions[regNum]++` 输入但只要求生成代码，不能代替本案完整类重编、异常阶段和执行对照。这里不照搬其包裹指令或启发式改写，也不新增通用更新 pass。

## Decisions

1. **给既有表达式 AST 增加唯一必要的后置语义。** 使用一个后置递增表达式节点，其目标必须由 build 阶段从已证明可写的实例字段或数组元素构造；emitter 在现有最高绑定级别写 `target++`，接收者/数组/下标沿用 `Field`/`Index` 的括号、来源和预算。比把 `receiver().value++` 拼成 `Local` 文本可靠：拼接会丢失嵌套来源及分组；比引入一般左值 IR 或可配置的全套更新运算更小。已存在的简单字段规则继续沿原路径，直到单独清偿文本承载债务。
2. **从最终消费者反向证明整条复制链。** 字段后缀核对 `dup; getfield; dup_x1; iconst_1; iadd; putfield; ireturn`：`getfield`/`putfield` 同一已证明 `I` 成员及同一接收者两份复制，`dup_x1` 留给返回的是读取的旧值，加法取该旧值和常量 1，最终写入的确是加法新值。数组后缀核对 `dup2; iaload; dup_x2; iconst_1; iadd; iastore; ireturn`：读写同一已证明 `[I` 的数组/索引复制，返回的是 `iaload` 旧值。方法调用等前置生产者不要求固定起始 BCI，但必须能通过现有最终求值位置/顺序证明单次呈现、无链外消费者，且不能越过中间独立的可观察效果。同一基本块并不保证异常表保护范围相同；折叠前还要用已有逐指令 effect/handler 事实核对整条候选与返回位置的有序 handler 集。只看邻接 opcode 或相同变量名均不够；不满足任一身份、类型、位置、独占消费、handler 或同块条件时不认领。
3. **以返回语句作为唯一发射点认领整链。** 正例在 `ireturn` 处构造 `return target++;`，把接收者、数组和索引从原 SSA 生产值递归渲染；被认领的调用、复制、读取、算术和写入不能在前面另发语句。目标的左侧先求值，Java 后缀操作在返回旧值前执行读取及写入，保持 null/界限检查和溢出语义。任何表达式构造失败应通过既有 fallback/延期生产者追溯覆盖整链，不能一半认领或重复发射。已由 `FieldIncrements` 证明的简单字段形状仍先由原规则认领；新规则只看未认领的返回链，不能双重认领。
4. **来源和成本随现有路径走。** 后置节点以真实写入 BCI 为主，复制/读取/加法为 derived，子节点带接收者、数组、下标及字段成员自己的来源，`return` 节点仍有其物理 BCI。候选识别只访问固定长度链及有界的现有值渲染，轮询取消并计入既有预算；默认/完整来源只影响附加 segments，不改变正文。若预算中断，沿用当前停止契约，不交付半个更新。
5. **不引入解析或运行依赖。** Rust 侧只读现有 class/IR 事实；受控测试中的 `javac`、`java -Xverify:all` 和 JADX 是验证手段，不进入产品路径。parse、方言校验、运行时选择、JVM 验证与 Java source recovery 仍为不同阶段。

## Risks / Trade-offs

- 接收者调用在 `dup` 前先被独立发射 → 先证明整链并归属生产者，整类调用计数验收一次；失败时依原始顺序引用生产者。
- 前置生产者被延期到返回处越过中间独立效果 → 复用现有最终求值位置/顺序判据，无法证明未重排则拒绝；边界样本保留原始调用顺序。
- 同块异常表从链中间开始或结束 → 逐指令 handler 集不同则拒绝单表达式投影；JVM 可验证的数组调用在保护区外、读取在保护区内的样本确认下标调用的异常必须逸出，不能被新 `try` 捕获。
- 把 `dup_x1`/`dup_x2` 的新旧值弄反 → 由 SSA 复制值的具体消费者判定，分别核对 `ireturn` 与 store，并以溢出和写后返回旧值验收。
- 字段相同名字但不同属主、数组相同变量名但不同索引 → 对成员三元组及 SSA 数组/索引身份逐项核对，并做受控负例。
- 更新路径与 `+=` 或已有简单字段递增同时认领 → 共享文件串行实施，旧值返回链优先判定，正反回归保持原行为；不把本项扩成复合赋值实现。
- 现有预格式化字段更新的来源/括号债务仍在 → 在独立债务记录中跟踪，不扩到本次提交；本次新形状必须使用真实后置节点。
