## Context

成员家族装配使用 `ClassSourceMemberRelation`、`ProvedMemberInnerSourceSegment` 和同请求恢复结果；`BodyBuilder::source_type_path_name` 已能在静态调用属主位置从准确二进制名取得已证源路径。局部声明的 `StmtKind::Declare` 仍只持有 `Type`，发射器直接调用 `Type::spell()`，于是成员类型留有 `$`。冻结 `OuterSuperEffects` 的 `main` 正是这个位置失败；桥调用和两次 `tick` 已分别证明。

## Goals / Non-Goals

**Goals:** 复用现有成员路径证据，为局部声明附上独立的源级拼写；语义 `Type` 保持二进制身份，普通声明与循环头由同一发射逻辑处理。

**Non-Goals:** 全局 `$` 名重写、泛型成员实参/原始类型推导、注解/强转/字段/方法签名中的所有成员类型位置、扩大 `Outer.super` 桥准入或修改 JVM IR。

## Decisions

1. **在声明 AST 附可选源名。** `StmtKind::Declare` 保留原 `Type`，额外携带从本请求已证路径取得的源级类型拼写；发射器对声明头使用它，没有时沿用 `Type::spell()`。原 `Type` 继续服务局部合流、赋值兼容及其他语义检查。对已生成文本做 `$` 字符串替换会误伤顶级合法 `$` 类、注释、字符串和来源 span，因此不采用。
2. **只认准确且非泛型路径。** 声明的 `Type::Reference` 所指二进制名必须在当前选定成员目标的 `source_type_path` 中唯一；每段泛型参数计数为零，路径的物理定义与当前选择一致。`source_type_path_name` 可复用其唯一性检查，不增全局命名表。数组/泛型声明另案处理。
3. **在统一声明构造点决定拼写。** 局部直接声明与 hoist/for 头共享同一已决定的局部 `Type`，只在表达式/语句 AST 成型时附加源名；`emit` 的提交和 source-map 重放遍历同一 AST，因而文本/偏移一致。拒绝或预算停止时不发布半成品别名。
4. **家族投影仍原子。** 该改变只修复确证的局部类型；`member_family_source_text` 不从文本反解析类型或隐藏其他物理来源。全类验收需要实际重编和运行，不能从单方法 AST 测试推出。

## Risks / Trade-offs

- `[路径只覆盖构造站点]` → 缺少该目标的同请求证据时保守留原拼写；后续需要扩展局部类型来源时另案。
- `[简单源名与顶级 `$` 类相似]` → 以选定物理定义和 typed 成员关系匹配，加入同名顶级类/多定义拒绝测试。
- `[其他源码位置仍有二进制名]` → 本任务只验已冻结家族的局部声明；审计中新位置记债务，不混入当前实现。
