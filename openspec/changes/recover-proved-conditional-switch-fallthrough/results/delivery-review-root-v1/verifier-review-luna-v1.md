## Findings

1. **The changed target method's quality is not pinned.** At verifier lines 410–414 the target branch checks only its usage delta and then continues, intentionally bypassing `verify_report_preserved`. The later anchor-specific checks require a report and source map, bind method identity, and compare the source-map BCI set with `javap`; they do not require the target outcome to be `recovered`/`Structured` or otherwise constrain `quality`, `fallbacks`, `representation`, or `syntax_status`. Other methods and control cases do retain full non-map/non-usage report equality. The saved successful sample currently reports `outcome.kind = recovered` and `quality = structured`, so those observed semantics can be asserted for the anchor without comparing it to the typed fallback baseline. As written, a changed method with the same emitted body/map and exact counters but downgraded quality could pass. If Structured recovery is part of this feature's acceptance contract, add a narrow expected-quality assertion for this exact target.

2. **Anchor map validation verifies origins/BCI coverage, not segment byte ranges.** `owned_method_bcis` checks origin owner/name/descriptor and nonnegative BCI, and the verifier requires the set of those BCIs to equal all physical instruction BCIs ([verify-conditional-replay.py:81](/Users/lordcasser/workspace/projects/jarde/openspec/changes/recover-proved-conditional-switch-fallthrough/results/verify-conditional-replay.py:81), [verify-conditional-replay.py:428](/Users/lordcasser/workspace/projects/jarde/openspec/changes/recover-proved-conditional-switch-fallthrough/results/verify-conditional-replay.py:428)). It does not inspect `start`/`end` or verify that each half-open range is valid within the target method report's UTF-8 text. The product's `Segment` contract defines these as byte spans into emitted text and `Segment::text` slices exactly that range ([source_map.rs:254](/Users/lordcasser/workspace/projects/jarde/crates/jarde-java/src/source_map.rs:254), [source_map.rs:296](/Users/lordcasser/workspace/projects/jarde/crates/jarde-java/src/source_map.rs:296)). Consequently, a structurally wrong but same-BCI map can pass if default/all share the same bad ranges. A minimal independent check should require integer non-bool `start/end`, `0 <= start < end <= len(report_text.encode('utf-8'))` for every segment. This validates bounds; verifying span-to-node correspondence would need stronger emission evidence and is outside this offset patch.

3. **Usage counters accept JSON booleans where integers are expected.** The new exact comparison uses `new[key] == value + offset.get(key, 0)`; the legacy unchanged path also uses Python numeric comparison. Since `bool` is a subclass of `int`, `True == 1` and `False == 0`, so a JSON `true`/`false` can satisfy an expected counter value despite violating the usage schema. `elapsed_millis` already uses `type(...) is int`; apply the same non-bool integer check to every counted usage value in both snapshots before comparing. This makes the exact offset a schema-checked numeric equality rather than relying on Python's coercive equality.
