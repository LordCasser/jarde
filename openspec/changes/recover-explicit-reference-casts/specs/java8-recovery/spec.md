## ADDED Requirements

### Requirement: 显式引用转换保留运行时检查与来源

对于目标引用类型和操作数可呈现的普通引用转换，系统 SHALL 呈现显式转换，并在现有可恢复的返回、局部、调用和数组表达式中保留其类型、求值次序及来源。系统 MUST 不因结果被丢弃或消费位置无法呈现而隐藏原有检查。

#### Scenario: 对象与数组转换在消费位置呈现
- **WHEN** 自写 Java 样例将 Object 转为 String、int[]、String[] 或多维引用数组，并由返回、局部、调用参数、成员访问或数组读取消费
- **THEN** 恢复文本保留目标类型和正确括号，转换及操作数的来源可追溯；同一样例的恢复正文可重新编译

#### Scenario: 单次求值与嵌套检查次序
- **WHEN** 转换操作数是带计数的调用，或样例有两层不同目标的检查
- **THEN** 恢复程序只调用一次并按原顺序执行两层检查，受控输入的返回值和异常类别与原程序相同；不得只保留最终目标

#### Scenario: null 与错误引用类型
- **WHEN** 同一 fixture 分别输入 null、正确类型和错误类型，并且部分方法在转换后立即解引用
- **THEN** 原程序与恢复程序在 null 结果、正常值、ClassCastException 和 NullPointerException 上一致，系统不将成功转换或可读文本报告为已执行通用验证

#### Scenario: 丢弃与拒绝保留检查效果
- **WHEN** 转换结果无可呈现消费位置，或后续表达式无法恢复
- **THEN** 结果保留被延期检查及其必要生产者的字节码来源引用，不输出非法裸转换语句，不重复或丢失调用效果；bridge 既有已证明呈现不受普通转换规则破坏

#### Scenario: 来源预算保持真实
- **WHEN** 嵌套转换能呈现，或输出预算在呈现中耗尽
- **THEN** 完整结果保留各层转换和操作数来源；预算耗尽继续按既有停止契约报告，不伪造完整文本、来源或方法质量
