## Context

见 [proposal.md](proposal.md)。固定 `lastIndexOf` 的自然循环集合为 BCI 5/11/22；唯一命中分支到 BCI 19 的 `iload_4; ireturn`。`Frame::loop_body` 目前仅把自然循环块与指向循环退出/继续目标的单后继转移源放入 scope，BCI 19 因无回边也无这类转移而被过滤。`region_at_inner` 对失去的分支边不发布结构，未覆盖块扫描随后引用 BCI 19，`build.rs` 的局部变量词法计划正确拒绝跨 quote 的 slot 4。已有规范化 CFG、SSA、`Region::Loop`、预算及来源记录足以证明该窄形态。

## Goals / Non-Goals

**Goals:** 在原有循环区域边界内，证明单个从循环体分支到达的终止返回叶，纳入循环体所有权，随后让现有局部声明/返回构建路径自然生成正文。保持普通循环、负例和预算行为。

**Non-Goals:** 通用多出口循环重写、共享返回块、多入口或异常流、条件内赋值（CF-06）、强制 `for` 拼写、放宽局部变量跨 quote 约束。

## Decisions

1. **证明终止叶再扩展循环体 scope。** 从自然循环内的条件分支出口枚举候选；对候选检查唯一正常前驱、相同方法路径、无额外入口/异常或子例程边、末指令为有值 `return` 且无正常后继。只有完整证书成立，才把候选加入该循环 `Frame` 的可达范围；内层区域 walker 仍按已有 if/直线规则写返回。其他出口继续走现有 break、continue 或拒绝路径。直接把所有离开自然循环的块加入 scope 会吞并循环外正常尾部，因此不采用。
2. **归属与局部证书在同一恢复中闭合。** 扩展范围的候选必须被循环体实际遍历并只被一个区域拥有，未遍历或重复归属仍是 fallback。`build.rs` 保持现有 `common_owner`、定义使用和跨 quote 拒绝，不为 fixture 放宽局部规则；返回表达式沿原 SSA 值读取。无需新增 `Region`/AST 枚举变体或另建循环局部分析。
3. **沿现有预算与来源路径实施。** 候选枚举、前驱/边检查按现有预算计费并传播停止；BCI 19/21 及分支/更新 BCIs 应映射到最终语句。既有 CFG/SSA 和类源恢复是本项目所需的事实源；引入第三方控制流库无法替代与本项目区域所有权、预算、来源契约的结合。

## Risks / Trade-offs

- [把正常出口尾部误判为循环内返回] → 要求候选终止返回、唯一来自自然循环条件分支的正常前驱，并覆盖额外入口负例。
- [扩展 scope 后与相邻区域双重认领] → 要求循环体 walk 实际持有终止叶、全局未覆盖扫描与区域所有权检查仍通过；共享叶保持拒绝。
- [局部槽位被错误提升或返回值被重复计算] → 不改变词法计划，检查完整类 Java 8 编译、验证运行和来源；覆盖命中/未命中及零次循环。
- [CF-03 的 Frame 变化产生交叉] → 先在含 CF-03 主线的基底实现，再跑共享尾和循环定向回归；该任务只扩大已证明循环 body 的终止叶 scope。
