# Discarded-call complete-class replay draft

This directory contains the v2 unrun collector and independent verifier for the discarded-call source-map change. Both are private drafts; neither writes or changes repository sources when prepared. The collector is designed to write only the exclusive `results/candidate-replay-root-v2/` tree when root later invokes it with frozen candidate inputs. The verifier writes `acceptance-root-v2.json` there only after every independent check passes.

The replay uses the accepted `baseline-root-v1` as its immutable oracle. It rechecks the accepted execution-manifest SHA, the three original Java inputs, the frozen JDK/JADX identities, and the build metadata’s source pins and CLI hash. It compiles the original class bundle and then renders/recompiles the complete probe plus the unchanged runner for JDK 8 and 23 under default, all-evidence, and JADX profiles. Each runtime leg uses a fresh profile class directory and `-Xverify:all`; all eight outputs must be the same six lines with empty stderr. The recorder uses the existing pinned guarded command runner and keeps command argv, times, exit state, raw stream hashes, and resource observations.

The independent verifier parses the actual javap output for all seven physical methods, checks all 18 original/generated class artifacts by SHA-256, BLAKE3, and length, and checks default/all text and source maps against the accepted baseline. It permits exactly three new derived origins: pop BCI 4 on the complete `discardStatic` call statement, pop BCI 13 on `discardAppend`, and pop BCI 15 on `discardListAdd`. It removes each exact addition from a copy of the candidate segment list and requires the rest of every segment, body, primary origin, span, and method identity to equal the old baseline. The `pop2` negative and consumed/deferred calls remain baseline controls; no new origin is claimed for them.

The coordinated validation contract is `preserve-proved-discarded-call-origins-candidate-cli-v1`; its CLI path is `/private/tmp/jarde-proved-discarded-call-cli-v1`, metadata is `results/candidate-cli-v1.json`, and build execution is `results/validation-build-root-v1/execution.json`. The frozen validation suite is required to contain the five coordinated tests, including budget/cancellation and a negative `pop2` boundary; the replay still accepts only the three stated positive map deltas. Source base and all three paths must be passed explicitly. The draft assumes the coordinated execution envelope fields sent by the validation-runner author; it does not fabricate any future SHA or report candidate success.

No collector/verifier execution, Java invocation, CLI invocation, Cargo command, or Git command has been performed for this replay draft. Only Python AST parsing is appropriate before root review.


The v2 preflight report records the actual baseline JSON paths and verified keys. Baseline method identity is under `methods[].item.identity`; `report.method` is the concatenated name and descriptor string, `report.fallbacks` is a list, and the method entry has a text string. Baseline `original_classes` lives directly under each JDK leg, while the javap command is found by its exact command label. The accepted baseline has exactly the three missing pop BCIs in all four default/all profiles. The candidate verifier checks that explicit baseline gap set, then requires zero missing BCIs for every candidate method. It matches the actual derived-origin shape (`bci`, `cp: null`, `method`, `provenance: Derived`). The build contract uses `/private/tmp/jarde-proved-discarded-call-cli-v1`; the baseline acceptance is pinned by its own SHA-256 as well as its execution-manifest SHA.

`schema-preflight-root-v2.json` was produced by executing `schema-preflight-root-v2.py`, which only reads the accepted JSON/raw records and validation-runner source, checks those observed schemas, and AST-parses both drafts. It confirms 26 baseline commands, seven physical methods, and exactly pop4/13/15 missing in each of the four old profiles. No candidate replay or toolchain ran.


Run the scripts later with `uv run --offline --with blake3 python -B ...`; this matches the accepted baseline verifier’s existing BLAKE3 dependency. The v2 output directory is exclusive and separate from any v1 candidate output.
