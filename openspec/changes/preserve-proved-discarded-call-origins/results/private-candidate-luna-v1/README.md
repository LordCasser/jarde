# Discarded call-origin implementation draft

Private preparation only. No repository file was changed, and no Git, Cargo, rustfmt, Rust compiler, JDK/JADX/Jarde CLI or test was run. No acceptance or runtime result is claimed.

`implementation.patch` is the minimal production change against the current `build.rs`: both successful ordinary call-statement paths share `Builder::call_statement_origin`, which reads only the existing `DiscardedEvaluations.discards` map through `discarded_result_pop`. For a proved pop it polls and charges one `AnalysisSteps` unit at that exact BCI, adds one derived origin to the existing call-primary `OriginSet`, and returns before either path reaches `push` if interrupted. It does not consult `pops_of`, so static-call qualifier behavior remains separate. The call Expr, source text, and evaluation order are unchanged.

`DiscardedCallSourceProbe.java` and `DiscardedCallSourceProbeRunner.java` give the intended Java 8 whole-class replay shape: static non-void `give` whose result is discarded on normal and throwing paths, `StringBuilder.append(String)`→`pop`, interface `List.add(String)`→`pop`, plus return-consumed and local-consumed/deferred contrasts. `ProbePop2.java` is a separate negative input; it must not be added to the positive compilable class. Use the existing real N17a negative suite for other refusal controls.

It expects exactly one derived segment for the pop on the complete statement span (indentation, semicolon and trailing newline), while the existing trusted-subject, default/all identity, full physical-method coverage, and report-binding assertions remain in force.
