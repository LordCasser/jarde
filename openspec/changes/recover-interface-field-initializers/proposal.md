## Why

Java 8 接口的每个字段声明都必须有初始化式，非编译期常量的赋值则实际存于 `<clinit>`。当前类源码把这类字段写成无初值声明、再把方法体写成接口不允许的 `static {}`：三字段合法样例的原 class 与 JADX 均能编译执行，Jarde 整类被 javac 拒绝。字段表顺序还可在不改变 `<clinit>` 的情况下重排，不能简单把方法体文本贴回字段表。另一个已验证的 class 在 `<clinit>` 中先读取未赋值字段的默认值，再以常数指令写入它，原运行是 `0|9`；若源码将后者声明为 `= 9`，javac 会改成 `ConstantValue` 并把前者内联为 9，产生 `9|9`。

## What Changes

- 仅在接口的完整初始化轨迹可证明为一次、按序的自身字段赋值，且重编译不会把运行时写入升级为编译期常量时，将对应表达式投影到字段声明初始化式，按已证执行顺序组织源声明。
- 在类源码报告中保留物理字段表及原 `<clinit>` 的身份、恢复结果与投影归属；受损、未恢复或含额外效果的轨迹明确拒绝，不输出貌似完整但行为不同的接口源码。
- 对原 class、JADX、Jarde 进行 Java 8 整类编译与运行对照；纳入字段表重排、`ConstantValue` 阶段变化与副作用顺序边界。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `java8-recovery`：在可证明的范围内恢复接口字段初始化式，并如实暴露无法投影的初始化工作。

## Impact

前置条件是类源码现有成员注解、字段 `ConstantValue`、方法体恢复及预算/停止合同保持已验收状态。实现局限于既有 `jarde-java` 方法体呈现到核心 `class_source` 装配的接缝，不改 reader 格式、CLI 协议、JVM 执行或外部依赖。普通类静态块、枚举常量、注解类型字段、多分支/异常处理的接口 `<clinit>`、跨类求值与无法证明的字段引用另行处理；本项不以 Java 文本反解析、按名字删方法或全局新增初始化 IR 代替证明。
