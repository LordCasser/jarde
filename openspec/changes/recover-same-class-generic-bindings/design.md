## Context

见 [proposal.md](proposal.md) 与 [Z1 巡查](../../evidence/java-syntax-2026-10-03/nested-generic-header-patrol/README.md)。`jarde-reader::signature` 已提供有界解析、作用域和逐位置擦除证明；`src/class_source.rs::project_method_signature` 当前扫描整张常量池，只要有同 owner、同方法名的 `Methodref`/`InterfaceMethodref` 就报 `generic_call_binding_unproved`，连 descriptor 和实际消费点都未核对。字段投影对同 owner、同名同 descriptor 的 `Fieldref` 也直接报 `field_generic_body_unproved`。这些是安全拒绝门，不是使用点证明。

类源码请求已选定物理类并逐成员恢复，拥有成员表、Code/常量池、独立方法结果与同轮预算；其泛型投影目前发生在成员遍历中，须等相关使用点与候选成员都已收齐才能作类级提交。物理引用、Java 源码重载选择和运行时派发是不同事实，不能互相替代。

## Goals / Non-Goals

**Goals:** 用完整的同类使用点证据准入一个有界泛型方法或字段声明；证明 Java 8 源码重编仍绑定原物理成员；在不完整、竞争或停止时原子拒绝。先以无竞争的顶层类闭合方法与字段，再验证相邻重载的正反边界；Z1 用于确认两个诊断门的实际归因。

**Non-Goals:** 不从方法体推断缺失的 `Signature`；不实现任意 Java 泛型类型推断、外部类层级解析或运行时虚派发求解；不改变 reader/query 的物理引用事实或独立方法恢复文本；不在本变更处理嵌套类头、lambda、成员类折叠、增强 `for` 元素类型和语料维护。未证明的 Z1 使用点可以继续拒绝，不能为了消除诊断计数放宽语义。

## Decisions

1. **复用现有事实，不引入通用解析器或 XRef。** `Signature` 语法、擦除和类型变量域来自 reader；真实调用/字段使用来自同次选定类的已解码 Code、成员身份和必要的 SSA/AST 侧证据。对每个使用点保留调用者物理身份、BCI、opcode、CP 指向的 owner/name/descriptor；只在类源码请求范围内做有界枚举。`jarde-query` 的全局引用搜索不进入单类恢复，JADX/Javac 只在测试中作对照。现有 noak/reader 能解析 classfile，却不提供 Java 源码重载绑定证明；新增库会重复语法或引入不必要依赖，故不新增。
2. **候选与提交分开。** 保留 `project_method_signature`、字段 Signature 投影的既有语法/擦除/正文判据；遇到同类 CP 引用时先保留未提交候选，待本类方法和字段记录完整后检查实际消费者，再复用现有整成员文本计费与发布路径。实现可使用私有局部暂存，不增公开报告类型。没有实际使用的 CP 条目只有在所有受支持消费来源与方法体完成扫描后才可排除；解码停止、不可达/未呈现片段、`MethodHandle`/bootstrap 等无法覆盖的引用来源按未证明拒绝。
3. **方法调用按源级候选集证明，字段按声明和使用类型证明。** 先用原 opcode 与 owner/name/descriptor 固定物理目标，再核对发射后的接收者、实参静态类型、目标声明及同名可见方法集。无竞争、同 arity 的已证形状可先准入；同名重载只在适用性与最具体选择都能证明时准入，继承候选或未知类型保持拒绝。字段无重载，但要核对同名遮蔽、读写值类型及后续消费者；仅靠 `Fieldref` 精确匹配不能证明参数化字段在 Java 源码中可用。任何相关方法的正文被引用、类型流未知或使用点集不闭合时，相关声明保持擦除形态。替代方案是按 CP 名称继续整体拒绝，安全但会让无用 CP 和已证调用长期阻断；另一方案是按文本或 `javac` 反推绑定，不能作为产品内证明。
4. **互相影响的候选一起验收再提交。** 若方法返回值来自待投影字段，或一个候选的类型改变另一个调用的源码静态类型，先对受影响使用点的候选集合做闭合检查，再整体提交该组。失败只拒绝该组，不回滚无关成员；物理记录、原始 `Signature`、独立方法报告与来源不改。每次扫描、类型递归、候选比较和输出写入使用既有预算并轮询取消；essential/all 只影响证据详情，不改变准入。类级装配在提交后才生成最终文本，避免声明与正文来自不同版本。
5. **分层验收。** 冻结一个无重载方法/字段最小 Java 8 类、未使用 CP 变体、同名重载可证/不可证变体、字段遮蔽与不完整扫描负例；逐项记录原 class、Jarde 和固定 JADX 的源码/`javap`/SHA。成功子集用独立调用方、泛型反射、`javac --release 8` 与 `java -Xverify:all` 比较调用目标、值、异常与字段状态。失败子集核对拒绝码、原 BCI、预算/取消和方法原始报告，不把能编译的保守文本计作语义等价。

## Risks / Trade-offs

- **源码重载选择依赖未选中的父类或接口** → 只在所选类及可证明的层级闭包内准入；缺失依赖维持拒绝，不假设 `Object` 之外无竞争方法。
- **泛型字段类型改变链式方法调用的适用性** → 证明字段的所有受影响消费者；首片不能完整追踪的链保留 `field_generic_body_unproved`，不做文本替换。
- **常量池未使用条目与隐藏使用来源难区分** → 完整检查 Code 与可消费该引用的受支持属性；任何扫描停止或未知消费者都不构成“未使用”证明。
- **Z1 同时有其它未完成类级形态** → 以独立最小类做正向整类门禁；Z1 只逐项核对本门的诊断变化，不宣称其全家族可编。
- **类级晚提交改变输出预算次序** → 在原成员文本不变的前提下计费并记录差异，低预算和取消必须保留一致的停止与物理事实；不为维持旧计数跳过真实工作。
