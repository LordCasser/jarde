## ADDED Requirements

### Requirement: 共享 catch-all 的静态整数字段清理只呈现一次
系统 SHALL 在 Java 8 字节码明确证明一个具名 catch、两处正常返回和共用 catch-all 的每条完成路径都执行同一静态 `int` 字段加常量清理时，恢复可编译的 `try`/`catch`/`finally`，并使正常返回、具名 catch 返回及异常重抛的字段效果与原 class 一致。系统 MUST 为所有被折叠的物理清理副本及异常行保留可追溯来源。

#### Scenario: 三份字段增量副本完全一致
- **WHEN** 一个 Java 8 类的 try 正常返回、具名 catch 返回和共用异常 handler 各有一份相同字段、相同 `int` 常量、相同加法的清理，且每份值只供该副本的字段写回使用
- **THEN** 系统输出唯一 `finally` 字段更新、保留两个返回和具名 catch；完整类源码可重编并在正常与 catch 路径各只更新字段一次

#### Scenario: 任一副本的字段或增量不同
- **WHEN** 三份清理中的任何一份读取或写入另一字段、使用另一常量或另一算术效果
- **THEN** 系统 MUST 拒绝把三份副本合并为一个 `finally`，并保留可定位到物理字节码的诊断

#### Scenario: 异常范围或值的归属不闭合
- **WHEN** 一份清理落在会再次捕获它的保护范围内，异常行顺序或边界变化，或者清理值有额外消费者/路径入口
- **THEN** 系统 MUST 不发布部分结构化 `finally`，并保留受影响的物理来源

#### Scenario: 资源限制和取消
- **WHEN** 该候选在证明或构建期间耗尽声明的预算，或者任务被取消
- **THEN** 系统 MUST 停止且不输出部分源码或部分来源图
