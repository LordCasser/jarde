## Context

见[提案](proposal.md)与[三方证据](../../evidence/java-syntax-2026-09-24/generic-constructor-signatures/analysis.md)。`jarde-reader::signature` 已能解析方法 `Signature`，以类型变量第一界证明参数/返回与物理 descriptor 的擦除；`class_source` 已把 `<init>` 写作类名，但通用方法泛型投影要求“静态直接参数返回”，因此拒绝这份已证签名。当前同轮恢复正文实际写出 `super(); return;`，不能把字符串相同当作正文证明。

## Goals / Non-Goals

**Goals:** 在现有类源码接缝恢复顶层、直接继承 Object 的简单构造器局部类型参数及参数；用同轮结构化正文事实证明参数不参与任何效果；保留原物理成员和局部拒绝。

**Non-Goals:** 不恢复 `this(...)` 委托、带实参的父构造器、字段初始化、参数参与正文、继承其它父类、嵌套类构造器或泛型异常；不改变通常有正文泛型方法的准入逻辑，也不把 JADX 的输出作为正确性证明。

## Decisions

1. **复用 parser 与擦除证明，不新增构造器 Signature 方言。** `<init>` 的 Signature 仍是方法签名，reader 的作用域、第一界和 descriptor 比较适用。源码层另验返回必须是 `void`、至少一个方法自有变量，界/参数均能完整拼写；不接受凭字符串扫描出来的 `<T>`。新 parser、第三方库或单独恢复 pass 均无新增证明价值。
2. **从同一恢复运行提取很窄的正文候选。** 在 `jarde-java` 的现有 class-source sidecar 接缝，只有完整、不含 fallback 的 AST 恰为无参 `ConstructorCall::Super` 加 `Return(None)`、`Code` 无异常处理器，且相应 SSA 指令只形成 `aload_0; invokespecial Object.<init>()V; return` 时交付参数槽/名候选；原 `InitRecord` 还须证明呈现的目标是 `java/lang/Object`。这个结构保证原参数没有读取/重写、额外效果或隐藏的 `this(...)` 链。候选不从最终文本反推；正文恢复未完成就不存在候选。宽泛地允许所有可重编构造器会把重载/参数类型约束扩到当前 AST/SSA 未证明的形状。
3. **类和调用绑定采用可解释的保守门。** 首片只接受顶层普通类、物理父类恰是 Object、零接口和无同类 `<init>` Methodref；拒绝复杂构造器/参数/type-use 注解和 varargs 等暂无法原位保持的声明。这样其它本类正文不因新的泛型构造器而改变调用编译或重载选择。未来如需放宽，应逐调用证明绑定，不以“源可重编”替代。类自身字段的存在不是拒绝理由，但任何实例字段写入会让正文候选失败。
4. **一次构造完整声明后原子发布。** 复用无正文方法已经引入的结构化界/类型拼写规则，参数名按同轮已证 slot 对齐，泛型变量在可见作用域里解析；无支持的异常后缀和物理异常均拒绝。构造器格式为修饰符、`<...>`、类名、参数；没有返回类型。签名语法、擦除、正文、同类调用、完整拼写和输出预算全通过后才调用现有 `project_generic`，否则保持物理声明与原报告。essential/all 正文与预算/取消语义沿用现有类源码操作。

## Risks / Trade-offs

- **AST 漏掉正文效果** → 同时要求无 ragged/fallback、完整执行、无异常处理器以及精确 SSA 指令形状；不凭重编成功放行。
- **源码重载绑定不同于字节码 descriptor** → 本类任何 `<init>` Methodref 先拒绝；后续扩围需有逐调用绑定证明。
- **无调试表时参数名不同** → 仅由同轮参数槽映射取名，不依赖 LVT；两种 debug 变体各做完整类与调用方对照。
- **范围保守导致已有可恢复构造器仍为物理声明** → 作为后续语法覆盖分析记录，不借当前子片引入泛用构造器类型求解器。
