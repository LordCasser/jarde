# Typed CI repair adapter v3 (private draft)

This version carries the v2 CI capture and independent verifier forward to a new capture directory and a new exclusive acceptance output. The historical typed build remains bound to the same metadata, CLI, build execution, runner, source base, product/test source pin sets, canonical include closure, fixed CI seeds, four CI jobs, and 52 successful steps. The source-file closure counts are still 17 product paths, 10 test-source paths, and 50 canonical inputs. The verifier takes the original source-derived typed test names/count explicitly and checks them against the frozen metadata; it does not describe that historical set by an assumed case count.

The separate repair gate now requires the root-v3 local execution record at `/private/tmp/jarde-typed-ci-repair-root-v3/execution.json`, schema `typed-ci-repair-local-root-v1`, and status `passed`. It checks the ordered fmt command and the three-suite Cargo command, each row's raw stream paths, byte counts and SHA-256 values, exit status, resource guard telemetry, and environment overrides. The test names are derived from the three exact Git blobs, and each binary must have one matching `Running` header, a `running N tests` block, every source-derived active name marked `ok`, and an exact `N/0/0` summary. The verifier does not infer a fixed test count from the number of suites.

The repair-only pin map contains nine inputs, checked against both the selected product commit's Git blobs and live files. It remains separate from the 76-path historical typed build closure. In particular, the new `NullThenBuilder` positive test is covered by the lifetime test source and its class/baseline pins, while the existing negative cases stay within their unchanged pinned source.

The currently available root-v3 repair record is failed: the meeting suite passed, but the reference-lifetime suite reported 7 passed and 1 failed in `null_first_exact_builder_writes_refine_only_the_local_type`. Cargo stopped before the required-conversions binary ran. The verifier therefore rejects this record and requires a later status-passed execution that contains successful raw output for all three suites. No CI, Cargo, Git, or JDK command was run to prepare v3. Only Python AST parsing and read-only hashing/source inspection were performed.

When the root-v3 repair record and new CI capture are ready, invoke the verifier with the same reviewed CLI/build arguments as the earlier adapter, but point `--repair-execution` at `/private/tmp/jarde-typed-ci-repair-root-v3/execution.json`, pass its actual SHA-256, and use the default v3 capture/acceptance paths. The acceptance output is exclusive and will not overwrite an existing file.
