# CF12 local-source-type replay — private v5 draft

Status: unreviewed and unrun. The collector and verifier are private drafts; no JDK, JADX, Jarde CLI, Cargo, Git, or product command was run for v5. Both Python files were checked with `ast.parse`, and the accepted baseline plus its inputs were read and hash-checked. No candidate result or acceptance is claimed.

The scripts require explicit candidate CLI, metadata, validation execution and SHA-256 values, source-base commit, JDK homes, and pinned JADX. The v5 collector fixes boundary stage recording so each profile row is initialized after the compile attempt regardless of its exit status; a failed compile therefore retains its own `compile` row and `runtime: null` rather than inheriting or omitting a row. They also require the exact independently accepted post-pop control baseline: `/private/tmp/jarde-cf12-post-pop-baseline-root-v4/execution.json` (SHA-256 `93dc97cf…433bc08`) and `acceptance.json` (SHA-256 `bc9be073…c7df06`). The acceptance is schema `recover-proved-local-source-types-post-pop-baseline-acceptance-v3`, status `accepted-independent-control-baseline`. The verifier checks the exact binding, six cases/eight classes, JDK23-only 48-command matrix, 16 reports, 38 method profiles and nine accepted pop-origin additions. It compares candidate controls and non-target anchor methods against those frozen reports. Only the named `test` method in `TestSwitch.test` and `TestSwitchNoDefault.test` may differ from that comparator.

Both anchors require successful complete-class compilation and runtime on Java 8 and 23, with successful fresh original/JADX/candidate runtime commands and exact stdout/stderr equality. Fresh Java23 original output is also compared with the historical original/JADX raw oracle. Physical instruction BCIs are parsed from the exact target method's frozen javap output and checked against its source-map primary/derived entries. Method identity includes the report member index, raw name and descriptor, owner digest and snapshot. Origin entries in this report schema do not carry a member index; each is bound to the uniquely selected report method by exact name, descriptor and owner.

The historical CF12 root-v6 acceptance is pinned by SHA-256. The scripts recheck its 429-file closed-input inventory and the consumed helper, class, SDK, runtime, report, javap and execution evidence. The accepted 451-entry copied-evidence list is used to locate and authenticate consumed historical artifacts; its mutable README progress copy is not treated as an input. The old raw command outputs outside the repository are validated against the exact SHA/length records in the pinned full-replay execution record, and historical original/JADX/Jarde classifications are recomputed from raw commands.

Every fresh command uses the pinned `run-validation-build-root-v9.py` guard (SHA-256 `51103f51…b8c33`) with the process-group and one-second 5 GiB free-space / 1 GiB `target` guards. The collector records argv, timing, exit status and raw stream hashes. It pins the Java/Javac/Javap files for both JDKs and captures the pinned JADX version command. The two self-contained anchors use both JDKs; the four CF12 controls use Java23 only because the original Java8 control runtime loads `JadxAssertions` class version 55 on a version 52 runtime.

The neighboring local-type boundary is recorded as a separate observation. The verifier checks the complete original source/Runner, the JADX and candidate render/compile/runtime command chain, source/report identity, raw outputs for any successful runtime, and default/all text-map equality when both reports exist. It preserves failed stages as classifications and never calls them passes. A boundary refusal does not relax the two successful-anchor requirements; root can decide later whether the recorded boundary classifications are acceptable.

The verifier also checks default/all report coverage for every captured class, complete generated class paths when compilation succeeds, the one historically expected CF12 compile refusal without requiring a full generated class set from that failed compile, and exact source-map/method identity. For controls and unrelated methods it compares report quality/outcome/refusal/diagnostics and every usage counter; only `analysis_steps` and `elapsed_millis` may differ in those counters.

`static-schema-preflight.json` records the accepted post-pop artifact hashes and the 429-file closed-input audit. The copied historical README differs from its old inventory record because it is a progress document; the complete closed-input inventory remains unchanged. The candidate CLI and build metadata for this replay are still supplied at execution time and have not been assumed or run.
