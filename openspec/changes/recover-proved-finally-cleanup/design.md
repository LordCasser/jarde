## Context

`guard::finally_copy` already recognizes a straight handler of `astore primary; cleanup; aload primary; athrow`, then deliberately refuses it. That is correct: an exception-table `catch_type == 0` does not establish that the normal-path cleanup is the same, or that every protected exit runs it once. The existing `guard::Plan` claims instruction ranges/blocks only after proving their coverage, `Region::Guard` preserves that ownership, and `StmtKind::Try`/the emitter already write the `try` part. The missing facts are **copy equivalence and completion flow**. The narrow 593-byte fixture demonstrates ordinary return and a try exception; the 947-byte snapshot fixture proves cleanup may mutate the returned field yet the saved value remains, and its JVM-valid copy/range variants change the observed result. Its two methods with an explicit `throw` in cleanup are negative completion-override boundaries; the separate 787-byte fixture shows a cleanup **call** throwing on a non-overriding source shape, where even a compilable JADX result duplicates its effect. The broader 907-byte fixture also isolates overriding return/throw where even a compilable JADX result has wrong effects.

## Goals / Non-Goals

**Goal:** Recover the straight Java 8 `try { return value(); } finally { cleanup(); }` family when both cleanup copies, the saved return, the original exception rethrow and every exit are proved. A cleanup call may itself throw; Java's `finally` then naturally replaces the pending completion. Source maps must include both physical copies and the exception row.

**Non-Goals:** Return or explicit throw from the cleanup body, break/continue, branches or nested guards in cleanup, multiple normal exits, shared/incompletely covered handlers, `jsr/ret`, arbitrary catch-all handlers, or a general semantic-equivalence solver. Those remain referenced and are separate audit/changes.

## Decisions

The local JADX 1.5.6 source is an algorithm reference, not a semantic oracle. `MarkFinallyVisitor.getTryBlockData` first selects a catch-all and groups its execution scopes; `cutHandlerBlocks` then requires every handler exit to throw the captured exception before removing the rethrow tail. `extractFinally` compares each remaining cleanup instruction across every non-finally scope and only then marks duplicate instructions `DONT_GENERATE`. `ProcessTryCatchRegions` runs later to wrap the already identified regions. Jarde should reuse that ordering—identify all exits, prove matched cleanup copies, then claim and present one logical body—but its proof must compare SSA values, targets, completion order and physical BCI ownership rather than register likeness. JADX's `SameInstructionsStrategyImpl` may equate debug/code-variable registers, and its `TestTryCatchFinally15` records an incorrect register merge; the executable 787-byte fixture also shows a compilable JADX result that runs cleanup twice on one path. These are reasons to keep the complete refusal when any comparison is incomplete.

1. **Add a bounded proof in the existing guarded-region pipeline.** Extend the `finally_copy` examination into a narrowly declared guard shape/rule, with a certificate carrying the protected range, normal and exceptional cleanup spans, saved-return load/return, primary store/load/rethrow, owned blocks, join and physical origins. Register the rule through the existing pass/profile catalogue if a claimed `Plan` requires it. No new IR layer, crate or independent output pass is warranted. A catch-all row is only a candidate; the entire certificate must pass before ownership changes.
2. **Compare the code that actually runs, not nearby opcodes.** Require one straight handler `astore primary; cleanup; aload primary; athrow` and one straight normal path `save result; cleanup; load saved result; typed return`. Prove a one-to-one effect sequence for cleanup with the same invoked members/field targets, argument constants or stable values and expression order. Normalize the two copies' physical SSA IDs before comparison; do not equate different SSA IDs by accident, and reject values whose stability across both paths is unknown. Reject an explicit replacement completion, an unmatched side effect, a different pool target or a branch. Bound the walk with the existing budget/cancellation checks.
3. **Prove control-flow coverage and snapshots before rewriting.** The exception row must protect exactly the try body and cover all exceptions from it, with no competing row/exit that would skip or repeat cleanup. In particular, neither the normal cleanup copy nor the handler cleanup copy may lie inside that row's half-open protected range: a JVM-valid [range-widened class](../../evidence/java-syntax-2026-09-24/finally-range-widened/analysis.md) changes only `end_pc` from 20 to 23, thereby catching a throw from the normal `cleanup()` at BCI 20 and running the handler copy at BCI 26. It produces trace `299` where a source `finally` would produce `29`; JADX preserves the two calls in this case. The normal path must save the try return *before* cleanup and return precisely that saved value. The handler must rethrow the captured **same** exception object if cleanup completes normally. No cleanup instruction belongs to both copies or is also emitted as a stand-alone statement. If a cleanup call throws, the generated Java `finally` replaces the pending value/exception as the bytecode does.
4. **Present one logical cleanup with both physical provenances.** Extend the existing `Try` statement with an optional `finally` body (or an equally small variant) and the existing emitter with `finally { … }`; use one proven copy to build its statements, attach derived origins for its matching copy, saved return, rethrow and exception row. The `try` body's returned expression must be rendered at its original evaluation position, not re-evaluated after cleanup. Where existing `body_range` cannot express that return, a specific proven return statement belongs in this guard shape. Failure at any stage falls back to a quote of the full owned candidate range, including deferred producers.
5. **Keep neighboring rules independent.** Existing resource, monitor and typed-catch proofs retain their precedence and coverage. `finally_copy` refusal remains for candidates outside this slice; neither `catch_type == 0` nor a syntactically similar handler is promoted to a source `finally` without the new proof. The broader fixture's overriding return/throw and JADX divergence are permanent negative evidence, not an oracle for this implementation.

2.2 的实际接缝已经明确：`guard::resources` 当前在 `finally_copy` 预筛后调用 `prove_finally_copy`，但无论证书结果如何都返回 `jre_guard_finally_copy`。只有证书为 `Some`、其半开范围能由 `explained` 完整覆盖、`Plan::owned` 确实包括 handler 与正常返回时，才能改为现有 `Verdict::Claimed(Plan)`；失败仍保留原拒绝。`Plan::body` 应覆盖受保护的 try 指令至正常 cleanup 前，正常 cleanup 作为唯一 `finally` 正文，handler 副本只作来源锚点；saved return 必须在 try 正文内按旧值发射，不能在 cleanup 后重新计算。现有 `StmtKind::Try` 同时供 TWR 和命名 catch 使用，最小扩展是可选的 finally 正文并同步更新 emitter/遍历，不复制一套异常区域 AST。

这里有一条不能跳过的结构门槛：当前 `Builder::body_range` 只是逐条调用 `instruction()`；`Comparison` 与 `Transfer` 在这条路径没有语句输出，因而若直接把 `ImplicitCleanup.run` 的受保护范围 `(0,20)` 当作平坦正文，BCI 3 的条件分支会静默消失。先交付的直线型 `FinallyNormal.run` 可用 `statement_free`/无转移门槛消费半开正文；带 `if`/`throw` 的 `ImplicitCleanup.run` 要把原有 Region 的条件/异常边结构纳入同一个 guard 的正文，或在能证明等价的更小结构内表达，不能仅靠扩大 `body_range`。在该结构接缝闭合前，这个样本继续完整引用；不能以 cleanup 副本证明成功代替正文结构证明。

后续结构化正文的优先接缝是现有 `Region::Try` 已使用的有界 `Frame::protected`/`region_at` 递归，而不是另写 finally 专用的 `if` 发射器。当前 `Region::Guard` 在拿到 `Plan` 后立即将全部 `plan.owned` 标成 visited，`Builder` 只拿平坦的 `plan.body`，所以不能直接复用递归：应先证明 cleanup 和完成语义，再让受保护正文在限定的物理范围内作为子 Region 认领，并使递归中的 catch-all 异常边只由这份已证 guard 负责，避免再次进入同一 guard 或把边当作普通 catch。子 Region 的块/BCI 集合必须与证书的正文所有权和 `explained` 范围精确相等，正常 cleanup、handler 副本及保存返回仍由外层计划负责；缺任何一项就保持现有整段拒绝。这是 2.3 的架构候选，需先用 `ImplicitCleanup` 的分支/抛错路径验证，不因已有直线型正例而直接开放。

现有控制流顺序还限定了这一接缝：`region_at_inner` 在 `visited.insert(node)` **之前**尝试具名 `try_region`，使其能从同一入口递归；`guard::examine` 则在入口已标记 visited 后才运行，且一旦 `Claimed` 就先认领全部 `plan.owned`。因此不能在当前 `Region::Guard` 发射时直接调用 `region_at(start, Frame::protected)`，它会把入口判作重入。实现时应让已证 guard 的受保护正文拥有与具名 try 类似的受控递归入口，再在子 Region 与外层 cleanup/handler 的所有权集合核对通过后提交 visited；不得通过跳过重入检查或重复发射平坦正文规避此门。

2.3 的下一步无需新 IR。`FinallyLeadSnapshot.run` 的物理异常表只保护 `[5,9)`，而同一融合块的 `[0,5)` 先写 `value = 41`；[三方基线](../../evidence/java-syntax-2026-09-24/finally-lead-snapshot/analysis.md)显示原/JADX 为 `41:99`，当前 Jarde 引用。`Plan.lead` 和 builder 在 guard 前的 `range(plan.lead())` 已是准确接缝。仅在 lead 完整、无分支且不属于异常表，和既有副本/保存值证书一起可由 `explained` 覆盖时，允许 `proof.protected.0` 落在当前块内部；仍以 `[5,9)` 作为 try 正文。不应为此把异常表的保护范围扩到 lead，也不改结构化分支的拒绝门槛。

## Risks / Trade-offs

- Equal-looking cleanup calls can consume different state or run a different number of times. Compare normalized operands and require a single path/copy per exit; refuse ambiguous mutations or aliases.
- Moving the pending return computation after cleanup changes side effects and the returned value. Verify the saved local/value SSA chain and full-class execution when cleanup mutates observable state or throws.
- A catch-all may represent generated control flow other than source `finally`. Treat the row as a candidate and keep the complete source-bearing refusal when its handler/copy/range proof fails.
- Claims over fused canonical blocks can silently drop instructions. Use the existing half-open BCI spans, `owned` and `explained` coverage checks, and quote any unexplained instruction.
