## Context

见 `proposal.md` 和 [DT-07 冻结审计](../../evidence/java-syntax-2026-09-27/dt07-nested-anonymous/analysis.md)。已验收的单层匿名接口投影会读取直接返回 AST，通过类型化类元数据绑定一个物理 child，以 XRef 检查所选范围并发射其方法体。本次冻结的双层形态中，现有 owner-use 闭合逻辑会把孙 child 的合成字段描述符 `this$0:LNested$1;` 视为额外引用；仅放行该引用仍会使孙 child 构造器和类身份暴露在根源码中。现有 emitter 能发射单个匿名表达式并接收预先准备的方法文本，但现有 per-method allocation scan、owner XRef 与匿名候选之间没有两级关系证书，也没有把嵌套匿名方法范围组合回根产物的事务对象；这些是本切片需要增加的最小私有机制。

## Goals / Non-Goals

**Goals:** 在同一个 class-source 请求中闭合恰好一条直接嵌套匿名接口关系，并从保留的同次物理证据组合出完整的两节点根表达式。

**Non-Goals:** 通用匿名类图重写；任意深度或兄弟节点；匿名父类表达式；捕获局部值；读取父捕获字段的嵌套正文；任意构造器/初始化效果；完整项目导出。

## Decisions

1. **增加小型关系证书，不另建匿名类后端。** 以物理定义、方法身份、分配/构造 BCI、接口描述符和类型化 `InnerClasses`/`EnclosingMethod` 绑定根分配、外层物理匿名类、精确实现方法、嵌套分配和内层物理类。证书只描述一条 parent-child 边及其唯一 immediate-parent 捕获字段；不得从二进制名标点推导关系。考虑过递归调用公开 class-source API（会重复读取、消耗预算并重复分析）和在根扫描中白名单当前字段描述符（会让后代关系仍未闭合），均不采用。

2. **复用现有同次扫描和 AST。** 消费每个所选物理方法保留的 `AnonymousAllocationScan` 与 `ClassSourceMethodAst`。要求覆盖完整、每一层都恰有选定的直接返回分配，并与相应 `invokespecial` 构造器匹配。内层捕获仅证明一个 synthetic-final 字段，其描述符必须等于所选直接父类；构造器从精确 `this` 参数只写入一次，且任何方法正文都不读取它。这是匿名关系边，不是放宽一般局部变量或外层捕获投影。第二分配、未解析消费者、不完整 XRef 范围或不支持的消费者都会拒绝整个候选。

3. **增加精确两级私有候选，从叶子向根组合并一次提交。** 当前 AST emitter 能处理单个节点，但不能独立表达 parent/child 的共同证明及各层 source-range 对应关系；增加一个仅表示这两个节点的私有候选，持有两条分配/构造身份、一个直接父捕获证书和叶到根的 staged method text/anchors，不向任意深度泛化。先发射内层实现方法体，再对外层实现方法使用现有 anonymous-return AST emitter；最后在根分配点把已组合的方法包入外层匿名接口体。通过 class-source 结构化 writer 放置完整表达式，使来源范围和锚点在每个外层方法放置时都正确翻译。不得拼接或全局替换已渲染文本，也不得改写独立物理报告。叶子、父节点或根放置任一步失败，都保留原始根文本和所有物理 child 报告。

4. **与并存投影冲突时原子拒绝。** 发布前要求根和两个所选 child 报告均执行完整，且没有不兼容的嵌套类族投影并存。这样能将初始两节点关系与 enum、annotation、static-member 及 generic-member 投影规则分开，而不是在一个候选中合并多种类族重写。

5. **以固定 probe 界定正例范围。** 首个正例使用顶级 `Factory`/`Action`、静态根工厂、不捕获根对象、唯一 `make()` 返回点，以及只更新根静态计数器的内层 `run()`。本变更不把 `TestAnonymousClass12` 作为正例：其匿名父类及经外围宿主读取字段的形态需要另一种 receiver/capture 证明。固定测试提供目标语法证据，不代表可以扩大证据边界。

## Risks / Trade-offs

- [类型化的后代字段引用可能掩盖其它类身份用途] → 仅接纳与精确 `EnclosingMethod`、直接父类描述符、构造器写入及完整范围 XRef 配对的字段关系；任何未匹配引用都拒绝。
- [省略物理 child 构造器可能改变行为] → 内层构造器严格限制为规定的 immediate-parent 捕获写入和精确 `Object()` 调用；Java 源码嵌套会重建同一编译器捕获边。以完整 Java 8 源码重编和验证器运行确认。
- [嵌套文本放置可能令来源范围失效] → 每层放置都使用结构化 writer 的范围翻译并测试物理来源锚点；不得沿用中间未缩进文本的偏移。
- [部分准备的后代可能泄露外层投影] → 在请求共享预算下原子构造和发布候选；错误或停止时不提交任何嵌套表达式。
