## ADDED Requirements

### Requirement: 已证明的字符串拼接作为对象构造实参

当已证明的字符串拼接链是对象构造器的真实实参，且其求值范围、唯一消费和异常范围可完整证明时，系统 SHALL 将该链呈现在对象构造表达式的实参位置。恢复结果 MUST 保持外层分配、内层拼接、构造器调用及最终消费的原有顺序和次数；证明不完整时 MUST 保留相关物理来源，不得将独立效果折入实参。

#### Scenario: 拼接实参的对象被抛出

- **WHEN** Java 8 字节码先分配异常对象，再计算字符串拼接实参并调用其构造器，最后抛出该对象
- **THEN** 完整类源码 SHALL 可用 Java 8 编译，执行时抛出原消息对应的异常，且拼接及构造均只发生一次

#### Scenario: 拼接实参的对象被返回

- **WHEN** 相同的构造形态以返回新对象作为最终消费
- **THEN** 完整类源码 SHALL 可用 Java 8 编译，返回对象的消息与原 class 一致，且不得丢失返回或重复分配

#### Scenario: 相邻已支持构造与拼接保持原行为

- **WHEN** 构造器接收常量或直接参数，或者已证明的字符串拼接直接被返回
- **THEN** 系统 SHALL 继续呈现原有完整语句，默认与完整证据模式的正文一致，并保留真实指令来源

#### Scenario: 不能证明的嵌套效果被拒绝

- **WHEN** 内层分配未被证明为该构造器的实际实参链、链的结果有多个消费者、链跨越构造范围或异常处理边界，或其中含独立 void 效果
- **THEN** 系统 MUST NOT 将其当作构造实参；保守结果 SHALL 保留涉及的分配、效果、调用及消费者的来源和拒绝原因
