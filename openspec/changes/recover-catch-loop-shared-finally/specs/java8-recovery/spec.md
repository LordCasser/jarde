## ADDED Requirements

### Requirement: 具名 catch 与循环正文的共享清理仅恢复为一次 finally

系统 SHALL 仅在 Java 8 方法的具名 catch、正文循环、正常与 catch 完成的清理副本、异常清理副本、handler 自保护范围以及原异常身份都有完整物理证据时，把同一可观察清理恢复为一份可重编的方法级 `try/catch/finally`。输出 MUST 保持各路径的调用顺序、执行次数、异常覆盖和全部字节码来源；证据不足时 MUST 安全拒绝，不能仅因副本调用名称相同而删去任何一份。

#### Scenario: 正文正常和具名 catch 完成

- **WHEN** 固定 Test3 同布局方法的加载与迭代均正常，或正文中的加载/逐项访问抛出可被具名 catch 接收的异常
- **THEN** 恢复方法 SHALL 在正常路径不记录错误、在 catch 路径按原次序记录一次错误，并在两条路径各执行一次 `unload()`；原方法、固定 JADX 与恢复方法的最终结果和可观察操作 SHALL 一致

#### Scenario: catch 或清理自身抛错

- **WHEN** catch 内的记录调用或任一路径的 `unload()` 抛出异常
- **THEN** 恢复方法 MUST 保持原字节码规定的异常覆盖与传播；清理调用不得被吞掉、重复执行或在 handler 自保护行上递归进入自身

#### Scenario: 物理形状或操作身份不成立

- **WHEN** 清理副本的接收者或目标不同、循环/具名 catch 有额外入口或出口、异常行缺失/扩大、自保护范围覆盖清理调用，或 handler 重抛的值不再是进入的 Throwable
- **THEN** 系统 MUST 拒绝唯一 finally 投影，保留未证明字节码和对应物理异常行的来源

#### Scenario: 方法来源、停止与整类质量

- **WHEN** 方法恢复成功、证明预算耗尽、请求取消，或同一类的独立静态初始化仍未恢复
- **THEN** 成功的方法 SHALL 使固定目标的全部 BCI 可追溯；停止或证明失败 MUST 原子保留安全拒绝；独立成员的失败 MUST 保留其质量标记，不能把方法级恢复宣称为整类可重编
