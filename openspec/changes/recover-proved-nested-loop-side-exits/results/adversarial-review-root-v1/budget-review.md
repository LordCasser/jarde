# CF11 side-exit proof final static review

Scope: read-only inspection of current `crates/jarde-java/src/region.rs`; no Rust/JDK/JADX/CLI/Git execution. This is a budget/accounting review, not a runtime result.

## Findings

1. **Material under-accounting in `nested_loop_side_exit` (lines 14547–14672).** The helper charges `child_blocks.len()` once at 14548–14553, then performs several separate full scans of that set: overlap check, nested-header check, path/scope check (14554–14564), owner/visited/scope/path checks over `side_owners` (14635–14653), and the child adjacency scan while constructing `internal_edges` (14662–14672). `loop_exit_nodes(&child_blocks)` at 14596 also scans child successors. Those latter adjacency rows are then scanned again by `nested_loop_exit_bridge`; its full canonical-edge scans are charged and polled, but they do not pay for the earlier `view.successors(from)` traversal. The single `len` charge therefore does not represent the actual node/edge visits. Several collection pipelines also do not poll while they run, so cancellation or elapsed-time interruption can be delayed across a large child set.

   Minimal direction: combine the child-set predicates into one explicit per-node loop with `poll` and one `AnalysisSteps` charge per node; while iterating each child node's successors, poll and charge each adjacency row. Replace the unmetered `loop_exit_nodes` pass here with that same charged adjacency walk, or separately charge/poll it. Prefix-node scans are already charged one step per walk iteration (14499–14537); the final canonical-row check is already charged and polled in `nested_side_exit_edge_rows_proved`.

2. **Material under-accounting in `continue_nested_loop_side_exit` (lines 5336–5390).** `region_at` charges its graph walk, but its returned tree is rescanned without a fresh charge/poll: `child_loop.blocks()` plus set construction and `is_structured()` (5338–5347), gateway `iter`/`windows`/`is_structured` checks (5351–5363), and the combined `Region::blocks` flatten/set comparison (5366–5383). `visited.difference(visited_before)` can traverse the full accumulated visited set (5385–5390) and is also uncharged. These are validation work after the charged walk, not work already included in `region_at`'s charges.

   Minimal direction: add explicit charged/polled traversal for these validation passes. A coarse charge can use the known canonical node/edge upper bound before a pass if exact per-Region traversal instrumentation would be disproportionate; do not treat `proof.owners.len()` as a bound on the entire existing `visited` set. The `visited` difference should be charged against `self.visited.len()` (or computed in an explicit polling loop).

3. **Transactional Stop rollback is present for the expanded body path.** `continue_nested_loop_side_exit` snapshots `visited`, `unclosed_tail_at`, `catch_joins`, and `fragmented` before recursive consumption, restores all four on refusal or Stop (5304–5307, 5394–5415), and appends to `run` only after success. Nested monitor walking restores `own_monitor` on both refusal and Stop in `monitor_body_walk`/`monitor` handling (around 6921–6966), so I found no new uncovered `own_monitor` mutation on this path.

   The production body expansion is in `effectful_dual_exit_loop`, not `header_tested_loop`: the former snapshots the same four state fields when `side_exit` exists, then restores them if body walking, the post-body charge, or `implicit_tail_latch_origin` stops (12828–12846, 12859–12873, 12906–12920). This correctly handles the new owners. The ordinary `header_tested_loop` path has no side-exit expansion in the current source excerpt; its existing non-transactional behavior is outside this change.

4. **Temporary snapshots themselves are uncharged work.** Both transactions clone potentially growing sets (`visited`, `catch_joins`, plus `fragmented`) before entering a speculative walk. The rollback logic is correct, but the copy cost is not covered by the new proof charges. If the budget is intended to cap CPU work rather than only traversal, bill the snapshot size before cloning; this is secondary to findings 1–2 and should use the project’s existing convention for speculative-state snapshots rather than introducing a new budget dimension.

## Recommendation

I would not accept the new side-exit analysis-step accounting as accurately covering its work until findings 1 and 2 are addressed. No architectural redesign is needed: add local charged/polled loops at the existing scan sites. Keep the current rollback structure. I prepared no production patch because the exact safe charging granularity depends on whether the implementation chooses explicit loops or conservative precharges; root can choose the smallest local form before the next build.
