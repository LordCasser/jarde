# CF11 local side-exit budget candidate

This is a private candidate only. No shared source was edited, and no Rust/JDK/JADX/CLI/Git command was run. Base is the current `crates/jarde-java/src/region.rs` bytes pinned in `pins.json` (SHA-256 `1852b39f34153772700cc3854a336ca087c05f07389f44f0ec172d29c508ede3`).

The proof-side child is `NormalFlow::NaturalLoop`; the candidate keeps its `BTreeSet<usize>` unchanged. Before cloning, it charges four units per child node for the clone plus three child-set predicates (overlap, nested-header, and path/scope), with polls around that grouped scan. It separately charges the two-way child-header partition, the `loop_exit_nodes` pass by child nodes plus canonical edges, prefix conversions/path checks, owner-set construction and checks, child adjacency/internal-edge construction, and owner-ID conversion. The final canonical-row closure retains its existing full edge-count charge and per-row poll.

The consumer-side `child_loop` is a `Region::Loop`. Only those Region traversals use the conservative upper bound `(canonical nodes + canonical edges) × MAX_REGION_DEPTH`: it covers `blocks()` aggregation, structural wrappers/transfer leaves, `is_structured()`, gateway window checks, and exact owner comparison. The `visited` difference is charged against the full current `visited.len()`, with a poll before and after. Each validation segment is charged before its scan; refusal predicates are evaluated before the post-scan poll so cancellation is not hidden by an early `Ok(None)`.

`effectful_dual_exit_loop` now precharges the side-owner projection before widening the local frame/body sets. After the body walk, it precharges expected-owner construction/coverage before mutating `visited`, and precharges `exact_side_owners` against the same canonical-node/edge/depth bound. A Stop from either post-body charge or the final scan poll restores `visited`, `unclosed_tail_at`, `catch_joins`, and `fragmented`, matching the existing body-walk rollback. No `own_monitor` behavior changes; nested monitor code already restores its own state on Stop.

Snapshot clone cost remains a separate accounting debt; it is intentionally not added here, consistent with existing snapshot conventions. This candidate is not compiled or runtime-verified. Root should review the conservative multipliers against the current analysis-step limits before applying it.
