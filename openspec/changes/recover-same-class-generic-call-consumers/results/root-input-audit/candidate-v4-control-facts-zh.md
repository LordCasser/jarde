# 固定 CLI4 控制事实（GC-04/05/08）

本页对应 CLI4 的固定 140+4 完整重放，只列事实与可支持的拒绝边界，不替 root 作最终裁定。四腿指 Corretto 8 / OpenJDK 23 × debug / nodebug。逐腿输入/输出哈希、candidate 完整源码、物理 `@method` origin、只读输入 `javap` 摘录、原/候选 Probe 反射与行为均见 [candidate-v4-control-facts.json](candidate-v4-control-facts.json)，SHA-256 `976133b57d131de9d187cc9c1dd2cd70d081beaa87855613e4de0d6ac4518a36`。七项仍按固定 replay 脚本的 `CONTROL_REVIEW_ONLY` 留给 root。所有七项四腿保存的编译和 Probe 均通过，但这不证明调用点拒绝/排除正确。

- **UnknownIncoming（GC-03/08）**：四腿原源码共同包含 `identity(T)`、`safe(T x) { return identity(x); }`、独立 `untouched(T)`、以及 `unsafe(Object x) { return identity((T)x); }`。safe / unsafe 的 receiver 都是隐式 `this`；候选源码写成 `this.identity(x)`（debug）或 `this.identity(arg1)`（nodebug）。input javap 在两个不同物理方法中各记录一个 `invokevirtual identity(Object):Object`；unsafe 的入参来自源码 unchecked `(T)x`。CLI4 将 identity/safe/unsafe 都发成 Object 并附拒绝标记，保留 `untouched(T)`。Probe 行为 `safe+unchecked+independent` 通过，完整反射不匹配。边界在于 safe 的 `T` 入边不能替另一条 unchecked/Object 入边提供充分类型证明；须验证关联回退覆盖完整入边，同时不影响独立 leaf。标记和行为本身不足以证明这条闭包已核实。代表源码：[UnknownIncoming.java:13](../candidate/candidate-v4/gc01-08-140/openjdk23/debug/UnknownIncoming/jarde/UnknownIncoming.java:13)。

- **CycleRelay（GC-08）**：四腿原源码 `left(T,boolean)` 条件分支调用 `right(x,false)`，`right(T,boolean)` 对称调用 `left(x,false)`，否则返回 `x`；receiver 均为隐式 `this`。候选两条语句显式变为 `this.right(x/arg1,false)` 与 `this.left(x/arg1,false)`；最终头为 Object 并带拒绝标记。input javap 保留两条互相指向的 `invokevirtual`，descriptor 均为 `(Object,boolean)Object`。有限路径 Probe 通过、反射不同。边界是推断环不能以相互待证的类型结论自证；有限运行通过不证明候选已拒绝循环类型推断。代表源码：[CycleRelay.java:13](../candidate/candidate-v4/gc01-08-140/openjdk23/debug/CycleRelay/jarde/CycleRelay.java:13)。

- **MethodHandleUse（GC-08）**：四腿原源码在 `relay(T x)` 中保存 `Function<T,T> f=this::identity` 并返回 `f.apply(x)`。方法引用的接收对象是 `this`，apply 的接收对象是局部 `f`；候选仍为 `this::identity` 与 `f.apply`（nodebug 局部名 `local2`），identity/relay 发成 Object 并带拒绝标记。物理输入是 `invokedynamic`、LambdaMetafactory bootstrap，其中 MethodHandle 常量指向 `identity(Object):Object`；relay 中实际调用是 `invokeinterface Function.apply`，没有直接 invoke identity。边界是 bootstrap 方法句柄不能作为本片 direct-invoke caller→callee 证据。行为通过、反射不同仍不能证明 collector 排除了 bootstrap。代表源码：[MethodHandleUse.java:13](../candidate/candidate-v4/gc01-08-140/openjdk23/debug/MethodHandleUse/jarde/MethodHandleUse.java:13)。

- **RawOwnReceiver（GC-05）**：四腿原源码先声明 `RawOwnReceiver raw=this`，再返回 `(T)raw.identity(x)`；调用 receiver 的源码静态类型为 raw 局部 `raw`。候选发射源码则将接收对象表现为 `this.identity(x/arg1)`，identity/relay 两头为 Object 并带拒绝标记；这是候选输出对源 receiver 的实际变化，不能把原 receiver 反向解释为 `this`。输入物理调用为 `invokevirtual identity(Object):Object`。边界理由是 raw receiver 的成员选择不能借用 class `T`；还要确认源码/AST 中 raw receiver 的类型事实参与了拒绝判定。行为通过、反射不同，marker 本身不是 callsite 证明。代表源码：[RawOwnReceiver.java:21](../candidate/candidate-v4/gc01-08-140/openjdk23/debug/RawOwnReceiver/jarde/RawOwnReceiver.java:21)。

- **ReboundOwnReceiver（GC-05）**：四腿原源码把变量声明为 `ReboundOwnReceiver<T> receiver=this`，随后赋值 `Object alias=receiver`，再把 `(ReboundOwnReceiver)alias` 赋给 `receiver`，最后 `(T)receiver.identity(x)`。raw cast 赋值是 unchecked assignment；它不会改变原变量声明静态类型 `ReboundOwnReceiver<T>`，因此不能说原源码最后调用必然按 raw receiver 选择。物理 input 在 BCI 5 有 `checkcast ReboundOwnReceiver`，BCI 11 有 `invokevirtual identity(Object):Object`；classfile 本身不保存此局部的泛型静态类型。CLI4 候选完整源码则实际声明 raw 局部 `ReboundOwnReceiver receiver`（nodebug 为 `ReboundOwnReceiver local2`），保留 Object alias 和 raw cast 赋值后从该 raw 局部调用。identity/relay 是 Object 并带拒绝标记。边界理由是 Object alias/raw cast/重绑定路径没有证明 `T` 可传到调用点，且 candidate 实际 raw 局部声明；不能把候选局部类型倒推成原源码类型。root 可以评估保守拒绝是否得到证明，marker 本身不充分。代表源码：[ReboundOwnReceiver.java:21](../candidate/candidate-v4/gc01-08-140/openjdk23/debug/ReboundOwnReceiver/jarde/ReboundOwnReceiver.java:21)，四腿完整 candidate 源文在 JSON `source_correlation.candidate_compilable_source.text`。

- **InheritedUnknown（GC-08）**：四腿原源码为 `InheritedUnknown<T> extends ArrayList<T>`，`relay(int index) { return get(index); }`，原 receiver 隐式为 `this`，候选输出为 `this.get(index/arg1)`，返回头 Object。input javap 的 BCI 2 是 `invokevirtual get(I):Object`，常量池符号 owner 为 `InheritedUnknown.get`，但该类没有物理 get 声明，父类是 `ArrayList<T>`；候选另带参数化父类签名拒绝标记。行为通过、反射不同。边界理由是符号 owner 是当前类不能证明目标方法属于本类声明集合；父类成员代换超出本片闭包。代表源码：[InheritedUnknown.java:4](../candidate/candidate-v4/gc01-08-140/openjdk23/debug/InheritedUnknown/jarde/InheritedUnknown.java:4)。

- **VarargsCall（GC-08）**：四腿源码声明 `@SafeVarargs final <U> U first(U... xs)`，relay 明确调用 `this.<T>first(x)`，receiver 为 `this`。input javap 记录 `first` 的 `ACC_VARARGS`、物理 descriptor `([Ljava/lang/Object;)Ljava/lang/Object;` 和 BCI 9 的 `invokevirtual first(Object[]):Object`。候选源码保留 `this.first(x/arg1)` 调用形状，但省去 `<T>`，方法与 relay 的最终头均为 Object 并标拒绝。行为通过、反射不同。边界理由是 varargs 调用适用规则及数组 descriptor 需要与直接固定参数推断区分；反射加行为不足以证明该调用未被 direct-invoke 推断误收。代表源码：[VarargsCall.java:13](../candidate/candidate-v4/gc01-08-140/openjdk23/debug/VarargsCall/jarde/VarargsCall.java:13)。
