## ADDED Requirements

### Requirement: 空具名 catch 的三份调用清理恢复为唯一 finally

系统 SHALL 在 Java 8 方法的两条已验证异常行分别指向一个空具名 catch 和一个 catch-all、正常路径/具名 catch 路径/异常路径各有一份相同调用型清理、所有入口出口及原异常重抛均被证明时，输出可重编的一个 `try/catch/finally`。输出 SHALL 保持三条路径各自恰好一次清理、具名异常的吞掉行为、非具名异常的原值重抛、清理自身异常的覆盖优先级及所有物理来源。证明不足时 MUST 保守拒绝折叠。

#### Scenario: 正常完成与具名异常
- **WHEN** 受保护正文正常完成，或抛出被空 `catch (Exception e)` 捕获的异常
- **THEN** 清理各执行一次，正常路径正常返回，具名异常被捕获后正常返回，源码只含一个 `finally`

#### Scenario: 非具名异常与清理异常
- **WHEN** 正文抛出不被具名 catch 捕获的异常，或任一路径的清理调用抛出新异常
- **THEN** 清理正常完成时原异常对象被重抛；清理抛错时新异常覆盖先前异常，且清理不被该方法的空 catch 再捕获或重复执行

#### Scenario: 三份副本或异常边界不一致
- **WHEN** 任一清理副本的调用目标、参数、接收者、副作用顺序或返回形态不同，异常行范围/顺序/目标改变，清理进入自身保护区，或存在外部入口及额外出口
- **THEN** 系统 MUST 拒绝生成唯一 `finally`，保留定位到字节码及异常行的拒绝证据

#### Scenario: 停止与原子输出
- **WHEN** 证明、区域构造或源码输出期间取消或耗尽适用预算
- **THEN** 系统 MUST 返回停止状态，不得发布半个 `try/catch/finally`、丢失清理效果或伪造来源
