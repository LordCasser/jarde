## Context

见 [proposal.md](proposal.md)。冻结的 [匿名捕获虚分派证据](../../evidence/java-syntax-2026-09-25/anonymous-super-dispatch/evidence.md)给出精确形状：`Base.<init>` 的 BCI 12/15 和 23/26 两次条件分支经 BCI 29/33 的 1/0 汇合，在 BCI 34 唯一由 `putstatic` 消费。当前输出把两个判断写成嵌套 `if`，在 BCI 34 留引用，却允许后续 `inBaseConstructor=false` 与 `return` 出现在一个分支中；生成的 `Base.java` 可以编译，运行时静态结果保持默认 `false`。

现有 `recover-conditional-values` 已用 `Region::If`、SSA Phi、`ExprKind::Conditional` 和字段写入处的布尔收窄恢复普通双臂值。实际 Region 树却把 BCI 34 同时走入内臂和外层续接：内层 `If@26` 的 true arm 成为 `[29,34]`，外层 `If@15` 的 join 是共享 false 块 33，第二次到达 34 被错标为 `Loop` fallback。现有 `Region::If` 要求两臂各自拥有不相交的块，不能表达两个 false 边共用 33、两个生产者汇入 34 的所有权；仅放宽 Phi 证明无法修复这一点。

## Goals / Non-Goals

**Goals:** 对一个静态字段写入消费的局部、无异常边短路布尔菱形，证明所有路径只到达一个汇合和一个消费点，写出与原 JVM 相同的求值及字段赋值；证明失败时保留完整来源缺口。

**Non-Goals:** 不修匿名类构造器/捕获投影，不推断源代码一定写过 `&&`，不对实例字段接收者、循环、switch、真实异常边或任意多前驱 Phi 发射短路字段赋值；真实异常边的完整引用仍在本 change 的拒绝合同内。不把非 0/1 JVM 值直接当 Java 布尔字面量。

## Decisions

1. **先修正这个图形的 Region 所有权。** 在递归构造普通 `If` 之前，以 CFG 边确认外层假边和内层假边汇入同一 false 生产者，内层真边抵达 true 生产者，两个生产者再汇入同一个消费块。为这一种不相交双臂无法表示的形状引入一个限定的 `Region::ShortCircuitValue`；它一次认领两次测试及两个生产者，消费块只归它一次。不得把共享 false 块复制到两个 `If` arm，也不得把第二次访问消费块叫作循环。这个局部表示有必要；不增加通用 CFG 重写器或第二套方法恢复。新节点先接入 builder 的穷尽匹配，默认**整体引用**两次测试、生产者、字段写入及消费块后缀；不能用只返回原始块起点的 `covered_bcis` 冒充逐指令来源，须列出参与块的 SSA 指令 BCI。在第二步 SSA 证明和第三步发射完成以前，不会因只是换了 Region 形状而虚报完整 Java。证明完成后，消费块后续指令才按原顺序发射。识别失败时原有 Region 逻辑也不得隐匿字段写入的来源。**拒绝边界的所有权也要先于值证明**：受控 IR 补丁把外层分支改指向 true 生产者后，普通嵌套 `If` 会留下两处 `@bytecode 34`，而不覆盖产生值的全部 BCI；此直接字节补丁未补 StackMap frame，不能作为可验证 JVM 语义样本。由 `javac --release 8` 生成且 JVM 验证通过的 `a || rhs()` 提供同类共享 true 控制骨架。对于两层分支、两生产者汇合、消费块含静态字段写入的近邻控制骨架，即使共享的是 true 生产者、生产者不是 1/0、或消费块先 `dup` 再写字段，也须先一次认领该局部；精确 1/0、唯一 Phi 消费和字段身份只属于下一步证明。近邻骨架不满足发射证明时整体引用并标记不完整，不可退给会重复进入消费块的普通 `If` 路径。
2. **再证明值与唯一消费。** 在 builder 中核对该 Region 的全部正常 CFG 边、无额外入口/异常边、栈深相同的 Phi、BCI 29/33 的精确输入、BCI 34 的唯一 Phi 消费者和 `putstatic` 字段身份，并拒绝不可嵌入表达式的前置效果。证明不依赖 BCI 邻近或字段名猜测。扫描按 `O(E + I + Phi)` 保守预收费，沿用现有深度/预算；任何拒绝都不发布部分折叠计划。
3. **用已有表达式保持短路并原子发射。** 允许把证明后的图写为嵌套 `?:`，例如 `a ? (b ? 1 : 0) : 0`，再在已证 `Z` 字段消费处使用当前的整数到布尔收窄。源码无需逐字匹配原 `a && b`；关键是 `b` 只在 `a` 为真时求值，且结果仅在原 `putstatic` 位置写一次。条件表达式及字段赋值的来源包含两次分支、两个生产者及写入 BCI；不提前求值 `equals`，不把字段赋值搬进单一分支。若构造表达式失败，整体 Region（包括原字段写入）退回可见缺口，不能留下缺写入的可编译正文。
4. **以原 class 行为验收。** `anonymous-super-dispatch` 同时含匿名类构造缺口；本 change 仅重编 Jarde 的 `Base.java`，运行时其余类取自冻结原 jar，检查 `observed` 和 `visibleDuringSuper`。再以简单短路静态字段样本与不规则 Phi 补丁独立检验准入/拒绝。JADX 结果仅作对照，不能替代原 class 的求值与异常顺序。
5. **异常保护区内先保全拒绝证据。** 冻结的 `ExceptionShortCircuit.assign(Z)Z` 在 `[0,18)` 有真实 `RuntimeException` 边；当前普通嵌套 `If` 先于局部短路候选取得所有权，遗漏 BCI 10/11。仅在同一个已识别 `try` 保护 frame 内，且参与块未越过该 frame 的边界、作用域或另一处理区时，一次认领有限候选；存在可达异常边就以 `jre_region_exception_edge` 引用整组测试、生产者和 `putstatic`，仍由既有 catch Region 持有处理器。builder 的无异常边证明继续拒绝 Java 字段赋值，不把该样本误算作已恢复。该规则只修正证据所有权，不扩展异常路径的表达式发射。

## Risks / Trade-offs

- [误认其他边进入汇合] → 必须核对 CFG 前驱集合与 Phi 输入一一对应，缺一则拒绝。
- [在字段写入前重复执行条件右侧] → 表达式子节点只在被选路径执行，并检查每个有副作用生产者唯一归属。
- [把可验证的非 0/1 `Z` 存储变成 Java 布尔] → 沿用已有目标消费处的最低位证明；不能证明时保留原始缺口。
- [受控样本的匿名构造缺口掩盖本项结果] → 仅替换 `Base.class` 运行，匿名类及调用者保持冻结原件；匿名投影归 2.10/5.3。
