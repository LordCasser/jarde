## ADDED Requirements

### Requirement: 同步区域后已证明的局部槽位复用

当 Java 8 class 的一个局部槽位先保存已恢复同步区域的监视器或清理临时引用，随后保存循环整数，且完整控制流与值来源证明两个生命周期不重叠时，源码恢复 SHALL 把它们当作不同局部变量。后续整数声明、读写及返回 SHALL 可编译且与原 class 的值和异常行为一致。证据不足时 MUST 保留可定位的保守拒绝，不得把引用与整数伪装成同一 Java 变量。

#### Scenario: 同步区域后循环复用监视器槽位

- **WHEN** Java 8 `-g:none` class 在 `synchronized` 中赋值一个随后用于循环上界的局部值，监视器及清理临时引用的槽位在同步区域结束后被复用为循环整数，且所有正常和异常路径均证明此前引用已结束
- **THEN** 完整类源码 SHALL 通过 `javac --release 8` 重编及 `java -Xverify:all`，循环零次和多次时的输出与原 class 一致；同步区域的监视器清理仍只执行原有次数

#### Scenario: 引用可能跨边界存活

- **WHEN** 同槽位的先前引用仍可能被后续路径读取、加载值仍留在操作数栈、异常处理器可从后续生命周期进入，或控制流可回到先前访问
- **THEN** 恢复 MUST NOT 将该槽位分割为两个可发布的 Java 局部；拒绝范围、相关 BCI 与物理来源 SHALL 可定位

#### Scenario: 预算或取消中断证明

- **WHEN** 生命周期和区域证明在预算耗尽或取消时停止
- **THEN** 恢复 MUST 保留既有停止状态与物理来源，MUST NOT 发布只完成一侧声明的源码
