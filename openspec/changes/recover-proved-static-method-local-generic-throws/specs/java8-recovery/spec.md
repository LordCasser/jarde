## ADDED Requirements

### Requirement: 已证静态直接返回方法保留局部泛型异常

对于 Java 8 类中已完整证明为静态参数直接返回的泛型方法，若异常后缀引用其方法自身声明、可完整拼写并与物理异常逐位置擦除一致的类型变量，系统 SHALL 在完整类源码中同时保留方法类型参数、参数/返回类型变量及 `throws` 类型变量。若上述任一来源、正文类型关系或 Java 源调用绑定未被证明，系统 MUST 局部保留物理成员及可核对的拒绝理由，不得只发布部分泛型方法头。预算耗尽或取消 MUST 继续按操作停止契约处理。

#### Scenario: 直接返回与局部异常变量
- **WHEN** 顶层非泛型 Object 直接子类的 `public static <T, X extends Exception> T echo(T value) throws X { return value; }` 有完整的签名、擦除、正文与调用绑定证明
- **THEN** 完整类源码同时包含 `T` 参数/返回和 `throws X`，重编后的反射仍显示两个方法类型参数、返回 `T`、异常 `X`，显式指定 `String, RuntimeException` 的调用方能在 Java 8 下编译并运行

#### Scenario: 无调试表
- **WHEN** 上述方法分别以 `-g` 和 `-g:none` 编译
- **THEN** 两份完整类源码都保留方法局部泛型异常和等价反射/调用语义，不依赖参数名调试表

#### Scenario: 返回变量也用于异常
- **WHEN** 已证方法为 `<T extends Exception> T echo(T value) throws T { return value; }`，同一个局部类型变量同时占据参数、返回及异常位置
- **THEN** 系统 SHALL 完整保留这三个 `T` 位置及其方法类型参数，重编后的泛型反射与 Java 8 显式类型调用仍与原类一致

#### Scenario: 签名异常证据不足
- **WHEN** 方法异常变量未绑定、异常类型界无法证明为可用异常、签名异常擦除与物理 `Exceptions` 不同，或异常后缀超出已支持的源级形状
- **THEN** 系统 MUST 保留该方法物理声明并给出局部拒绝，不得输出错误的 `throws X` 或一半泛型头

#### Scenario: 正文或绑定证据不足
- **WHEN** 返回值不是已证参数直接来源，正文有未覆盖的副作用，或类层级/本类调用令源级绑定无法证明
- **THEN** 系统 MUST 局部回退物理声明并说明拒绝；本项不宣称整个回退类在存在泛型调用时一定可重编

#### Scenario: 原子停止
- **WHEN** 完整方法头在预算或取消前无法构造并交付
- **THEN** 操作 MUST 返回对应停止状态，已交付文本不得出现部分类型参数、参数/返回或异常变量投影
