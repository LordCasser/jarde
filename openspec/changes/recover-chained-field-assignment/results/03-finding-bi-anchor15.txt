## 4. The guard analysis (parent's condition 3)

The value-level soundness guard (`ff3cf21b`, `crates/jarde-java/src/build.rs`) fires when a
**value-level refusal is one of the body's own top-level statements** and the surviving text would
compile:

```rust
let refused_value = builder.stmts.iter().position(|stmt| {
    matches!(&stmt.kind, StmtKind::Fallback { reason, .. } if value_level_refusal(reason))
});
if !class_initializer && !builder.stmts.is_empty() && refused_value.is_some()
    && (builder.return_type.is_none() || !completes_normally(&builder.stmts))
```

Two facts decide this shape, and both were measured:

* **the refusal is not one of the body's own statements**: it is quoted *inside* the surviving `for`
  loop, and the guard's own documentation excludes that position — “a refusal quoted *inside* a
  surviving loop, `if` or `try` is the enclosing structure's own partition, which still presents with
  the gap marked where the refused statement was; neither is this guard's business, so the refusal is
  read off the statements of this body itself”. `refused_value` is `None` for `earlyRet`;
* **it is not a boolean-method coverage gap**: the guard's return clause is
  `(return_type.is_none() || !completes_normally(stmts))`, and this body ends in `return true;`, so it
  does **not** complete normally — the clause holds. The same fixture proves it: on the baseline,
  `andUse` (a *top-level* value-level refusal in a `boolean` method) renders `jarde_refused_body();`,
  i.e. the guard fired there. The clause is not what fails for `earlyRet`; its position is.

**Answer: outside the guard's pinned scope by design** (the nested position), not a hole the guard
should have caught. The guard is left untouched, as the ruling requires — a guard whose scope covers
refusals nested inside surviving structures is the guard owner's decision, not this change's.

## 5. Classification, per the ruling

`BI` is **not** a clean recovery. It is recorded as *“recovery of three members + a newly reachable
pre-existing critical anchor 15 face”*: this change makes the class's stripped text compile for the
first time, which turns a compilable-wrong face that was previously hidden behind a class-level
compile failure into a reachable one. The face itself, its method's text and its cause are unchanged
by this change (byte-identical), and the follow-up (guard-scope extension or the conditional-RHS
compound assignment) is the soundness slice's own work — `compilable-wrong` first, ahead of every
recoverability item.
