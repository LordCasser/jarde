# 1.2 家族负例与拒绝边界

本阶段复用冻结阶段一 Java 8 家族及现有请求集成/proof-unit，不新增生产代码或另造重复夹具。表中“物理来源保留”指拒绝时仍能检查原 root/child 的身份、成员和物理文本；proof-unit 不声称变体能通过 JVM verifier。

| 边界 | 夹具/测试及证据等级 | 期望拒绝位置 | 拒绝后保留 | 验证命令 / 局限 |
| --- | --- | --- | --- | --- |
| 双向 `InnerClasses` 不一致 | `member_inner::tests::family_relation_needs_matching_typed_rows_and_uses_member_flags`：对 child self-row 分别移除、改可见性；typed-fact proof-unit，非 verifier-valid 声明 | 家族关系阶段；child 的 self-row 缺失或 flags 不匹配时 `child_relation_agrees` 为 false | root/child 原物理报告由 `disagreeing_child_relation_cannot_authorize_package_private_call` 集成测试检查；已有 verifier-valid `wrong-relation.jar` 仅改 child self-row 的 outer 索引 | `cargo test --locked -p jarde --all-features --lib member_inner::tests::family_relation_needs_matching_typed_rows_and_uses_member_flags`；`cargo test --locked -p jarde --all-features --test member_family_identity disagreeing_child_relation_cannot_authorize_package_private_call`。JAR 只验证单向 outer 冲突；另一方向用 typed-fact proof-unit，不声称字节码变体可验证。 |
| 同名多物理定义 | `missing_or_duplicate_selected_child_refuses_family_without_losing_root`：同一 ZIP 中重复 child 路径，走真实 snapshot/environment 解析请求；不是 JVM classpath 运行夹具 | child 的唯一物理定义解析阶段，结果为 `Refused { child: None }` | root 方法、报告和 root 文本 | `cargo test --locked -p jarde --all-features --test member_family_identity missing_or_duplicate_selected_child_refuses_family_without_losing_root`。重复 ZIP 路径的运行时选取语义依 JVM/ZIP 实现而异，因此这里只主张 Jarde 物理解析拒绝，不主张 verifier-valid。 |
| 非捕获同类型 receiver | 冻结阶段一真实 javac class；`family_capture_distinguishes_other_and_refuses_unclosed_shapes` 证明 `other.state` 的 receiver 不来自 child `this`，且不进入捕获读证书；捕获字段读取仍获证 | 不把显式 `other` 归类为捕获 receiver；错误归类在 `scan_capture_method_uses` 的 receiver 来源检查拒绝 | `other.state` 的物理 Fieldref/BCI；捕获读的独立物理身份 | `cargo test --locked -p jarde --all-features --lib member_inner::tests::family_capture_distinguishes_other_and_refuses_unclosed_shapes`。正例 class 可由阶段一 `java -Xverify:all` 证据复核；测试中的 Fieldref 替换为 proof-unit，不声称该修改后的变体 verifier-valid。 |
| 额外字段读取/写入 | 同上 proof-unit：真实 SSA 下将显式 receiver 读取改指捕获字段、将捕获读取指令变为额外 `putfield` | 捕获闭包扫描的 receiver/唯一写入检查；拒绝捕获投影 | 原字段表、原方法与捕获字段物理来源；无字段被隐藏 | 同上测试命令。两个受控 Code 变体均为 proof-unit，不是 JVM verifier 结论。 |
| 异常边界 | 同上 proof-unit：给真实捕获构造器 prologue 增加覆盖写入区的异常处理器 | `capture_constructor_shape` 的构造器模板/处理器检查，捕获证书拒绝 | child 构造器的原 descriptor、Code、方法报告和 root 报告 | 同上测试命令。变更仅针对已解码 Code 事实，不声称 classfile verifier-valid；本阶段仅覆盖构造 prologue 异常范围。 |
| 预算 / 取消 | `family_row_scan_observes_real_budget_and_cancellation` 对真实 typed rows 使用 `analysis_steps=0` 和预取消 token；`child_body_stop_keeps_root_and_child_physical_coverage`、`capture_analysis_stop_keeps_completed_physical_child`、`call_proof_budget_stop_keeps_capture_and_both_physical_reports` 覆盖请求阶段预算停止 | 预算/取消在家族 row scan 处传播为请求停止；之后各集成止点分别拒绝捕获或调用证明 | 已完成的 root/child 物理表、方法、文本、coverage/execution；不宣称完整 family | `cargo test --locked -p jarde --all-features --lib member_inner::tests::family_row_scan_observes_real_budget_and_cancellation`；`cargo test --locked -p jarde --all-features --test member_family_identity`。取消单测位于真实 scanner 单元边界，集成取消下的部分 root/child 报告不在此处声称已覆盖。 |

这些样本证明的是各阶段拒绝边界，不等同于完整源码投影验收。可 verifier-valid 的冻结变体仅有既存 `wrong-relation.jar`、`null-check-removed.jar` 与正例阶段一 JAR；双向 row facts、字段闭包和异常范围的受控变体属于 proof-unit。重复物理条目按 Jarde 输入模型测试，不作为 Java classpath 行为主张。所有拒绝均以原物理身份/来源为准，不能据此推断输出已经是可编译家族。
