## Goals / Non-Goals

**Goals:** 为理论上有必要调查的优化建立完整方案，明确哪些工作能删除、哪些能摊销、哪些只是提前或并行执行；用固定工作负载和证据选择实施项，并能逐项撤销策略、解释退化与停止投资。

**Non-Goals:** 不要求八组方案全部上线；不以缓存命中率代替用户体验；不改变 JVM/恢复正确性、不扩大默认预算，不建立通用任务调度平台、统一 allocator 或全程序模型。本规划不直接修改生产代码或主 specs，不预设某个 cache/线程池/数据库库选型。

## Decisions

### 1. 理论与决策顺序

每项先回答：同一结果所必需的最小读取/计算是什么；当前多做了什么；能否先在操作内复用；保留到下一请求的实际价值是什么。顺序为删除无关工作 → 消除操作内重复 → 摊销跨请求工作 → 在明确延迟目标下预取/并行；这是依赖与复杂度顺序，不是未经测量的收益排名。

对同一固定工作负载，用互斥阶段占比 `p`、局部加速 `s`、新增管理开销相对原总时长 `h` 估计 `S = 1 / ((1-p) + p/s + h)`。`s` 与 `h` 的测量边界不得重复计入管理开销，无法拆分时使用端到端实测，不强行填写预测。`1/(1-p)` 仅是忽略额外开销、完全消除该部分的乐观上界。`s/h` 未测时写“未知”；工作计数不能当 `p`，也不能把缺失数据填零。多个优化的阶段若重叠，不相加占比、不相乘独立加速比，使用消融和组合实测。

cache 的首要收益假设是命中避免的计算大于查找、key、复制、同步和保留管理成本，内存另设约束。预热被用到的概率为 `q`、构造成本为 `C` 时，无条件预热比按需构造多做的期望工作是 `(1-q)C`；其价值应体现在已声明的关键路径延迟，不能把提前支付当成计算消失。并行除可并行份额外，还受资源竞争、确定性归并和在途内存限制。

### 2. 基线、工作负载与测量边界

| ID | 工作负载 | 必须分开的指标 |
| --- | --- | --- |
| W1 | 新进程/新 snapshot 的冷单方法；另有库内新 snapshot 对照 | 启动、open/hash、目标发现、recover、编码/输出、端到端 |
| W2 | 同 snapshot、不同 class 的连续方法导航；同方法重复只作控制组 | 一次准备、每请求延迟、序列总时间、container/class 层命中 |
| W3 | 同 class 的多个方法；再扩到多个 class 的固定方法集合 | class/方法定位和解析次数、每方法结果、总量、峰值工作集 |
| W4 | 单 consumer/多 consumer XRef、小页/大页/完整续页 | 首次结果、每页及全序列时长、重扫范围、临时结果/未扫描范围 |
| W5 | 大于缓存容量的单次 sweep 与往返热点访问 | 总 CPU/墙钟、容量拒绝/淘汰/重建、驻留和峰值 RSS |
| W6a | 已明确需求的全量导出，W3/W5 × 1/2/4/6 worker | 冷进程至输出关闭的总量、首次结果、CPU/RSS、有序背压和取消 |
| W6b | 独立宿主请求并发、相同/不同目标及 single-flight 候选 | 吞吐、单请求尾延迟、在途内存、排队/取消隔离、共享工作 |

W1–W5 使用可再生成 fixture 和已有 API。W6a 已由调用方明确，见 [add-parallel-bulk-recovery](../add-parallel-bulk-recovery/design.md)；先实现可独立验证的串行批量，再以相同产出验证多 worker，不再等待其它宿主需求。W6b 仍需实际需求与重复构造证据，缺失可单独暂缓，不能据此暂缓 W6a。预热调查以 W2/W4 的固定导航序列补充命中和放弃序列。flat/nested、STORED/DEFLATED、重复名、损坏、深度、容量退化均有最小受控输入；大语料作为附加证据，不成为 CI 的 `/tmp` 依赖。

固定 baseline/candidate revision、dirty patch 摘要（正式验收使用固定构建）、输入摘要、release 编译选项、线程数、profile/roots、预算、输出单位和精确目标顺序。对照只改变目标因素；正确性修复若必须纳入，两侧先对齐行为。原始样本与统计脚本随证据保存。

使用开销可校准的 P5 计数/阶段计时，不搭建新观测服务。计时按互斥阶段或扣除子阶段，报告未归因余量；仪表化与非仪表化对照识别干扰。阶段时间在 harness sidecar，不进入领域报告。内存 cold 仅声明 engine 无派生事实；不宣称 OS page cache 也冷。准备、预热、填充、失败重试与最终输出都进入对应完整工作流的总账。

每个实验预先记录主指标、允许退化、内存上限、样本量和统计方法；至少 10 个独立重复，尾延迟结论需要另行设置足够样本，不能用 10 次的经验 p95 推广。交错执行基线/候选，重建所声明的初态，保存机器负载和全部有效样本。统计方法/阈值不得事后为结论调整；不能区分时写“收益未证实”，必要时在新声明的安静窗口完整重测。

### 3. 调查档案与准入门禁

每个方案的实施期调查档案包含：工作负载和用户目标；固定证据；当前调用/数据生命周期；必要工作与重复工作；`p/s/h` 或缺失项；备选方案；拟修改 capability；正确性/资源约束；实验和回退步骤；最终决定。档案放在本专项实施期的 `verification.md` 或其链接的仓库证据中，不要求现在创建空结果文件。

| 门禁 | 必须完成的判断 | 输出 |
| --- | --- | --- |
| G0 基线 | 指定工作负载、正确性基线和可复现计数/时间 | 可重复实验与未测项 |
| G1 必要性 | 无关/重复工作的证据，或能解决明确延迟/吞吐/内存目标的上界 | 准入、否决或有理由暂缓；不默认扩大范围 |
| G2 最小实验 | 单因素原型、直接路径对照、资源/语义/退化验证 | 实施方案与独立子 change，或撤销原型 |
| G3 交付 | 子 change 门禁、收益/代价证据、可执行回退演练 | 显式 opt-in 或符合预先标准的启用决策 |
| G4 重排 | 重测优化后剩余热点，复核相互重叠 | 下一方案优先级或停止 |

结构性访问范围修正可以由不必要工作证据准入，不需要先虚构大耗时占比；但发布加速结论仍需时间对照。缓存和调度实验默认关闭。若主指标收益不足以区分噪声、乐观上界不能满足目标，或资源代价超限，停止该策略；调查可以完成为否决/暂缓，但不能标成性能实现完成。

### 4. O1：容器定向访问与已验证 backing 复用

- **必要性/证据：** 一个指定 container 的查询不需要展开未搜索 sibling；重复请求不应在事实仍被保留时重建目录。历史条目/展开计数已支持此入口。
- **方案/现状：** 按 origin chain 定向访问、完整目录 raw-name 多值表、locator 和跨请求有界 backing 已交付。实现和行为规格由已归档的 [bound-container-lookup](../archive/2026-09-20-bound-container-lookup/proposal.md) 唯一负责（8/8，`b22ea04`）；本专项复用其验证，不重新实现。
- **调查/实验：** B 原始路径、D 定向直接路径、C/W 空/热 store、F 容量不足；隔离 CP/Header 命中；W1/W2/W5 增加无关 sibling、目标目录规模和深度。
- **约束/验收：** 未搜索 sibling 展开为零；保留期间目录和父 backing 不重建；重复 raw name 不合并；cold 完整目录和 CRC 检查保留；计数变化不冒充 wall-clock 改善。
- **回退：** D 经验收后成为新的直接路径基线；运行期只对可选 cache/backing 保留失败降级，关闭跨请求保留仍走 D，构造失败不发布完整 facts。D 本身的缺陷用提交回退处理，不在生产长期保留旧整树路径作为“加速失败 fallback”。

### 5. O2：操作内 class 读取、结构与方法定位复用

可信 prepared class 及其 bulk/class-source 消费由 `add-parallel-bulk-recovery` 已实现；普通入口的选择/driver/callee 交接与查询消费者的按需复用由 `add-demand-driven-core-results` 负责，父专项测量实际剩余重复与资源代价。

- **必要性/证据：** consumer、driver/callee 对同一可信 class 重复读/parse；单方法解码重复扫描方法表，全类调用存在 `K × M` 的定位检查。
- **方案：** 以 class_view 已共享的验证字节/成员列举为基线，调查尚未共享的结构和方法 locator、consumer 只读事实与 callee 同次类读取；方法 key 用 raw name/descriptor 并保留重复声明歧义。driver 类名/flags 已由 `carry-declaring-class-evidence` 交接，不重复立项。先用局部借用/共享对象，不把整个 MethodIr 改成长期全局缓存。
- **调查/实验：** W3/W4 分别启用 bytes 共享、结构共享、locator，记录 inflate/hash/parse/表项检查次数和峰值数据；覆盖多 consumer、accessor、多方法类及稀疏单方法。
- **约束/验收：** 相同 backing 的仍持有事实不重构；不同 snapshot/物理来源不混淆；Strict/Forensic 及原始结构的解析策略不互相代答。共享 code/bootstrap 解码时只保留必要 use-site 摘要，避免为省扫描而驻留全部方法 IR；保持 consumer 输出顺序与预算/诊断语义。
- **回退：** 单个局部复用步骤可撤销，回到直接解析；容量不足优先完成当前事实消费再释放，不能在取消/耗尽后重跑。共享事实的所有权和 class digest 只能来自已验证读取，禁止相信外部伪造摘要。

### 6. O3：按需查询、保守候选过滤与可停止续扫

- **必要性/证据：** `max_items` 目前不能限制当前 unit 的全部构造；provider 每页重建，boundary unit 重扫。单类别查询没有必要物化未请求的类别或恢复 IR。
- **方案：** 先复用目录与当前 unit facts，再调查有停止反馈的 item sink、可重放且绑定查询身份的细粒度续扫位置。消费者按需求解码；候选过滤仅在可证明无假阴性的关系上使用，CP 命中不能冒充 XRef/解析结果。
- **调查/实验：** W4 改变 page size、命中密度、单类体积、消费者集合，比较首屏、全序列与重扫条目；在页后缀放入损坏数据，观察提前停止带来的诊断/coverage 变化。
- **约束/验收：** 未扫描后缀如实保留为未覆盖/未决范围，`page.has_more` 不等于搜索完成，Unknown 与 execution 按各自成因独立报告；不能把页满自动记为预算耗尽/取消，也不能在存在未覆盖范围时把空 items 当作完整搜索无命中。完整扫描且确实无命中仍可返回完整空结果。稳定顺序、cursor identity、结果计费和重复/遗漏门禁必须成立。分页或诊断观察范围若改变，先在独立子 change 明确 delta，不能按“缓存透明”跳过产品决定。
- **回退：** 禁用候选过滤返回直接扫描；分页实现切换如影响 cursor schema，明确拒绝旧 cursor 并要求显式重启，不能静默跳项。已经发布的前缀不能自动重发；有界停止不能退化为无限扫描。

### 7. O4：按 class 组织的批处理与进程生命周期摊销

- **必要性：** 已知目标集合时，按 class 共享读取比逐方法独立重建上下文更接近必要工作量；内存 cache 无法跨独立 CLI 进程复用。
- **方案：** 全量导出需求已明确，由 `add-parallel-bulk-recovery` 定义同步库操作、内部有界物理遍历和薄 CLI JSONL；按 class 准备、按方法持续交付，消费完即释放局部工作集。不新增守护进程或独立多请求服务。调度分组与对外结果顺序分离，归并缓冲也有界。
- **调查/实验：** W2/W3/W5 比较原顺序、按 class 分组、长生命周期库调用和多进程 CLI；一次性 sweep 不用同方法热缓存结果代表收益。
- **约束/验收：** 一个 batch 有总额度，单方法结果和取消范围明确；不得通过逐方法新建预算突破总额度；失败方法不伪装整个 batch 成功。新操作只恢复显式物理范围内的声明，不把依赖加入目标，不把方法产物包宣称为完整类源码；普通按需入口不隐式扩大范围。
- **回退：** 回到串行直接调度但继续使用相同总预算；未发布的缓冲可丢弃，已发布结果不可自动重复。新增协议的停止/继续行为单独规格化。

### 8. O5：分层缓存、共享 payload 与准入策略

- **必要性：** 重复访问才产生摊销价值；低成本命中、按字节有界和防止一次性扫描污染是保留机制的前提。
- **方案：** 先操作内 facts，再 container/原始 CP/Header，随后仅按证据考虑 method decode、X1、resolution、IR/source 或持久结果。层次是候选，不是同时建八个 store；复用现有 FactsCache。调查可信摘要传递、共享不可变 payload、锁外昂贵工作、按字节/单项限制和大项 bypass。满则拒绝为初始策略；只有复用距离与热点淘汰证据支持时引入淘汰或第二次访问准入。
- **身份：** 物理目录绑定 snapshot/origin/验证 schema；CP/Header 绑定内容/parser/registry/policy；X1 加 consumer schema；resolution 加 symbol/source context、loader/view/platform/dependency snapshots；IR/source 还需方法、分析/恢复规则及命名/输出证据。origin 单独绑定，不能以 class name 作全局身份。
- **调查/实验：** W2/W5 的真实命中、避免的工作、lookup/hash/clone/锁成本、超容量行为和驻留量；分别报告每种产品，不能把组合命中全部归给容器。内容变化、依赖补齐、profile/schema 改变和失败构造均有负向实验。
- **约束/验收：** 首版只保留完整不可变 facts，重建本次报告；失败/取消不能成为永久 negative，环境相关的 Missing 不能只按名称缓存。工作量额度、cache 驻留与活动工作集分别记录；共享 backing 去重计权，外部仍持有引用时不宣称已释放 RSS。
- **回退：** 拒绝、失效或损坏时丢弃相应项，在剩余预算内直接计算；已取得的本次 facts 继续消费。持久缓存若准入，内容身份/版本校验、原子发布和可完全删除重建是前置，不能依赖它保证正确性。

### 9. O6：受控预热与预取

- **必要性：** 仅当后续访问有可验证预测性、且前台等待有明确目标，提前安排工作才有价值；本项不默认满足准入。
- **方案：** 宿主显式给 scope/products/预算，调用与前台相同的事实生产路径；明确批次中下一个 class 的有限预取优先于猜测整棵树。打开 container 可准备其目录，打开 class 可准备成员定位；默认不预分析全部 Body/IR。纯库不自行推断用户空闲，不引入后台全树任务。
- **调查/实验：** W2/W4 用相同导航轨迹比较 off/on，加入不打开结果、切换 artifact、取消等放弃路径；记录准备成本、前台延迟、总 CPU/字节、预测命中与未使用数据、资源竞争。
- **约束/验收：** 独立、可取消、有优先级和在途/驻留上限；预热范围不能扩大前台请求的 coverage；只发布完整验证 facts。局部请求不会因启用保留而隐式启动全局 Body 读取。
- **回退：** 关闭预热不影响前台正确性；资源压力先停低优先级未完成工作，释放不再使用的结果；不能把取消失败藏成前台 cache miss 后的无限重试。

### 10. O7：有界并行与相同计算合并

- **必要性：** W6a 的类间并行需求已经明确，先由串行批量消除同类重复，再测 1/N worker；实施归 `add-parallel-bulk-recovery`。W6b 的相同 key 同时构造需另有证据，不能将 single-flight 作为普通类间并行的前提。
- **方案：** 显式 worker 和在途字节上限，确定性归并；相同事实可采用 single-flight，生产 key 继承 O5 对该产品的完整身份及实际语义依赖，不以类名或显示名称判断相同。容器事实绑定 snapshot/完整物理 origin，环境相关产品再绑定 view/runtime profile、适用 consumer/query schema 等依赖；不要求纯内容事实附带无关环境。独立子 change 明确每个 key 的字段及生产者状态表；订阅者各自保留预算、coverage、结果过滤和取消状态，不能共享整份请求报告。优先宿主已有执行能力，是否需要私有 pool 由实测和依赖评估决定，不先引入 async runtime。
- **调查/实验：** 1/N worker、相同/不同目标、热点竞争、大项、超额排队、不同完成顺序、等待者取消、生产者失败；同时报告吞吐、尾延迟、CPU 与内存，不只报告最快线程数。
- **约束/验收：** 一个消费者取消不能取消仍有合法需求的共享工作；构造失败/取消不能永久污染 key。共享计算有独立有界生命周期或可安全转移/重试，最后一个需求撤销后停止无用工作。每个请求仍检查自身预算/结构限制；稳定输出顺序不足以证明紧预算前缀确定，须验证工作分配、已计费范围和停止边界。当前 specs 无法容纳的调度语义先另行明确，不能放宽 fingerprint 掩盖竞争。
- **回退：** 串行或禁用合并仍受同一请求总预算；处理 in-flight 等待者，防止挂起、重复发布或重新计费。并行速度提高但延迟/内存超出声明上限，不能作为默认策略交付。

上述订阅者/共享生产者规则仅针对 single-flight 候选。W6a 首版使用操作私有的 scoped workers、一个共享总预算、按类有序结果槽，不引入订阅系统。新 bulk 并行的足额语义确定性与中止子集边界已在子 change 显式定义；旧串行完整报告门禁保留，详见 §13。

### 11. O8：字节表示、摘要与输出成本

- **必要性：** 前述工作消除后，复制/hash/编码若占目标总时长或峰值内存的重要部分，才进行局部优化。
- **方案：** 调查读入/校验期间计算摘要、可信 digest 继续传递、STORED/standalone backing 区间共享、必要的容量预留、CP 字节共享以及 JSON 长度计数的固定点简化。mmap/文件 backing 仅在不可变快照与内存目标可同时满足时另案；全内容摘要仍需要读取对应内容。
- **调查/实验：** W1 的启动/open 单独测，不能拿它解释 W2 的 recover 合计；改变大输入、小输出和大输出，记录 hash 字节、复制/分配代理和最终字节一致性；测取消发生在 hash/编码阶段的响应。
- **约束/验收：** 不省略 CRC/size/metadata 检查，不以 lossy 字符串替代 raw bytes，不接受伪造摘要。snapshot 命名后内容不变；输出计数含必要分隔符，输出预算必须在提交前约束，不能发布半个成功 JSON。
- **流式边界：** 新 bulk JSONL 单独按完整记录确认交付，允许诚实的未完成前缀；残缺末行不计交付，无最终 Complete 记录或最终 flush/close 失败不得成功退出。此 delta 不放宽既有单文档命令。
- **回退：** owned immutable bytes 和直接编码作为安全路径；错误输出不可伪装成功，已经写出字节时不自动重发整个响应。不要为了减少几次复制引入 unsafe 自引用或无界全局 intern。

### 12. 组合、依赖和实现所有权

O1 已交付。`add-parallel-bulk-recovery` 继续拥有 O2 批量类准备、O4 bulk、O7 worker/总账/窗口，以及任务活动容器交接；`add-demand-driven-core-results` 拥有 O2 普通操作的可信事实交接、O3 增量结构查询与 O8 可选证据产品。下一轮顺序见 §15。O5 更高层缓存、O6 预热、O7 single-flight 和 O8 mmap 仍独立准入，不是这两项的前置，也不因已有规划默认上线。父专项不重复认领实现，重叠收益用消融区分。

实施项准入时登记具体 change、受影响 specs 和责任范围；已有 `bound-container-lookup` 唯一拥有 O1。子 change 需要新增产品行为时按正常 proposal/spec/design/tasks 定义，不能把总专项的候选描述当已批准的协议细节。多个方案的预期收益重叠时先做单因素实验，再做所选组合消融。

### 13. 语义、确定性与回退共用门禁

足额完整结果跨策略比较定义、origin、顺序、诊断、覆盖范围、质量和 text/source map；只有实际工作 usage、cache 状态/计数及耗时允许不进入语义 fingerprint。既有串行路径及新 bulk workers=1 在未触发 elapsed 截止或外部取消、且策略/容量/初态相同时，完整确定性检查继续只排除领域报告的 elapsed_millis，保留预算计数；阶段时间在外部 sidecar。新 bulk workers>1 采用子 spec 明确的足额语义确定性及独立资源总账：准入次序、cache 归属和紧预算/取消子集可能不同，必须记录实际付费与交付范围；不得把身份、语义诊断、规则、coverage 或 source map 加入资源白名单。预算/取消实验采用声明的受控停止点和调度扰动；真实墙钟终止另作延迟实验，不要求其跨运行落在相同指令。

紧预算热路径可能完成而冷路径未完成，必须真实报告；不能回放旧 usage 伪造相等。延迟扫描若改变观察范围，先按子 spec 验收，不能通过从 fingerprint 删除 coverage/diagnostics 获得“透明”。

| 回退层 | 触发 | 行为 |
| --- | --- | --- |
| 实验回退 | 上界不足、收益未证实、复杂度/内存代价超限 | 撤销原型或保持未启用，保留原始数据与否决原因 |
| 运行期降级 | cache miss/失效/容量不足、可恢复的加速构造失败 | 同 snapshot、相同语义、剩余预算内走直接路径；只丢弃失败的可选事实 |
| 终止 | 取消、额度耗尽、已无法安全继续 | 返回真实停止与已发布前缀，不重置 Budget，不自动重试 |
| 发布回退 | 语义/身份/预算/确定性回归，或超出已声明退化界限 | 阻止启用或回退该独立提交；不能回退其它正确性修复 |

策略关闭是回退机制，不要求长期保留全部旧实现；阶段实验可保存旧可执行产物与 fixtures。cache clear 只释放 store 持有引用，不能销毁活动请求借用的 backing。部分结果已发布后的重试必须由明确的 continuation 契约驱动，不用回退隐藏重复输出。

不同证据选择的正文与核心语义一致性按 demand-driven 子 spec 独立验收；同一选择下的完整确定性门禁不放宽，完整证据仍比较全部 source map/规则明细。

### 14. 库复用与依赖选择

沿用已准入 rawzip/flate2/noak、现有 Arc/集合和 P5 harness；依赖的许可、维护与已知缺口以 `openspec/dependencies.md` 和各子项固定版本证据核对。优先利用已有 parser 的切片/locator/事件能力，避免另写 ZIP、CLASS 或 JSON parser。确需 cache、线程池、持久层或 mmap 库时，G2 比较现有依赖能力与新增库的维护、许可、平台、取消和边界测试成本；未通过不得加入依赖。没有具体缺口时不预选新库。

### 15. 核心库的按需边界与下一轮顺序

核心 crate 的普通调用以明确的问题决定范围、事实类别、必要分析和证据深度。`Engine + ArtifactSnapshot + request + Budget` 保持现有边界；不增加公共 Session、全局后台索引或第二套恢复管线。跨请求保留继续显式有界，当前消费者已经持有的可信事实必须直接交接。

[add-demand-driven-core-results](../add-demand-driven-core-results/design.md) 是该产品契约的唯一详细设计，包含必要结果、类型化证据选择、正文提交/证据停止、产物绑定、局部证据和细粒度 query cursor。其任务保持待实现，父专项不通过新增字段列表提前宣称交付。

| 工作负载 | 应测的核心边界 | 本轮实现归属 |
| --- | --- | --- |
| W1/W3 选定方法 | bind/prepare/driver/callee 对同一选中定义只准备一次；不解码未选 body | demand-driven D2 |
| W2 连续导航/放弃 | 显式保留命中、未保留重建、最后消费者释放、无无关预取 | demand-driven D2/D5；保留策略另行准入 |
| W4 小页/续页 | provider 与 consumer 停止、位置重放成本、未知后缀、完整结果拼接 | demand-driven D4 |
| 方法源码/证据追问 | 必要计算、可选明细构造、局部/完整映射、产物核验、输出字节 | demand-driven D1/D3/D5 |
| W6a 全量导出 | 活动容器交接、共享总账、1/N worker、有序背压与清理 | bulk 原 change |

当前代码已经共享 prepared CP/Header（642e49f），不再以旧深拷贝为待实施项。剩余普通单方法条件性 callee 重读、class_source 的 bind + prepare 双读取和 query 整单元收集需要分别见证。活动容器任务交接不能靠 CLI 的保留配置代替；新任务状态以各子 change 的实时清单为准。

决策顺序：独立关闭已复现的数组槽宽与 T5 转换错误；推进 ordinary prepared 交接和必要结果/证据产品；增量 query 独立验收；bulk 同时关闭其生命周期与真实全量门禁。算法正确性修正不混入证据或调度改动。

并行性能重新基于锁等待、worker 计算与内部有序等待归因。discard 样本仅排除编码/文件写出作为唯一原因，不能排除内部背压；总账锁是待测候选。改变证据选择的输出收益和同产出算法收益分开报告。Rust/Java 不是速度证据，完整导出、单方法及追问序列的工作单位不可互换。

## Risks / Trade-offs

- 候选很多导致专项失控 → 所有方案有调查任务，只有 G1/G2 准入项有独立实现范围；否决也是有证据的交付。
- 缓存/批处理降低重复计算但增加驻留 → 分别量化生命周期和内存，覆盖超过容量的 W5。
- 延迟执行改变错误可见范围 → 保留未扫描语义，先定子 spec 再实现，不把减少验证包装成性能。
- 预热把成本移到计时区间外 → 始终保留准备与总成本、放弃轨迹及争用对照。
- 并行只改善吞吐却损害单请求延迟/取消 → W6 多指标及受控停止实验，默认保持保守策略。
- 多项改动/仪表干扰导致错误归因 → 固定构建、逐阶段消融、开销校准，记录不可归因部分。
- 暂缓被误读成完成实现 → 调查状态与产品交付状态分别记录，专项归档引用子项真实状态。

## Migration Plan

停止传播前置已完成；G0 重新核对后续恢复修正和仍开放反例，正式候选须通过其声明工作负载的正确性门禁，并保留其它未覆盖缺口。建立 harness 与八项调查登记，复用已归档 O1 的实现/计数证据，补齐本专项归因与原始样本。按 G1/G2 选择后续项，单独定义产品 delta、实施、验证和演练回退，每完成一项都重测并更新排名。启用策略仅依据已声明工作负载，不扩大成全局默认；独立调查不必等待无关恢复覆盖全部完成。

本专项最终交付：可复现测量入口、每项调查决定与证据、所有已准入子项的实施/回退记录，以及剩余候选的明确处置。未准入方案无需实现，但必须有调查结果或明确的缺失工作负载/证据及重新进入条件；未完成的已准入项不能因任务多或预算不足被标为完成。当前只生成规划，执行这些步骤需后续 apply。
