# Root 独立验收（2026-09-24）

本 change 的准入范围是有唯一合法 `Signature`、逐位置擦除匹配、方法正文及同类调用绑定已证明的普通参数化方法。独立审读了 `src/class_source.rs` 的候选路径、reader 的 `parse_method_signature`/`prove_method_signature_erasure`、`src/facade.rs` 和 `crates/jarde-java/src/report.rs` 的同轮数据来源。实现复用既有 Signature 和 Program/SSA 证据，没有新增反编译 pass；候选失败时保留 descriptor 方法头。方法本地 `<T>` 原路径未被替换。

Root 用自己的 `/tmp/jarde-ordinary-root-accept-target` 构建并运行 `ordinary_generic_projection` 10/10、`generic_method_projection` 9/9、`generic_method_budget` 4/4、`class_source` 47/47；reader Signature 单测 7/7、`method_signature_proof` 3/3，query 7/7、`p1_xref_metadata` 35/35。原源码与 Jarde 的 `OrdinaryParameterizedSignatures` 在 `-g` 和 `-g:none` 下分别按 Java 8 重编，同一个独立 `ReflectionRunner` 经 `java -Xverify:all` 的五行泛型反射及返回值 `7` 完全一致；JADX 两种调试模式的重编/运行也与原类一致。Jarde 两份完整类源码 SHA-256 分别为 `fe7088a24f0470fadd1bc6d8be65bb2e82ca870d0d9522be72b495487957f220` 和 `ce044e233e357341e85a7237bec62e21814acb22783b71e9401156121e8a5e7a`。独立 `OverloadBinding` 负例中，原类和 Jarde 均输出 `char-sequence`，`javap` 所见两份 class 的目标 Methodref 均为 `choose(CharSequence)`；Jarde 仍拒绝不充分的泛型 identity 候选，完整类 SHA-256 为 `bdaf1cac3299bdfdbb385a77a3ae1c6de8c64a3585414d34eba48adfccd2f866`。

边界复核不把 verifier 可接受等同于可重编。把 `List` 等长改成不存在的 `Tree` 后，直接参数/数组因擦除不匹配而回退；嵌套 `Map<String,Tree<Integer>>` 的外层 Map 擦除仍匹配，Jarde 与 JADX 都写出不存在的 Tree，`javac --release 8` 失败。嵌套引用的类存在性证明需要独立 source-resolution 任务，不能称为本 change 已覆盖。类级 `U`、歧义内部类拼写、type-use 路径和 raw 正文污染等拒绝案例记录在[边界证据](../../evidence/java-syntax-2026-09-24/ordinary-parameterized-signatures/boundaries.md)；其中 raw class 的 `ClassCastException` 不是 Signature patch 单独造成。

`cargo fmt --all -- --check`、`git diff --check` 和 `openspec validate recover-ordinary-parameterized-signatures --strict` 通过。完整 `jarde-reader` 套件只有 fixture census 断言失败：实际 `(196,1260,124,562,8)`，固定值 `(164,1152,98,381,8)`，其余 166 项通过；`p5_corpus_fingerprint` 因共享工作树出现 75 个未列入 manifest 的新 fixture 而失败。未修改 census/manifest 来掩盖共享语料变动。`cargo clippy` 严格全目标先遇到共享基线 lint，屏蔽已知 lint 后又遇到其他 change 中 `recover_for_class_source` 测试调用缺少新增布尔参数以及 `cloned_ref_to_slice_refs`；相同包的 `--lib` 检查屏蔽既有 lint 后通过。本 change 的定向验收不以全目标已绿为前提。
