## Why

固定 JADX `TestLoopConditionInvoke` 的区域已全部结构化，但当前 Jarde 把赋值目标 `int` 与调用右值 `char` 的合法扩大转换误判为类型不符，最终拒绝整个 `test(C)Z`。完整上游及独立动态控制均已实际复现这一缺口；应在既有赋值消费者内修正类型准入。

## What Changes

- 对已经证明的条件内局部赋值，在保留原精确类型相等路径的同时，接纳有确切 Java 类型证据的合法基本类型扩大转换。
- 保持右值在原条件位置求值一次、局部声明类型、物理来源、方法级原子拒绝及停止传播。
- 用完整固定上游及六场景动态控制，实际比较原始源码、JADX 与 Jarde 的完整生成类、状态、调用次数、异常和 source map；原始常零 helper 的观测与动态控制分列。
- 前置交付：indexed List 叶子6/6，产品5bd自身CI39153653464已接受；文档主线c0abb3adc已实际核干净并与远端一致。新的控制生成源码基线仍待实际采集，接受前不集成候选代码。
- 非目标：改变变量类型推断、扩大局部赋值形状或区域准入、引用可赋值求解、装箱/拆箱、窄化、任意长宽度赋值、循环风格改写及整CF07/71单元完成声明。
