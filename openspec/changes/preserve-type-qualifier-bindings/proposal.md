## Why

默认参数名 `arg0` 可以遮住 class 同名类型，使静态字段与外部静态调用绑定到参数类型的其它成员。root 的两个完整 Java8 类均被 jarde 零引用恢复且可重编译，但 12 项运行中有 10 项错值；另一个有 debug 名 `java` 的普通方法因包首段被遮住而编译失败。三份原 class/JADX 对照均一致，见 `../../evidence/java-syntax-2026-09-22/type-name-shadowing/`。

## What Changes

- 在本方法局部名称分配时，避让现有静态调用及静态字段呈现需要的类型限定符首段，保持名称在 Java 中仍指向池项声明的 owner。
- 将这些约束并入已有 blank final 字段的名称预占；默认名、debug 名、分段局部和共享非槽名称使用同一候选判断。
- 保持已有别名证据、真实指令来源、确定性命名及预算停止契约，完整类重编译执行验证成员目标和被修改的字段。
- 本项只处理可调整的方法局部/参数/合成名称。不重命名 class 或真实字段、不引入 imports/类型解析器，不改静态调用的接收者求值规则，也不扩张方法引用/泛型恢复。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `java8-recovery`：静态调用及字段的类型限定符不能因恢复局部名称而改绑，受影响名称仍遵守原证据与预算契约。

## Impact

涉及既有 report 的命名输入准备、NameTable 约束和静态 owner 的同源查询；复用当前 facts/字段计划/类型拼写，不新增 AST 或恢复 pass。生产接入等求值顺序任务归还窗口，优先于单纯覆盖扩展。真实字段遮住包名、方法引用限定符及内部类声明拼写属于独立边界；不能为绕过它们删生成成员或改写调用目标。
