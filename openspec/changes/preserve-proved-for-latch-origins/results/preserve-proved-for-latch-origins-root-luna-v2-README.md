# Private patch v2: preserve proved for latch origins

This candidate supersedes neither nor overwrites v1. It is a unified diff for `crates/jarde-java/src/region.rs` and `crates/jarde-java/tests/p3_loop_exit_gateways.rs`, stored only under `/private/tmp`. No repository file was edited; no Git, Cargo, JDK, CLI, formatter, or test command was run.

The implementation extends the existing `implicit_tail_latch_origin` path. It retains the final-Straight, unique natural latch, terminal goto/goto_w + decoded transfer, sole Normal successor, and exact single canonical Normal outgoing edge checks. After obtaining the terminal BCI, it polls the existing budget before any new early return. When `ForHeader` exists, it additionally checks that `update_block` is this latch, the final two SSA instructions are exactly `update_bci` then the terminal transfer, and the decoded Increment/Store writes `proof.slot`. Existing edge charging and per-edge polling stay in place. The single-arm join gate still accepts only `LoopForm::While` with exactly one origin and validates that origin through the same helper.

The Plain positive test checks all original method BCIs and derived BCI 20 on the complete `for` statement span and expected physical method/class identity in `prefixWhile`, `takenArm`, and `loopAndTail`. Two mutation-only negative tests use the frozen class bytes in memory. Static inspection of its Code attributes and javap facts confirmed exactly three method-body patterns at BCI 17 (`iinc 3, 1`, bytes `84 03 01`) and at BCI 20 (`goto 8`, bytes `a7 ff f4`). One test changes only each method's iinc slot operand from 3 to 2 and expects the independent while proof/origin with no for projection. The other changes only each goto displacement to +3 (target BCI 23) and expects no loop construct or loop-derived BCI 20. These modified bytes are analysis inputs only; they are not run in a JVM. Iterator@42, ordinary while@14, and existing budget/cancellation tests are unchanged.

No direct fabricated-`ForHeader` seam is introduced. The two negative tests exercise real decoded method bodies; update-slot rejection tests the failed ForHeader candidate while preserving the independent while proof, and the changed-target case tests that a non-backedge cannot receive a loop origin. Exact runtime/build behavior and all assertions remain pending root review and guarded execution. This artifact does not claim acceptance or OpenSpec completion.
