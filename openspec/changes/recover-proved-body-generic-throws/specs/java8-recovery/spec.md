## ADDED Requirements

### Requirement: 有正文方法的已证类级泛型异常保留

当类源码投影具有完整且无效果的 `void` 方法正文、已发布的类类型变量作用域，以及与物理异常列表逐位置擦除一致的方法泛型异常签名时，系统 SHALL 在该方法声明中保留类级异常变量，并 SHALL 保持方法的物理身份、正文和异常顺序。无法证明正文、泛型异常合法性或源码调用/继承绑定时，系统 MUST 保留物理异常声明或给出局部拒绝，不得发布部分泛型声明。预算停止或取消 MUST 遵守现有操作状态与原子输出契约。

#### Scenario: 空正文类级异常变量
- **WHEN** 顶层 Java 8 类直接继承 `Object`，其无参 `void run() throws E {}` 的 `E` 第一界为 `Exception`，正文在同轮被证明只有一条无效果的 `return`，且没有未证明的继承或本类调用绑定
- **THEN** 系统输出 `throws E`，重编类的异常反射结果仍为 `E`，原 class 合法的强类型调用方可在目标 Java 8 下重编并运行

#### Scenario: 调试信息不参与异常来源
- **WHEN** 上述 class 分别以 `-g` 与 `-g:none` 编译
- **THEN** 两种 class-source 结果均保留同一个泛型异常变量，结果不依赖局部变量调试表

#### Scenario: 证据不充分时局部回退
- **WHEN** 方法 Signature 的异常变量未绑定或与物理异常列表擦除不符，或正文含未证明的指令、异常处理器、继承契约或本类同名调用
- **THEN** 系统 SHALL 拒绝该方法的泛型异常投影并保留可核对的物理成员，不得只替换 `throws` 文本而留下不一致的声明

#### Scenario: 预算与取消
- **WHEN** 同轮正文证明或声明输出在预算耗尽或取消前无法完整完成
- **THEN** 系统 SHALL 报告对应停止状态，且已交付的 class-source 中不得出现部分泛型异常声明
