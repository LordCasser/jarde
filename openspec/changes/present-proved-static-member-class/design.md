## Context

见 `proposal.md` 和冻结 `static-member-basic` 三方证据。`src/member_inner.rs::scan_family_root` 已用根类的 typed `InnerClasses` 行发现最多一个直接成员候选，并用子类自身的行反证关系，但明确排除 `ACC_STATIC`。当前 `ClassSourceMemberFamily::Prepared`、构造调用证书和 `render_member_class` 都以非静态外部实例捕获为前提；静态成员不能简单伪装为已证捕获。方法 AST 的 `New` 节点保留二进制目标，类源码文字由 `class_source` 装配，物理报告独立。

## Goals / Non-Goals

**Goals:** 在同一个根类源码单元装配一个无字段、非泛型、方法完整的直接静态成员；根类中精确指向该类的返回类型和无参创建使用源名。保留物理类身份、报告和原来的非静态捕获家族规则。

**Non-Goals:** 第二个子类、多级静态嵌套、泛型成员实参、静态成员字段/复杂构造器、跨类使用点重写、从任意 `$` 名反推嵌套关系。这些分别需独立证据与任务；不能为了当前样例全局改名。

## Decisions

1. **关系入口共用，证明分支明确。** 放宽现有根类候选扫描的静态位禁令，但仍要求最多一个准确直接子类、源名合法、根子双方 `InnerClasses` 行完全一致、子类无 `EnclosingMethod`、选定物理定义唯一。`FamilyRootCandidate.access_flags` 已包含静态位，无需新扫描器或名称索引。`ClassSourceMemberFamily` 增加明确的静态准备状态（或等价且不把捕获标为 `Refused` 的表示），与非静态 `Prepared` 的捕获/限定构造证书分开；不让“没有捕获”冒充“捕获证明失败”。
2. **窄证明后重用源码装配。** 子类要求无字段、非泛型、完整可写的声明/方法正文及一个平凡无参构造器；其构造器原始 Code 必须仅实现对 `Object()` 的调用和返回。根类只改准确引用该物理子类的非泛型方法返回类型及直接无参 `new`，成员类型源名由关系证书生成，内部 `Type`/目标仍是原二进制身份。`Named$Top` 缺 typed 关系，绝不进入该路径。方法签名按原描述符与源路径重新拼写，创建表达式从同次 AST 投影；不得对整段文本搜索替换 `$`。
3. **复用一个根类 writer。** 现有 `source_text_with_member` 已控制根类成员顺序及嵌套子类位置；扩展其可选成员投影输入以容纳静态与捕获两种被证明的源形态，静态分支不生成隐藏捕获字段/参数/桥的派生范围。子类的构造器源名从准确成员简单名重建，其他方法保留原独立报告的正文。先形成完整候选源码及派生物理锚点，成功后原子替换根类 `text`；失败、预算或取消时不提交部分修改。
4. **物理与源码单元分离。** `class_source(StaticMemberBasic$Leaf)` 仍返回独立物理报告；根类投影是另一源码单元。Java 8 重编验收只编译根类单元和真正独立的 `Named$Top`，不把物理子类报告再作为同一项目的顶级源码，否则可能与 javac 生成的嵌套 class 同名。类源码 API 当前不提供全项目导出。
5. **JADX 是语法参照，证明以 reader 为准。** `TestInnerClass2` 和 `ClassModifier`/`ClassGen` 可校核 `static class` 与 `new Leaf()` 的形态；Jarde 的候选以 typed 属性和选定物理定义为准。当前库已经具备解析、版本门、选定运行时、方法恢复及家族 writer；额外第三方库不能提供该范围内的身份与预算证书，不引入新依赖。

## Risks / Trade-offs

- `[已有家族数据结构隐含捕获]` → 静态状态独立标识，在 writer 只复用布局，不复用捕获专有字段/派生锚点；既有非静态回归保持原输出。
- `[签名或表达式误拼写顶级 `$` 类]` → 按准确物理定义和双方 typed 行定位，仅重写目标子类，不处理名称相似项；用 `Named$Top` 控制验证。
- `[只改使用点导致缺声明或编译失败]` → 根类文字最后原子提交，Java 8 重编根类源码单元及真实独立依赖。
- `[其他成员位置仍留二进制拼写]` → 本切片限冻结场景中的方法返回与直接构造，发现字段、参数或跨类位置另记债务，不虚称整个 DT-02 完成。
