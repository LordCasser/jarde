# PriorAssert diagnostic delta (private v1)

This patch only improves assertion failure context in the existing PriorAssert test. If the numeric initializer or the no-anchor condition fails, the panic now prints the actual recovered `value.text` and the projections whose method anchors refer to `value.item.identity`. It does not assert or presume whether naming is correct, and it changes no production rule.

Static capture path: for an ordinary class with javac's synthetic `$assertionsDisabled` field, `capture_assert_asts` is selected during class preparation. `recover_prepared_member` forwards that flag to `recovery_presented_for_class_source`, which retains the method AST sidecar. The class-source assembly later attempts `project_class_source_assert_statements` before assembling its final report; that fold requires the class-wide switch-field/clinit proof and per-method field-use census before it stages member text. Separately, `Engine::class_source` invokes the integer-name adapter after the report is assembled, only for a complete report without competing family projections. Its array path skips a matching `projection_inputs.member_texts` entry; otherwise it requires original-AST replay to match the current member text. Therefore an assert appearing in recovered text does not itself establish that the assert folding pass staged the method. Actual diagnostic output will distinguish a valid `VALUE` projection from a refusal or replay mismatch.
