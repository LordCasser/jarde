# Independent v4 verifier review

This immutable preparation derives from v3 and targets the completed `candidate-full-class-root-v7` run. It has not been executed. It pins the v7 manifest inventory, CLI v2 binary, and candidate metadata v2 hashes; it also requires the exact absolute paths recorded for those frozen inputs.

The v7 inventory contains 417 unique entries, but its recorded order is not lexicographic; v4 therefore verifies the closed path set independent of row order, while checking every entry hash. A read-only schema inspection of v7 confirmed 75 commands, 32 render rows, 417 closed inventory files, 2 imported oracles, 2 original controls, 4 Jarde candidates, and 4 JADX candidates. The success counts intentionally exclude the two imported oracles. Render documents expose `text`, `fields`, `methods`, `integer_constant_projections`, and complete physical method reports; the row does not contain `class_source_text` or `physical_inventory_matches`. Original controls use `member_map.instructions_by_method`; the accepted array baseline has no corresponding row map, so the verifier parses BCI offsets from the hash-checked captured `javap -p -c -s -v` stdout. `control-original` rows have no `group` key, so the identity census defaults those rows to `controls`.

The previous accepted ArrayFill baseline is the exact `array-literal-boundaries-next/baseline-root-v2` path pinned by v7, with the accepted independent verification JSON and inventory. The captured baseline paths were checked to exist. V7's preflight actually contains `blake3-runtime`; the verifier checks that real label and independently recomputes BLAKE3 for each input class, joining class, field/method owner identities, and projection anchors. It also checks that the JADX ZIP is exactly the five javac23 control classes, with no Runner, and scans each emitted class directory against its recorded class census and javac source paths.

Expected outcome counts are 8 positive default-profile projections and 10 negative default-profile observations (five refusal controls on two JDKs). For each physical method in all 32 renders, it checks every source-map primary method identity and owner BLAKE3, then verifies every mapped BCI belongs to that same method in the original javap instruction set (controls from their original member map, arrays from the accepted baseline raw javap). It checks the two assertion modes, source text, physical report text/source maps, complete-class compilation and runtime raw streams, and inventory closure. A pass establishes these recorded evidence and provenance checks only; it does not prove the original source used the projected names or complete the OpenSpec change.
