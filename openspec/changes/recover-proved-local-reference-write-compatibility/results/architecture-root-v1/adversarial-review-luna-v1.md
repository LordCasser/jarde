## Findings

1. **Completeness of the candidate's access set is the main correctness gate.** `slot_uses` in `crates/jarde-java/src/build.rs` (around line 1928) derives its map only when `reuse.variable_at(slot, bci)` returns `Some`, and skips BCIs in `elided_cleanup`; an unmapped local access is absent from `uses` rather than represented as an incomplete record. Therefore checking `uses[variable]` for every write/read and `path.is_some()` is insufficient by itself to prove “all writes” and “all Loads.” A candidate must independently walk every SSA local read/write for the candidate slot, charge/poll before inspecting each item, and establish that each such access is either mapped to this exact `LocalVariable` and present in the examined set, or belongs to a different proved split identity. A same-slot access for which `variable_at` returns `None`, or an omitted/elided access not accounted for by the proof, must refuse the candidate. Otherwise an ambiguous slot-reuse access or hidden consumer can escape the Object gate. This is a real potential hole, not a reason to add a generic type service.

2. **All-load direct-return check must validate both sides of the edge.** For every mapped read, require the matching `Operation::Load` and SSA instruction to read the candidate local and produce exactly one stack value; require that value to have exactly one consumer, and verify the consumer instruction itself is a `Return` whose actual input is that exact stack value and whose physical method return descriptor is exactly `Ljava/lang/Object;`. Merely seeing a `Return` operation at the sole-use BCI, a compatible frame type, or a phi/load adjacency is not enough. All SSA consumers must be considered, including copies, stack phis, and non-return uses; any such use refuses this narrow candidate. Check that there is at least one read so the read-side proof cannot succeed vacuously.

3. **The direct Object trigger is suitably narrow only if exact.** `direct_reference_write_type` (around line 3011) names direct producers such as method/field descriptors, class/string constants, allocations and arrays; the candidate should require the exact type `Type::Reference("java.lang.Object")`, not a frame-derived `Ref(Unknown)` rendered as Object, not an array spelling, and not an Object supertype inferred from unrelated writes. `written_type` (around line 32114) can intentionally use frame/creation facts that are adequate for ordinary emission but are not identity or precise producer evidence. Every write must separately be an initialized reference or actual null (null may be accepted as assignable to Object); reject primitive, `Top`, `Second`, uninitialized values, return addresses, unspellable/unknown non-null values, and caught-value/header writes. At least one *stored operand* must supply the exact Object producer; a missing store operand must not be silently replaced with the local's written SSA value to fabricate producer proof.

4. **Array, parameter, header, and exception boundaries need explicit guards.** The spec explicitly leaves array shape, parameters, and incomplete handler coverage outside this rule. Reject parameter slots before considering body writes; reject resources/catch/header locals using the existing region/identity facts rather than slot/name heuristics; do not skip `Definition::Caught` in this all-write proof. Reject array-typed writes (including any `Type::Reference` spelling beginning with `[`), even if Object assignment and Object return would compile, because the agreed candidate must not erase array shape. Any missing path, unknown handler access, or handler write must stop this candidate rather than be ignored. A locally complete normal CFG path is not automatically proof that exceptional paths/handler stores were covered.

5. **Budget/Stop and publication must remain atomic.** `decide_types` returns `Result<..., StopReason>`, and existing writes are charged/polled. The additional slot enumeration, load lookup, consumer walk, instruction/operation checks, and any SSA-use iteration all need bounded charging and cancellation polling before each evidence read. Propagate `StopReason` unchanged. Do not insert a tentative `Decided::Type(Object)` into the returned map before the entire write/read proof closes. Existing declaration callers consume the map for both declaration paths; no output, source-map, or fallback assignment should be committed on a partial proof.

6. **`NoType::ConflictingWrites` message is not accurate for the intended refusal.** Existing `NoType::message` (around lines 540–576) says “no Java declaration can hold both.” That is false for `String` plus `Object`: an `Object` declaration can hold both. It is also an overbroad claim for primitive/reference conflicts because Java boxing may make an `Object` declaration source-assignable, although it may not preserve the emitter's exact conversion/semantics. Keep the existing refusal category if that is the contract, but change the message to the precise fact: the selected declaration type is incompatible with the later write and this region is refused rather than emitting a contradictory assignment. Do not claim that all alternative Java declarations were disproved.

## Assessment

The proposed positive rule is sound within its stated scope if exact identity/access closure is proved: an initialized reference or null can be assigned to `Object`, and a direct `Object` return accepts the resulting local without a new cast. This depends on all writes/reads being accounted for and the physical method descriptor and SSA consumer edges matching the claim. The current `uses` map alone does not establish closure because unmapped and elided accesses are omitted. That is the blocking implementation question to inspect in the private candidate.

The planned CharSequence receiver, array lifecycle, parameter, slot-reuse, catch/handler, and Stop controls target the right boundaries, but no actual controls or generated-source compile/runtime results exist yet. The frozen observation is one same-IR positive shape; it is not evidence for those boundaries. The message correction is a small accuracy fix tied directly to any conflict result this narrow rule may produce. No general least-upper-bound inference, hierarchy search, new pass, or type service is warranted for this slice.
