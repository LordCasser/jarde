# CF11 local reference-write observation checker prep v1

This is a private, unexecuted adaptation of `/private/tmp/jarde-for-condition-checker-root-v7/check_controls.py` (SHA-256 `a05acce687bf0e22bfab9eb8ae00520d53a006b740732f4b0041182ce72a464a`). It preserves that checker’s raw stream, tool pins, classfile method/BCI, javap, source-map, conditional compile, and runtime comparison checks. It does not run collector or toolchain commands. The current adaptation is for the v2 private input manifest and the capture schema `cf11-target-full-source-capture-v3`.

The checker requires `--expected-javac-debug debug|none`, binds it to the captured receipt’s `javac_debug_profile`, and checks every recorded javac compile argv has exactly the corresponding `-g` or `-g:none` flag. It parses `LocalVariableTable`, `LocalVariableTypeTable`, and `LineNumberTable` directly from each target class’s nested `Code` attributes. For `none`, those attributes must be absent from every target method. For `debug`, the literal target’s `positive(List)String` method must contain actual `values`, `target`, and `iterator` LVT rows and a nonempty line table. The evidence is structured binary attribute data; javap text is not used to infer debug attributes.

The source pins file is bound to SHA-256 `eeddbbc55a91f763771fe2ef8fa2fd3671480d53d933befd8cbff5b449dc4475`; its manifest and listed source pins are checked. The original Java 8 and Java 23 Runner outputs must match byte-for-byte and contain 29 unique case lines: the 21 source-baseline cases plus the eight added no-cast cases. Nine reference-control lines and all nine no-cast lines (the existing last-value case plus eight additions) are compared against the intended lines pinned in `pins.json`.

The checker records slot-control load/store lines from the actual javap method and the actual parsed LVT ranges. It explicitly leaves SSA identity uncollected and does not conclude that a slot was reused or that a local was split. Missing method maps, uncovered physical BCIs, failed or unusable Jarde/JADX outputs, default/all differences, generated compile failures, and runtime mismatches remain observations in the output. The status describes capture quality only; `assessment` always says observation-only and product behavior acceptance is not claimed.

The exact two invocations are in `run-plan.json`. Their execution JSON paths follow the v2 run plan: `/private/tmp/jarde-local-reference-write-baseline-root-v2-debug/execution.json` with profile `debug`, and `/private/tmp/jarde-local-reference-write-baseline-root-v2-no-debug/execution.json` with profile `none`. These are planned inputs; no capture result is claimed here.
