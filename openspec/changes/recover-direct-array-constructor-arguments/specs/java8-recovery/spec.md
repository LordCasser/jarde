## ADDED Requirements

### Requirement: 普通构造参数 SHALL 组合已证明的直接数组表达式

当数组完整表达式的最终值正是普通构造调用的物理实参、只有该调用消费且求值区间、效果、异常归属和所有权均可证明时，系统 SHALL 将它呈现在相应构造参数中，保留每个长度、元素、分配和调用的单次执行、原始顺序、值及完整物理来源。支持范围 SHALL 由现有数组表达式证明决定，不得因长度非零、长度动态、元素为引用或维度较多而额外拒绝已有完整证明。

#### Scenario: 原始 TestFinally3 debug 与 noDebug

- **WHEN** 输入来自未改写的原始 TestFinally3 源码的两个 Java8 target profile，构造参数为新建空 byte 数组
- **THEN** 完整独立 TestCls 和包含该成员类的 owner 均保留所有方法并原样重编成功，隔离运行与原始类的固定行为一致，原有 finally 正文和其他方法保持正确

#### Scenario: 裸数组与动态多维分配

- **WHEN** primitive 或 reference 数组的动态长度、正长度或多维长度和直接构造消费满足完整表达式证明
- **THEN** 构造参数保留所有长度及求值次序，负长度和长度生产者异常在原位置发生，后续参数或构造器不得提前执行

#### Scenario: 已证明的初始化数组组合

- **WHEN** 初始化数组、子数组或包含已证明构造元素的引用数组具备闭合事实且其最终值唯一供给外层构造实参
- **THEN** 完整数组表达式与外层构造正确组合，各元素、嵌套构造和外层构造各执行一次，顺序、对象身份和来源不丢失

#### Scenario: 精确消费与异常边界

- **WHEN** 同一调用读取的值并非候选数组最终值，或存在额外消费、未闭合 store、无关效果、跨块、异常覆盖变化或所有权冲突
- **THEN** 系统不得仅凭调用 BCI 或数组分类接受该组合；无法证明时保留明确拒绝及实际来源，不发布改变语义的 Java 正文

#### Scenario: String 与其他普通构造使用相同完整证明

- **WHEN** String(char[]) 或其他普通构造的直接数组实参满足完整证明，包括有副作用的已证明元素以及构造结果存储后再返回
- **THEN** 系统 SHALL 按相同的值身份、求值和异常边界准入，不以历史常量元素或直接 return 特判额外拒绝

#### Scenario: 共享预算与原子停止

- **WHEN** 数组事实查找、实参身份扫描、依赖闭合、异常覆盖或呈现过程中发生预算、取消或期限停止
- **THEN** 系统按实际工作计费并保留真实停止原因与位置，不发布部分构造正文或映射，不把停止转成成功或普通不支持
