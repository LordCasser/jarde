## Context

见 [proposal.md](proposal.md) 与[受控三方证据](../../evidence/java-syntax-2026-09-25/ordinary-new-void-effect/analysis.md)。`init::verify` 对区间内的 `Operation::Invoke` 调用 `produces_a_read_value`，其 `values.is_empty()` 分支使 `()V` 调用自动通过；非空分支只要求同块任何后续读取，也未限定到构造器实参。构造站点仅认领分配、复制和构造器调用，Builder 因此把未认领调用写成独立语句，导致 `new` 的类初始化推迟。

## Goals / Non-Goals

**Goals:**

- 在当前 `new@1` 的站点验证内证明区间调用确实是构造实参依赖，而非把“有栈结果”或“同块有人读过”当作充分条件。
- 失败继续走既有 `StatementFree` 拒绝与引用原始字节码的路径；成功的普通调用实参仍作为一个构造表达式发射。

**Non-Goals:**

- 不恢复独立调用夹在分配和构造器之间的特殊 Java 写法，也不改变 `new` 的 JVM 语义、构造器 AST 或成员内部类分支。
- 不在这个变更清理其它纯运算或非调用指令的可移动性边界；若审计发现另一个独立反例，单独登记。

## Decisions

1. **使用现有 SSA 值定义追溯实参链。** 从 `<init>` 的普通实参值出发，在当前基本块内沿定义指令及其读取递归追溯，收集构造表达式实际使用的 BCI；区间中每个 `Invoke` 必须在该集合内。无栈结果调用无法成为值生产者，自然拒绝。用已访问集合界定循环和重复读取，受该方法既有 IR/请求预算约束；不新增 IR、跨阶段索引或通用 effect 机制。相比把 `values.is_empty()` 改成 false，这也关上“有返回值但只被无关操作读取”的宽门。

2. **保持原拒绝和呈现合同。** 调用未归属时使用既有 `NEW` 的 `StatementFree` unmet refusal，诊断写出独立调用 BCI；`Sites` 不认领候选，报告的 `presented` 只反映验证成功。Builder 原有 fallback 必须覆盖分配、调用及构造器来源，不能仅靠记录 false 就视为修复。有效调用实参继续走现有 `new_expr` 和参数类型校验。JADX 可供定位类似算法，但其这份样本同样重排，不能照搬准入；现有 Rust SSA 已有全部所需事实，无额外依赖的收益。

3. **以执行结果验收顺序。** 锁定 verifier-valid 原 class `CST`、JADX/Jarde 旧文本重编 `SCT`，测试修复后的 Jarde 站点必须拒绝且追溯全部相关 BCI；另用 javac 正常构造调用作接受控制，检查调用只发射一次。由于拒绝产物不宣称可编译项目，不把 fallback 文本硬改为可执行 Java 作伪等价验收。必要证据、全部详情与范围选择只改报告物化，不改站点决定。

## Risks / Trade-offs

- [值依赖闭包忽略某种无栈结果但语义上属于参数求值的调用] → Java 构造实参的值依赖必须通过栈/局部值呈现；未能证明时保守拒绝，后续用精确正例再开放。
- [站点拒绝后 Builder 仍写出已重排的 `new` 文本] → 测试同时检查正文、质量和物理 BCI 来源，不能只断言记录标志。
- [与成员内部类 OpenSpec 同时修改普通验证] → 本变更只触及普通构造调用归属；两份实现按小范围合并验收，后者不能借此放宽成员限定/null-check 的独立证明。
