## 变更使用约束

- 每个阶段保持独立 OpenSpec change；`proposal.md` 的 capabilities 必须与 `specs/<capability>/spec.md` 一一对应。
- P0 的顶层 locator 与有界内存快照不在 P1 重做；P1 才增加 nested/MR/Boot 的递归候选、布局和 RuntimeView。
- 各阶段只有实际完成并验证的任务才能勾选；P0 状态以归档 tasks/verification 与主规格为准，P1 以归档记录为准，P2 以归档记录为准，P3–P5 以各自归档记录为准；后续修正以当前 active change 的 tasks 与最新复核为准。本文描述依赖和门槛，不把规划完成解释为实现完成。
- 每个 change 的实施阶段归档前先执行对应 strict validation，再按架构验收 IDs 和真实语料验证；有行为 delta 时 archive 默认同步主 specs，不使用 `--skip-specs`。
- 优先复用 P0 已评估的 noak、rawzip、flate2 rust_backend、blake3、serde、thiserror、clap；后续库、持久 index 或并发方案先依 [选型准入](dependencies.md) 评估。JVM/JADX 不进入生产核心运行依赖，只可作为受控测试 oracle。

## Java 8 `.class` 语法恢复对标 JADX（2026-09-24 巡查裁决）

先按本地 `/Users/lordcasser/workspace/testzone/jadx` 的 `2fb1b163`（`v1.5.6-26`）源码核对能力，再按下表的证据和 OpenSpec 子任务实施；已有三方执行记录使用安装的 JADX 1.5.6。两者的 region-mode pass 顺序相同，但不能把测试源码里出现的语法直接算作 JADX 输出能力：`IntegrationTest` 先编译输入，部分目标测试标记 `@NotYetImplemented`。对标范围是 **Java 8 class 文件到 Java 源码**，不把 Dex、Android 资源、Java 17+ 声明或逐字复原原源码混入同一门槛。JADX 的实际路径是统一输入指令 → CFG/SSA/类型 → Region → String/enum switch、循环、finally 等局部重写 → Java 输出；jarde 已有 reader、CFG/SSA、Region、AST、类级装配和规则报告，当前无需另建通用 pass 管线。

[类与方法同名类型变量的三方探针](evidence/java-syntax-2026-09-25/method-type-variable-shadowing/analysis.md)补出可恢复的词法作用域边界：原 Java 8 的 `ShadowPlain<T>` 与 `ShadowBounded<T extends Number>` 各有静态方法自己的 `<T>`，强类型调用方在有无调试表时均可编译运行；旧 Jarde 把同名视为冲突并退回 `Object`/`CharSequence`，JADX 1.5.6 只恢复无界形状，异界 `T extends CharSequence` 也退化。[独立 OpenSpec 与 Root 验收](changes/recover-shadowed-method-type-parameters/verification-root.md)已让 reader 的现有类/方法签名证明先查方法变量，再查类变量，并逐位置核验物理擦除；静态直接参数返回复用原源码投影。`-g`/`-g:none` 两份完整类、原强类型调用方和反射与原 class 一致；[verifier-valid 错界控制](evidence/java-syntax-2026-09-25/method-type-variable-shadowing/analysis-negative.md)仍局部拒绝。不需要新解析器或全局 pass；非静态方法、外层内类变量与复杂正文仍是分开的证明范围。

[接口 `super` 的双向对照](evidence/java-syntax-2026-09-25/redundant-interface-super/analysis.md)显示正常 Java 8 双接口显式选择中，Jarde 的 `Left.super`/`Right.super` 重编执行仍得 11/22/33，而 JADX 1.5.6 降为类 `super` 后误得 7/7/14；这是应保留的优于 JADX 的行为。另一份只改 `InterfaceMethodref` owner 的 verifier-valid class 同时直接实现 `Parent` 与 `Child extends Parent`，JVM 可调用 Parent 返回 3，Jarde 却写出 javac 拒绝的冗余 `Parent.super`。[父类链冗余接口对照](evidence/java-syntax-2026-09-25/superclass-redundant-interface-super/analysis.md)进一步证明其它直接接口无关仍不足以放行：`Base` 或更远的 `Root` 已实现 `A` 时，patched `A.m()` 可在 JVM 返回 1，`A.super.m()` 却被 javac 以冗余接口拒绝。[抽象覆盖与继承 default 对照](evidence/java-syntax-2026-09-25/abstract-interface-super/analysis.md)又证明单直接接口也不足以放行：抽象 `Child.value()` 使原 class 在调用处抛 `AbstractMethodError`，Jarde 的 `Child.super.value()` 不能重编；而合法继承 `Parent` default 时 Jarde 保留 `Child.super` 并返回 3，JADX 写成不可编译的裸 `super`。按[独立 OpenSpec](changes/prove-interface-super-source-legality/design.md)在已有特殊调用选择外按需、按选定环境和预算同时证明其它直接接口及完整父类链均不使 qualifier 冗余、且目标 default 唯一可访问；不把不合法源形状改写成其它调用。旧 `preserve-special-call-dispatch` 的全库门禁债务与此语法边界分开。

[接口 `super` Root 验收](changes/prove-interface-super-source-legality/verification-root.md)现已把合法的显式接口选择与上述非法源码限定名分开：选定接口闭包、全父类链与唯一可访问 default 都证明后才发布精确 `I.super`。两种调试表输入的四类合法完整类均能按 Java 8 重编并运行；直接/父类冗余、抽象覆盖、缺依赖及重载歧义都保留来源回退。当前重载歧义是有意的覆盖边界，即使个别 Java 调用本来合法也不会猜测绑定；这比照搬 JADX 对接口调用的裸 `super` 降级更可靠。

**JADX 对照之外的两条已实测边界。** [多项物理异常顺序](evidence/java-syntax-2026-09-25/throws-order/analysis.md)在 `-g`/`-g:none` 下可由 `javap` 和反射同时观察；JADX 1.5.6 用集合归并后把三种源顺序统一写为 `SQLException, IOException, ReflectiveOperationException`，其中两种失序，Jarde 当前保留物理顺序及重编后的反射顺序，不需跟随 JADX 的改写。[泛型外部实例创建内部类](evidence/java-syntax-2026-09-25/inner-generic-instance-constructor/analysis.md)则仍超出当前两者：原 `a.new B<Integer>(3)` 可执行，JADX 写 `new A.B<>(3)` 导致完整源码重编失败；Jarde 对泛型嵌套声明与构造调用保守拒绝。[非泛型调用点拆解](evidence/java-syntax-2026-09-25/inner-generic-instance-constructor/simple-member/analysis.md)及[五个 verifier-valid 错形变体](evidence/java-syntax-2026-09-25/inner-generic-instance-constructor/simple-member/invalid-controls/byte-variants/analysis.md)现已按[独立验收](changes/recover-proved-member-inner-construction/verification-root.md)闭合：Jarde 对已选目标/外层关系和 SSA 身份、早检查都可证明的调用输出 `outer.new Inner(args)`，Java 8 重编与原 JVM 的成功、null、嵌套及前置效果一致；关系错、身份错和迟检查保守拒绝。新增保留完整 null-check 形状的身份变体中，JADX 1.5.6 源码虽可编译，却把原 `actual-null:null:A` 改为 `actual-null:null:`；只错外层 `InnerClasses` 的变体则证明目标类自述不足以保证调用方源码可重编。首片仅覆盖公开非泛型调用点；泛型外层的 JADX 错误、类级类型作用域和完整嵌套声明装配留待后续。

[非泛型外层加泛型成员的独立探针](evidence/java-syntax-2026-09-25/inner-generic-instance-constructor/non-generic-outer-generic-member/analysis.md)进一步收窄了缺陷：JADX 1.5.6 对返回 `Outer.Inner<Integer>` 的 `Use` 能写出可重编的 `outer.new Inner<>(...)`，但返回 `Object` 的 `UseObject` 却写为不能重编的 `new Outer.Inner(outer, ...)`，把物理合成首参当源码实参。两份原 class 在 `-g`/`-g:none` 均可执行，`UseObject` 的 null 路径仍保持参数效果次数不变。Jarde 现有成员证明仅因目标 `Signature` 拒绝此形状，故按[独立 OpenSpec](changes/recover-proved-generic-member-call-sites/design.md)扩展已证物理前缀与签名尾部的对齐，先验收 caller-only、原依赖 jar 重编。完整 `Outer<T>.Inner<V>` 源码还需外层/成员类签名作用域、成员声明及嵌套类装配的独立任务，不由调用点完成推断。

[泛型外层的四形状矩阵](evidence/java-syntax-2026-09-25/inner-generic-instance-constructor/shape-matrix/analysis.md)把 raw/参数化 `Outer.A<T>`、普通/泛型成员及 `Object`/参数化返回分别编译验证：原始 Java 8 调用方均可独立重编并运行，JADX 1.5.6 四个调用方都省略 `outer.new`、均不能对原始目标 jar 重编。[Jarde 基线](evidence/java-syntax-2026-09-25/inner-generic-instance-constructor/shape-matrix/jarde-baseline.md)则显示调用点受外层 `Signature` 硬拒绝、调用方嵌套泛型方法头不能投影、完整嵌套声明也不能装配。[已完成的 OpenSpec 与 Root 验收](changes/recover-generic-enclosing-member-call-sites/verification-root.md)用选定类关系、签名擦除和同次成员构造证明闭合四个 caller-only：`-g`/`-g:none` 均对原始 Outer jar 重编并保持八行成功/null/效果轨迹，all/essential 正文及完整 BCI 来源一致；合法 `$` 顶层名仍保守拒绝。完整类族源码另需跨 class 声明树及词法 `T`/`V` 作用域的独立 change。JADX 的构造输出位置与分段泛型解析可参考，`SKIP_FIRST_ARG` 的形状判断不能代替 Jarde 的目标、SSA 身份和早空值检查证明。

**超越 JADX 的 String switch 正例。** [中间 default 三方对照](evidence/java-syntax-2026-09-24/string-switch-variants/analysis.md)固定了一个原/JADX/Jarde 18 行行为一致、但旧版 JADX/Jarde 都保留两级整数分派的 Java 8 class。JADX 要求第二级每个显式整数 key 均有字符串映射，故把没有任何字符串比较写入、但与 default 共目标的空洞 key 拒绝。[最终 CLI 重放](changes/recover-string-switch/verification-2.2-to-3.1.md)表明 Jarde 在证明初值、写入集合、共目标与穿透后输出单层字符串 switch，18 行仍逐字一致；JADX 1.5.6 仍是两层。

**String switch 的拒绝边界。** [两个合法 Java 8 反例](evidence/java-syntax-2026-09-24/string-switch-negative-fixtures/analysis.md)确认 hash 的额外消费者不可被清理：JADX 1.5.6 在 `ExtraHashUse` 产生未声明 `r0`，完整类无法重编，Jarde 保留两级分派与原 class 6/6 行一致。错误 hash bucket 和桶内额外副作用也须保留原分派；[最终 CLI 验收](changes/recover-string-switch/verification-2.2-to-3.1.md)对三个负例均保留两层且原/Jarde 执行相同。[来源/预算验收](changes/recover-string-switch/verification-2.4.md)也已完成。

**增强 `for` 的算法边界。** 本地 JADX 的 `LoopRegionVisitor` 先识别有唯一双输入 phi 的归纳变量，再在数组情形核对初值 0、步长 +1、`index < array.length`、`aget` 与长度来自同一数组值；迭代器情形核对 `iterator()`、`hasNext()`、`next()` 和 iterator 值的两处使用，再改写 Region 并隐藏原指令。Jarde 借鉴其 SSA 使用约束，在已验收的数组子切片证明数组引用只求值一次、元素类型、退出边和异常/副作用次序；[包装读取扩展](changes/project-proved-wrapped-array-elements/verification.md)只接受元素读取前为纯局部/整数运算且每轮只读取一次的表达式。尤其 JADX 对包裹在表达式中的 `aget` 没有充分证明前置副作用，对 `next()` 的保护区也没有保持；[数组](evidence/java-syntax-2026-09-24/array-wrapped-binding/analysis.md)与 [Iterable](evidence/java-syntax-2026-09-24/iterable-raw-projection/remaining-4-1/analysis.md)的完整类运行已分别证实错误结果和异常逸出。Jarde 的直接 `Iterable` 切片已证明调用 owner、容器源码类型、SSA 独占消费、元素转换及逐调用处理器一致；其他 owner 仍需类型证据，不能靠方法短签名或修改推断类型强行凑出语法。一个仅有 `iterator()` 方法却不实现 `Iterable` 的[冻结 Java 8 探针](evidence/java-syntax-2026-09-24/enhanced-for-algorithm/analysis.md)在安装的 JADX 1.5.6 中保留 `while`；[索引逃逸与错配数组反例](evidence/java-syntax-2026-09-24/enhanced-for-current/analysis.md)也未被 JADX 折叠。完整可执行的计数 `for`/迭代器 `while` 是拒绝投影的保底路径。

**增强 `for` 负例同时暴露的独立基底债务。** [当前 Jarde 重放](evidence/java-syntax-2026-09-24/enhanced-for-algorithm/analysis.md)没有把索引逃逸或错配数组误投影，却对两条合法手写循环输出 explanation-only，完整类缺返回语句；这属于 P0 循环/局部生存期形状，须另行处理。非 `Iterable` 探针保留 `while`，给单类编译补上同输入嵌套类的 classpath 后可重编运行且与原 class 相同；不能把第一次裸编译的缺类错误算成产品缺陷。这类数组负例只验收不误投影，不虚报它们的 Jarde 运行等价。

[异常边界的独立探针](evidence/java-syntax-2026-09-24/iterable-exception-boundaries/analysis.md)还证明受保护 `Iterable` 局部跨 quoted fallback 时，Jarde 的三个合法方法仍 explanation-only，完整类缺返回语句；它归入已存在的 [P0 异常区/局部生存期任务 2.5](changes/preserve-local-scope-across-exception-regions/tasks.md)，而非新增一个循环投影修补。不能为了输出增强 `for` 绕过该结构债务：root 复编的 JADX 1.5.6 在 12 行中有调试信息错 4 行、无调试信息错 3 行，分别把异常送错 catch、跳过或重复执行 finally。现有 `Iterable` 投影的逐调用 handler 集合相等门槛应保持。

**增强 `for` 的独立文本质量与局部生命周期。** [缓存声明清理](changes/prune-proved-foreach-cache-declarations/verification-root.md)已在成功数组投影中按 `LocalVariable` 身份、声明来源和后继访问证明删去失用的 `int local3; int local4;`；直接/安全包装数组正例在有无调试信息时均 Java 8 重编且执行等价。[同槽复用三方对照](changes/separate-reused-local-lifetimes/evidence/analysis.md)冻结了更深的独立缺陷：预修复 Jarde 把循环前 `int[]` 临时和循环后 `int` 绑为同一局部，完整类重编失败。[同槽生命周期修复](changes/separate-reused-local-lifetimes/verification-root.md)现沿既有 SSA/CFG/帧/LVT 与声明接缝实现 Ref/Int 的有界分段，`-g` 和 `-g:none` 均完整类 Java 8 重编、`-Xverify:all` 运行与原/JADX 对齐；未能分段的确定引用/原始类型冲突报告拒绝。互斥分支可在各自值链及 CFG 证明下恢复；无 LVT 的循环内反复复用、异常 handler 和 category-2 仍有明示边界。引用间子类型及原始类型间转换的全面声明赋值判断属于独立类型相容性债务，不把本次确定类别门称为通用类型检查器。

**`Iterable` 子接口 owner 的类型证明。** [成对 Java 8 三方对照](evidence/java-syntax-2026-09-24/iterable-subtype-owners/analysis.md)显示 `List`、`Collection`、自定义 `TextIterable extends Iterable` 的增强 `for` 分别调用自身接口的 `iterator()`；JADX 仅在有调试表时把前两者恢复为增强 `for`。Jarde 的[平台 owner 有限扩展](changes/project-proved-platform-iterable-owners/verification-root.md)已用 Java 8 标准接口关系及接收者的完整源类型名，让 List/Collection 在有无调试表时都输出可执行增强 `for`，同时复用现有 SSA、处理器及原子 AST 候选，无须因此先造通用子类型求解器。自定义接口仍保留 `while`：单类输出只持有本定义类，须由请求环境提供其定义及传递继承证明，不能把任意同名 `iterator()` 或平台 owner 白名单推广为一般规则。

**增强 `for` 元素类型的显示质量。** [typed/raw Java 8 探针](evidence/java-syntax-2026-09-24/typed-iterable-foreach/analysis.md)区分了两个问题：现有 `Object` 绑定加原位 `String` cast 行为正确，但丢失了原方法参数 `Iterable<String>` 的泛型声明；raw 参数上直接写 `for (String … : values)` 则不能编译。字节码的直接 `checkcast String` 足以在一个严格受限的局部子集证明元素运行类型，却不证明方法的泛型 `Signature`。可以合成显式 `(Iterable<String>) values` 来写 typed header，但这会增加 unchecked 源转换且反射签名仍为 raw；现阶段不为外观单独引入该适配。[普通参数化 Signature 三方证据](evidence/java-syntax-2026-09-24/ordinary-parameterized-signatures/analysis.md)与[独立 change](changes/recover-ordinary-parameterized-signatures/tasks.md)现把可信方法声明作为前置；之后仍需另证相同参数槽到循环 AST 的类型传递、`next()`、cast 和异常边界，才能选择 `String` 元素。现有泛型方法任务 2.3/3.1 处理方法自身类型变量，不应顺手扩围。保留 `Object`/cast 是可编译且可执行的当前闭环。

**验收口径。** 对每个自写场景固定源码、`javac --release 8` 产物及哈希，同一输入分别交给版本固定的 JADX 与 jarde；分开记录语法形态、完整类 `javac`、`java -Xverify:all` 的值/副作用/异常、需要时的反射签名，以及报告的未恢复部分。合法 class 变体检验误投影。JADX 与原源码都只是对照，原 class 的实际行为和 classfile 属性才是正确性判据；`for-each` 与手写迭代循环可能有相同字节码，输出它必须证明等价，不能宣称识别出唯一原写法。旧冻结 CLI 的 RED 不代表当前工作树，active change 的勾选也不代替重建后的整类复核。

**整仓门禁债务（另行收束）。** [String switch 3.2 独立验收](changes/recover-string-switch/verification-root-3.2.md)的定向 Rust 与 Java 执行、格式、OpenSpec strict 均通过；2026-09-24 当前共享工作树的 `p5_corpus_fingerprint` 报告其它在途任务留下的 61 个未登记夹具，严格 Clippy 另报 enum/region/report 的 7 项既存 lint。这些是跨变更集成门槛，须在对应工作完成后审查 manifest 与 lint；不能借单个语法 change 盲目重录或顺手重构无关模块。

**当前工作树门槛。** 2026-09-24 已修正测试文件位置和枚举证明调用签名，`cargo check -p jarde-java --tests --locked` 通过。循环测试值、普通 switch 穿透与异常作用域的定向测试通过；其它相邻异常局部作用域用例仍有预存失败，已拆入 [独立变更](changes/preserve-local-scope-across-exception-regions/tasks.md)，不可视作全套绿色。枚举投影现已分别消费 `<clinit>` 所调用的私有数组工厂与公开 `values()` 的完整 IR，并修正 helper 表读取 BCI 身份；[独立复核](evidence/java-syntax-2026-09-24/enum-switch-labels/values-proof-review.md)确认两份 verifier-valid 数组负例拒绝、普通与交换映射三方执行相同，但该 change 的预算/语料/静态检查总验收尚未关闭。编译产物放在独立临时 target，验收后清理。

## 全量导出架构（2026-09-21，主体已实现，验收继续）
